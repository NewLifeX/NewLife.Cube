# OSC-26092694a1 — 甘特分组、画册布局与多级排序

## 1. 目标愿景

同一套只读舞台补上三处完成度：甘特可按字段分组、卡片增加画册布局、表格可按最多三列在服务端排序。

- 目标 1：甘特 `mapping.groupField` 可选；有值时记录归入分组父节点；父节点点击不打开详情；`moveable` 仍为 false。
- 目标 2：~~卡片画册布局~~。执行中按产品要求撤回，卡片仍只有标准、偏大、整行。
- 目标 3：`sorts` 最多 3 列，字段必须属于工厂字段且属于 GetPage `search ∪ list`；非法 400。禁止客户端传入任意 `OrderBy`。单列排序的旧参数继续可用。

## 2. 为何做

迁移方案 §7.4 / §10.4 #19、#20、#21：甘特无分组、卡片不是画册、表头只有单列 `sort`/`desc`。这三项都留在只读呈现和排序白名单内，不碰拖拽写回。

## 3. 已锁定范围

| # | 决策 |
| --- | --- |
| 1 | 一个 OSC、三条任务线，可分别验收。 |
| 2 | 甘特分组字段候选与看板相同（布尔、枚举、下拉、LOV、徽章）。空字符串表示不分组。 |
| 3 | 分组父节点是前端合成行，不写入数据库。 |
| 4 | 画册是 `CardLayout` 新值，不是新的 `ViewKind`。 |
| 5 | 多级排序不改 XCode `PageParameter`。从查询串 `sorts` 读取，编译后写入 `pager.OrderBy`，并清空 `pager.Sort`。 |
| 6 | 同时有 `sorts` 与 `sort` 时，只认 `sorts`。仅 1 列时前端仍发 `sort`/`desc`，不发 `sorts`。 |
| 7 | `NamedView.sort` 保留。新增 `sorts` 数组；读取时若只有 `sort`，视为长度为 1 的 `sorts`。保存时两者一起写，`sort` 等于 `sorts[0]`。 |

## 4. 做什么

- 甘特配置增加分组字段；运行时把记录包进只读分组父节点。
- 卡片配置增加「画册」；`RecordCard` 按该布局渲染。
- 表头单击仍只改第一排序列并清掉其余列。工具栏「排序」弹层编辑最多 3 列。后端白名单编译 `OrderBy`。

## 5. 不做什么

- 不做甘特依赖线、拖条改期、进度可调。
- 不做看板/日历拖拽写回，不做视图 Tab 拖序。
- 不做字段矩阵与值集收口。
- 不接受 `orderby` 查询参数作为排序入口。已有服务端默认 `OrderByKey` 仅在用户未指定排序时保留。
