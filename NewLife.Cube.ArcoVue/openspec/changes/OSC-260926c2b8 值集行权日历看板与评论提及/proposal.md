# OSC-260926c2b8 — 值集行权、日历看板补齐与评论提及

## 1. 目标愿景

实体下拉和名称翻译服从与列表相同的租户和行权；日历能展开当日溢出并在有新增权时从空白日建记录；看板列可折叠；讨论框能把已有的提及通知真正发出去。

- 目标 1：`entity:` 的 `ListData` 与 `BatchLabel` 在无目标实体查看权、无租户上下文（Enforce）或行权范围外时不返回该行；枚举值集行为不变。
- 目标 2：日历月格中 `+N` 可展开当日全部事件；有 Insert 权时点击本月空白日打开新增抽屉并写入开始日期；无新增权、非本月格子不新建。
- 目标 3：看板列头可折叠/展开，折叠向上收起、列宽不变；有编辑权时把卡片拖到另一列，用已有 PATCH 写回分组字段。不写入 ViewProfile，不做列内排序。
- 目标 4：讨论与回复提交 `mentionUserIds`（最多 20）；后端通知逻辑不改；评论正文仍是纯文本。

## 2. 为何做

这三块是迁移方案 §10.4 与竞品报告里仍能用代码复现、且彼此无共享改动面的补全项。值集走 `LovController.FetchEntityList` 的 `fact.FindAll`，绕过 `SearchData`。日历 `+N` 是不可点的文本。评论 POST 已支持 `MentionUserIds`，前端只传 `content` / `parentId`。

用户要求把这三项放进同一个变更。三条线独立验收，不互相阻塞。

## 4. 做什么

**A.** `FetchEntityList` / 实体 `BatchLabel` 叠加目标菜单 Detail、租户条件、DataScope。不可见行不出现在下拉里，也翻译不出名称。

**B.** 日历溢出弹层与空白日新增；看板列向上折叠；看板跨列拖放写回分组字段。

**C.** 讨论框增加提及人选，`cubeApi.comment.post` 增加 `mentionUserIds`。

## 5. 不做什么

- 不做字段矩阵、GetPage 去匿名、导出列裁剪。
- 不做甘特分组、画册布局、多级排序（见 OSC-26092694a1）。
- 不做日历周视图、看板列内排序、日历/甘特拖拽写回、评论富文本、提及关系落库。
- 不把 `DataPermissionAttribute` 表达式套进值集（行权以 DataScope 为准；无归属接口的实体只受菜单 Detail + 租户约束）。
