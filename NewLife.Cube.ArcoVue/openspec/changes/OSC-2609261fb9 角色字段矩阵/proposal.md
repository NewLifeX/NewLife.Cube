# OSC-2609261fb9 — 角色字段矩阵

## 1. 目标愿景

角色可以按实体收紧字段的可见与可写，列表、详情、表单、导出和写入使用同一套结果；没配过矩阵的角色保持今天的字段集。

- 目标 1：`GetPage` / `GetFields` 去掉匿名；未登录 401。已登录时按当前用户裁剪五分区。
- 目标 2：某角色对某实体一旦存在授权行，该实体对该角色变为白名单；未列出的字段不可读、不可写。没有任何授权行时不裁剪。
- 目标 3：更新时丢弃不可写字段，不把整单打回 400；导出列与可读字段一致，敏感列脱敏仍在裁剪之后执行。
- 目标 4：系统角色不裁剪。多角色取并集：任一角色不裁剪或对该字段可读/可写，则结果可读/可写。

## 2. 为何做

迁移方案 §8.6 BE-B2：今天藏列在 ViewProfile，GetPage 仍是 `[AllowAnonymous]`，导出用 `Factory.AllFields`。行权与脱敏（OSC-2608273d95）不是列 ACL。

## 3. 已锁定范围

| # | 决策 |
| --- | --- |
| 1 | 新 Cube 实体 `FieldGrant`，不改 XCode `Role` 表。 |
| 2 | 缺省不裁剪，避免升级后所有页面空白。 |
| 3 | 白名单按「角色 + TypePath」生效，不是按单字段悄悄生效。 |
| 4 | `CanWrite=true` 保存时强制 `CanRead=true`。 |
| 5 | 写入路径丢弃不可写属性，不返回 400。 |
| 6 | 管理入口只在角色编辑抽屉，不给每个实体做字段 ACL 页。 |
| 7 | 不新做分享令牌解析。去掉匿名后，embed 仍须靠现有令牌把分享者写入当前用户；若因此 401，修令牌注入，不把 GetPage 改回匿名。 |

## 4. 做什么

- `Cube.xml` 增加 `FieldGrant`，生成实体。
- 角色 Update 权限下读写某角色、某 TypePath 的授权集合。
- `GetPage` / `GetFields` 登录后裁剪；列表/详情 JSON 去掉不可读属性；Insert/Update 丢弃不可写属性；导出列求交。
- 角色抽屉增加「字段权限」区块。

## 5. 不做什么

- 不改 XCode `Role.Valid`、不挂 `DataScopeInterceptor`（BE-A1～A5）。
- 不做值集 `entity:` 收口（OSC-260926c2b8）。
- 不做公式列、查找引用多列、导入接口新公开。
- 不用 ViewProfile / `ColumnsJson` / `Authority` 当 ACL。
- 不审计「谁改了字段矩阵」之外的新日志格式；保存走角色 Update 已有日志即可。若角色保存本身不写字段差异，本号不另造审计协议。
