# OSC-260922201a — 小白流程设计与就地审批

## 1. 目标愿景

让没画过流程的管理员用「部门负责人或签」「满 2 万走财务，否则走主管」这种话说完设计，让没办过审批的人在待办行上直接同意或驳回，不必先打开进度再打开意见窗。

- 目标 1：设计器用六种选人并写成「部门负责人 · 或签」；依次审批可新建；条件多分支从左到右命中第一条，最后一支为「其他情况」；人为空可选自动通过、转部门负责人或指定某人。
- 目标 2：待办行主按钮就地完成同意、驳回或已办理，只多一层气泡；看进度才打开抽屉。记录抽屉的审批页签内同样就地办理，不再套一层进度抽屉。
- 目标 3：办理人节点不能驳回整单；同一审批人自动跳过；离职转部门负责人；意见可挂附件；同一业务键同时只有一条在途（数据库占用，不单靠进程锁）。
- 目标 4：拥有「效率」菜单的角色在同一页按流程、部门、用户、节点、年或月看到平均耗时、中位耗时和超过 48 小时的比例；办理节点和勾了「不计入效率」的节点不进统计。

## 2. 为何做

[Doc/审批流竞品分析.md](../../../../Doc/审批流竞品分析.md) 对照飞书后的结论：引擎骨架够用，差在选人语句、多分支、空人策略，以及办事的人要点开好几层。OSC-26090347f1 已归档，本号在其上加法，不换 Elsa / Flowable / BPMN。

## 4. 做什么

1. 扩展节点 `to` 与 `emptyPolicy`；发布校验；发起请求携带自选人。
2. 设计器：六种选人、依次审批、空人策略、多分支画布、办理人节点、卡片人话。
3. 引擎：部门负责人与表单字段展开、空人策略、办理完成、同一人跳过、离职转交、占用表。
4. 发起抽屉：只读步骤预览；自选人在同一抽屉内选择；条件预告按第一条记录。
5. 待办行就地同意/驳回/已办理；进度与记录页签展示当前节点、命中分支、自动处理说明；意见附件。
6. 效率页：同一页按流程、部门、用户、节点、年、月聚合。部门取办理人当前的 `DepartmentID`。谁能看由「效率」菜单权限指定。



## 5. 不做什么

- 不重做表单设计器，不新增表单控件类型。
- 不把 `level` 做成「向上 N 级」界面。字段可留下，发布时 `level` 不是 1 则 400。
- 不让办理人驳回、不把办理任务算进「同一人已同意」。
- 不把待办同意改成「先开进度抽屉再开意见窗」。
- 不改 GetPage 匿名契约、不改 `PermissionFlags`、不在业务表加审批状态列。
- 不改自动化执行器。条件仍复用 `AutomationFilter.Match`。
- 效率页不做组织树、个人与部门并排对比图、打印和导出。点一行只在本页收成筛选。超过 48 小时的阈值固定，本号不做配置项。
