## 3. 节点 JSON

未知字段留在节点 `Raw`，保存时原样写回。

### 3.1 `to`


| 字段                            | 合法                                                            | 缺省                                                          | 非法               |
| ----------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------- | ---------------- |
| `kind`                        | `users` `roles` `departments` `manager` `starterPick` `field` | 无 kind 时：`users` 非空→users，否则 roles，否则 departments；三者都空则发布失败 | 其他字符串发布失败        |
| `users`/`roles`/`departments` | 正整数数组                                                         | `[]`                                                        | 非数字丢弃            |
| `level`                       | 仅 `1`                                                         | `1`                                                         | 不是 1 则发布失败       |
| `scope`                       | `all` `roles` `departments`，仅 `starterPick`                   | `all`                                                       | 其他发布失败           |
| `multiple`                    | bool，仅 `starterPick`                                          | `false`                                                     | 非 bool 当 `false` |
| `field`                       | 实体字段名，仅 `field`                                               | 无                                                           | 空则发布失败           |
| `fieldAs`                     | `user` `manager`                                              | `user`                                                      | 其他发布失败           |


`manager` 取发起人主部门 `ManagerId`。`field` + `user` 取该字段用户 Id；`field` + `manager` 取该字段部门的 `ManagerId`。字段不存在则发布失败（设计器保存时）或发起 400（运行时字段被删）。

### 3.2 `emptyPolicy`


| 值         | 行为                          |
| --------- | --------------------------- |
| 缺省        | 停住，通知发起人（旧图）                |
| `pass`    | 节点自动通过，意见「审批人为空，自动通过」       |
| `manager` | 交给发起人部门负责人；仍空则停住并通知         |
| `user`    | 交给 `emptyUserId`；用户无效则停住并通知 |
| 其他        | 发布失败                        |


新插入的审批/办理节点写入 `emptyPolicy: "manager"`。

### 3.3 办理节点

`type=oa.handle`。数据字段与审批节点相同。`mode=sequence` 发布失败。没有驳回动作。

### 3.4 发起 `picks`

`POST` 发起体增加 `picks`：`{ "<nodeId>": [userId, ...] }`。仅 `starterPick` 节点必填。`multiple=false` 时数组长度必须为 1，否则 400。其他节点出现在 `picks` 里则忽略。

### 3.5 占用表

`WorkflowOccupancy`：`Id` 自增主键，`TypePath` + `EntityKey` 唯一索引，`InstanceId`。与实例、主体同一事务插入。终态（通过、驳回、撤回、作废）删除。唯一索引冲突 → 409，文案「已有在途审批」。（2026-09-25 复核修正）

### 4.2 待办行按钮（就地）

视口 ≥768px：主按钮旁弹出 `a-popover`，宽 480。<768px：同一内容用全宽 `a-modal`，仍然只有这一层，不打开进度抽屉。


| 节点           | 行上可见   | 气泡内                | 禁止           |
| ------------ | ------ | ------------------ | ------------ |
| `oa.approve` | 同意、驳回  | 常用语、意见、附件（阶段内一并做）  | 打开进度抽屉       |
| `oa.handle`  | 已办理    | 常用语、意见、附件          | 驳回按钮、批量驳回包含它 |
| 转交/加签/回退     | 「更多」下拉 | 同一行再开一个 popover 选人 | 第二层抽屉        |


驳回意见必填，空白则按钮不可提交。同意与已办理意见可空。

点行标题或「进度」打开进度抽屉。点主按钮不打开它。

### 4.3 记录抽屉

### 4.4 发起抽屉

步骤预览只读，例外是 `starterPick` 行内嵌选人。未选齐时提交按钮禁用。多条记录时预览下固定一行：「条件按第一条记录判断，将走：{分支标题}」。无 XOR 时不显示这行。

| 节点状态                 | 显示              |
| -------------------- | --------------- |

| 自动通过 / 自动跳过 / 转部门负责人 | 自动通过、自动跳过文案随引擎意见进「审批意见」时间线；转部门负责人为任务改派，无单独文案 |

### 4.6 画布手感

对照[飞书审批管理员手册](https://www.feishu.cn/hc/zh-CN/articles/360033971554)第 4 章。下面四项只改设计器呈现。并行分支见 §4.7，那一项要改引擎。

| 项 | 做法 |
| --- | --- |
| 节点设置 | 不再占固定右侧栏。点节点从右侧打开抽屉（宽 400，无遮罩），画布铺满内容区。关抽屉即取消选中。窄屏链式预览同样打开这个抽屉 |
| 连线加号 | 菜单挂到页面最外层，盖住节点卡片。五项短名各带图标：审批人、办理人、抄送人，分隔条之后是条件分支、并行分支。审批 / 办理 / 知会仍走现有插入窗口；条件分支、并行分支直接插入 |
| 节点卡片 | 单独标题栏：类型徽标 + 签核方式，右侧垃圾桶删除。内容区只写接收人（人员 / 角色 / 部门 / 部门负责人）。未指定时内容行橙色提示。属性抽屉里审批人六种用下拉选择 |
| 条件节点 | 卡片写出分支条数，以及「其他情况」是否已接上。缺默认分支保持橙色警告。条件编辑仍用现有「添加条件」和「其他情况」 |

明确不做：连续多级上级、并加签 / 减签、表单设计器、字段级可读矩阵。

### 4.7 并行分支

对照[管理员设置审批流程并行分支](https://www.feishu.cn/hc/zh-CN/articles/046280562486)。`oa.xor` 仍是条件分支：按顺序命中第一条，都不中走「其他情况」。并行分支是另一种节点 `oa.parallel`，画布形状与条件分支相同（若干分支 + 最右「其他情况」），运行时同时进入多条。

| 规则 | 做法 |
| --- | --- |
| 进入哪些分支 | 没写条件的分支一律进入。写了条件的分支，沿用 `AutomationFilter.Match`，按第一条记录判断，命中才进入。同一分支内仍是现有的一条过滤，不另做「条件组且 / 或」 |
| 其他情况 | 只有其它分支都没进入时才走。避免一条都进不去 |
| 汇合 | 画布上并行节点后面的那个节点是汇合点，写入 `joinTarget`。已经进入的每条分支都办完，才进入汇合点 |
| 驳回 | 任一已进入分支上的审批驳回，整单驳回，并取消其它分支上还开着的任务。办理节点仍不能驳回整单 |
| 进度 | 只读画布全图渲染：没进入的分支显示「未处理」（2026-09-25 复核修正），进入的分支标当前 / 已完成 |
| 效率 | 分支上的审批任务照常计入。办理节点仍不计入 |

旧图没有 `oa.parallel`，打开方式不变。

## 5. 引擎规则

1. 展开顺序：kind → 得到用户 Id 列表 → 去掉禁用用户并改派其部门负责人 → 空则 `emptyPolicy` → 创建任务 → 同一人跳过（仅 `oa.approve`，且本实例更早审批节点已同意）。
2. 或签：跳过的一人即可让节点通过。会签：只跳过该人。办理节点不跳过。
3. XOR：`cases` 顺序，第一条主体，`AutomationFilter.Match`，否则 `defaultTarget`。与现实现一致。
4. 办理完成：任务 Done，不把实例打成驳回，然后沿出边继续。
5. 并行分支（待实现，§4.7）：`oa.parallel` 同时进入所有命中分支；都不命中才走「其他情况」；全部进入的分支完成后才到 `joinTarget`；任一审批驳回则整单驳回并取消其余在途任务。`oa.xor` 仍只走一条。



## 6. 效率页

对照飞书「效率诊断」里管理员能用的三项：平均耗时、完成率、超长等待（飞书用 48 小时）。团队效率和个人效率在飞书桌面端要扫码看，本号不做。办理人节点在飞书不计入，本号同样不计入。来源：[飞书审批成员手册](https://www.feishu.cn/hc/zh-CN/articles/102254611657)、[管理员手册 5.5](https://www.feishu.cn/hc/zh-CN/articles/360033971554)。

### 6.1 谁能看

菜单叶子 `效率`，URL `/Cube/Workflow/Efficiency`，`EnsureLeaf` 排序 10、图标 `Chart`。能看的人 = 对该菜单有 `PermissionFlags.Detail` 的角色，外加系统管理员。没有这权的人菜单不出现，`GET` 返回 403。不另做「指定角色」表单。

### 6.2 计入与排除

| 任务 | 是否计入节点耗时 |
| --- | --- |
| `oa.approve` 且节点未标 `excludeStats`，意见不是「自动跳过」「审批人为空，自动通过」 | 计入 |
| `oa.handle`、`oa.cc` | 不计入 |
| 节点 `excludeStats: true` | 不计入 |
| 流程根 `excludeStats: true` | 整张流程不出现在流程下拉，也不进三个汇总数 |
| 缺省 | 计入 |

设计器：流程属性抽屉里一个勾选「不纳入效率统计」，默认不勾。审批节点属性里一个勾选「不计入效率」，默认不勾。办理节点不显示该勾选。

耗时 = 任务 `UpdateTime - CreateTime`（已结束：Done / Rejected / Transferred）。未结束的 Active 任务用「现在 − CreateTime」，只进入「超长等待」计数，不进入平均和中位。

节点在某实例上的耗时，起点都是该 `NodeId` 计入任务的最早 `CreateTime`：

- 或签：最早一条已结束任务的 `UpdateTime` 减去起点。
- 会签、依次：最晚一条已结束任务的 `UpdateTime` 减去起点。还有人未结束时，该实例该节点不进平均和中位。

超过 48 小时：已结束节点耗时大于 48，或未结束审批任务等待大于 48。比例 = 已结束且超过 48 小时的节点样本 / 已结束节点样本。未结束的超长单另计，不进这个比例。

完成率 = 时间窗内发起、且状态为通过或驳回的实例数 / 时间窗内发起的实例数。撤回在分母、不在分子。

平均、中位的单位是小时，保留一位小数。样本为 0 时平均和中位显示「—」，比例显示「—」。

实例超过 2000 条的截断见 6.5。

### 6.3 聚合

`groupBy` 只接受 `process`、`department`、`user`、`node`、`year`、`month`。缺省 `process`。其它值 400。

| groupBy | 一行是什么 | 名称从哪来 |
| --- | --- | --- |
| `process` | 一个流程定义 | 定义名称；`excludeStats` 的流程不出行 |
| `department` | 办理人当前主部门 | `User.DepartmentID` 对应部门名；`DepartmentID=0` 的行标题为「未分配部门」 |
| `user` | 一个办理人 | 用户显示名 |
| `node` | 该流程的一个审批节点 | 快照节点标题；必须带 `definitionId`，否则 400 |
| `year` | 一个公历年 | `2026年` |
| `month` | 一个公历月 | `2026-09` |

部门按查询当时的 `DepartmentID`，人不在原部门时历史单算进现部门。年、月按实例 `CreateTime` 的公历年、月。节点耗时规则仍按 6.2，先算出计入样本，再按上表归堆。三个汇总数是筛选之后、分组之前的全体，不是当前页行的再平均。

时间：`days` 为 7、30、90，或 `year` 为四位公历年（今年与前两年）。两个都缺省时 `days=30`。`groupBy=year` 时忽略 `days`，固定返回今年与前两年共三行（没数据的年仍占一行，样本数为 0）。`days` 与 `year` 同时出现，或 `year` 不是这三年，返回 400。

点行不换页，只改本页筛选：

| 当前聚合 | 点一行 |
| --- | --- |
| 流程 | 带上该 `definitionId`，改成按节点 |
| 部门 | 带上该 `departmentId`，改成按用户 |
| 年 | 带上该 `year`，改成按月 |
| 用户 | 带上该 `userId`；已有流程则改成按节点，否则改成按流程 |
| 月、节点 | 不改聚合；就地展开该行最慢的 10 条 |

筛选条件以标签留在表上方，点标签即去掉该条件并回到上一级聚合。

### 6.4 页面（一层）

路由一页，不是抽屉。自上而下：

1. 时间（近 7 天 / 近 30 天 / 近 90 天 / 年份）和「按：流程、部门、用户、节点、年、月」。未选流程时「节点」不可点。
2. 已选标签。
3. 三个数：平均耗时、完成率、超 48 小时仍未办完的单数。
4. 表：名称、样本数、平均耗时、中位耗时、超 48 小时占比。默认按平均耗时从高到低。样本为 0 的年行排在最后。
5. 仅月、节点两行可展开最慢 10 条：标题、办理人、耗时、未办完则标「等待中」。点标题才打开进度抽屉。

耗时文案：不足 1 小时写「N 分钟」；1 小时到不足 48 小时写「N.N 小时」；达到 48 小时写「N.N 天」。

空数据：「这段时间没有计入统计的审批」。三个年行都是 0 时也用这句，不画空表。

### 6.5 接口

`GET /Cube/Workflow/Efficiency?groupBy=process&days=30&definitionId=&departmentId=&userId=&year=`

```json
{
  "avgHours": 3.5,
  "completionRate": 0.8,
  "overdueOpen": 2,
  "truncated": false,
  "rows": [{ "key": "12", "title": "请假", "count": 12, "avgHours": 30.0, "medianHours": 20.0, "over48Rate": 0.25 }],
  "slow": [{ "instanceId": "1", "nodeId": "n1", "title": "请假", "assignee": "张三", "hours": 50.0, "waiting": true }]
}
```

`slow` 最多 10 条。仅 `groupBy` 为 `node` 或 `month` 且带了对应的 `nodeId` 或 `month`（`yyyy-MM`）时返回；否则为空数组。展开时再请求一次。实例超过 2000 条时只取 `CreateTime` 最新的 2000，`truncated: true`，页顶说明「只统计最近 2000 条」。

## 8. 测试设计


| 用例                     | 期望                  |
| ---------------------- | ------------------- |
| 旧图无 kind、无 emptyPolicy | 发布通过；空候选人仍通知发起人     |
| kind=manager 且部门有负责人   | 任务落在该用户             |
| emptyPolicy=pass 且无人   | 实例继续，意见含「自动通过」      |
| 三分支按序                  | 只走第一条命中；都不中走默认      |
| oa.handle 驳回           | 400 或无此动作           |
| 同一人第二审批节点              | 无待办，意见「自动跳过」        |
| 办理节点同一人                | 仍有待办                |
| 占用唯一索引冲突               | 409                 |
| 前端待办矩阵                 | 办理节点无驳回；同意不返回「打开抽屉」 |
| 前端进度                   | 未命中分支在只读画布显示「未处理」    |
| 效率聚合                   | 办理任务、自动跳过、`excludeStats` 不进平均；等待 49 小时的未完成任务只增加 overdueOpen |

| 前端耗时文案                 | 30 分钟、3.5 小时、2.0 天三档 |
