# OSC-0014 — 全局模板（表单全局唯一）

## 1. 为何做

个人 ViewProfile 能满足个性化，但无法让系统管理员为某实体发布统一的初始视图与筛选体验。为保持默认 CRUD 皮肤的可预测性，本号引入每个 `typePath` 一份 `UserId=0` 的全局模板：**视图/筛选两个域**由管理员发布模板、普通用户可基于模板分别创建个人配置域；**表单域已按「全局唯一」模式落地（OSC-0013 迭代）**——每实体全局只有一份表单布局，管理员定义、作用于所有用户的 新增/编辑/详情 表单，普通用户无个性化。

## 2. 已锁定范围

| # | 决策 |
| --- | --- |
| 1 | 每个 `typePath` 最多一份全局模板，固定存为 `ViewProfile.UserId=0`。 |
| 2 | 仅系统管理员（`Roles.Any(e => e.IsSystem)`）可读取管理态、发布和恢复模板。 |
| 3 | 视图/筛选域：个人配置、模板、系统种子按 `个人 > 模板 > 系统默认` 解析；表单域：全局唯一（`UserId=0` 一份，所有用户共享读取，无个人层）。 |
| 4 | 视图/筛选域覆盖单位是配置域整体（非字段级 patch 或 tombstone 合并）；表单域整体替换 `FormJson` 线缆（无个人域）。 |
| 5 | 视图/筛选域：用户首次保存该域时以当前有效值创建个人域副本，之后不再受模板更新影响；表单域无个人副本，管理员发布即全局生效。 |
| 6 | 模板发布、删除和恢复必须记录 Cube 操作日志；普通用户不得通过 body/query 指定 `UserId=0`，也无表单布局写入口（OSC-0013）。 |

## 3. 做什么

- 新增管理员模板专用 GET/PUT/DELETE API（**视图/筛选域**），保留既有个人 API 与 `UpsertForUser(userId>0)` 约束；表单域复用已落地的全局唯一机制（`/Cube/ViewProfile` 的 FormJson 管理员写入 + 全局读取，OSC-0013）。
- 扩展 ViewProfile Biz 层的模板查询、模板 upsert、模板删除和审计逻辑；模板与个人记录走相同 JSON 契约；全局 FormJson 沿用 `SaveGlobalFormJson`/`DeleteGlobalFormJson`（OSC-0013）。
- api-core 增加 template API；前端加载个人+模板并按配置域解析有效状态（表单域直接读全局 FormJson，不参与三层解析）。
- 视图域恢复由视图菜单「恢复默认」承接（不显示独立来源徽标）；表单布局入口保持「仅管理员可配置全局布局」（OSC-0013），普通用户只读共享；模板管理抽屉文案以「搜索」表述筛选域。
- 处理模板变更、视图/筛选个人域恢复、旧个人记录和不存在模板的兼容路径。
- 补齐后端鉴权/审计/XUnit、前端 resolver/组件测试与文档同步。

## 4. 不做什么

- 不做角色、租户、应用级模板，不做多人协同、审批、版本历史或模板草稿。
- 不做字段级合并、通用 JSON patch、跨实体模板、Widget/画布/跨表查询。
- 不改变 apps 整页覆写和 Section 局部覆写优先级：默认容器才消费模板。
- 不允许模板改变 GetPage 字段、字段权限、数据权限或 CRUD 提交行为。
- 不为表单域引入个人可覆盖模板、恢复个人域或三层解析（表单已全局唯一，OSC-0013）。

## 7. 成功标准

- [ ] 管理员可安全发布、读取和删除 `UserId=0` 模板（视图/筛选域）；普通用户无模板写入口，也无表单布局写入口。
- [ ] 视图/筛选有效配置严格按个人、模板、系统种子顺序，且两域独立继承；表单有效配置为全局唯一一份（所有用户共享）。
- [ ] 模板更新不会覆盖已有视图/筛选个人域；用户恢复对应域后立即回落模板或系统默认；表单布局管理员更新即全局生效（OSC-0013）。
- [ ] 模板管理操作被审计，配置不能改变 GetPage 权限和 CRUD 契约。
- [ ] 本 OSC 新增单测全部通过，相关构建无错误，文档按实际实现增量同步。
