# OSC-26090347f1 Amd-3 — 流程设计与审批界面（对照飞书审批）

> **日期**：2026-09-19  
> **依据**：飞书帮助中心《审批管理员手册》《审批成员手册》；OpenAPI `approval-v4` 概述；当前 ArcoVue `web/src/views/workflow/*` 与 `NewLife.Cube/Workflow` 实现。  
> **定位**：吸收飞书审批的**节点语义与办理心智**，不复制其「独立表单设计器 + 审批应用」。Cube 的表单权威仍是实体 `GetPage` / FormJson。

本文是 [information-architecture.md](./information-architecture.md) 与 [design.md](../design.md) 的界面补充。V1 引擎能力（或签/会签/依次、前/后加签、知会、回退、超时、XOR）**保持**；本节只收口「设计器怎么画、审批人怎么看」。

## 0. 产品对照（先定边界）

飞书审批定义 = **表单设计 + 流程设计** 两页签。员工发起时填审批表单，实例页左侧是单据、右侧是流程。

Cube OA 定义 = **流程图绑定 TypePath**。员工在实体列表勾选已有记录发起；单据就是实体行。审批人看的「表单」是 RecordDrawer / 实体详情，不是另一套控件画布。

| 飞书 | Cube（本号必须遵守） | 禁止照搬 |
| --- | --- | --- |
| 表单设计：拖控件 / 控件组 / 关联显示 | 复用实体字段与 FormJson | 审批专用表单设计器 |
| 流程：开始→审批人/抄送人/办理人/条件→结束 | `oa.start` / `oa.approve` / `oa.cc` / `oa.xor` / `oa.end` | `oa.handle` 办理人节点（V2） |
| 审批方式：会签 / 或签 / 依次 | `mode=and/or/sequence` | BPMN 并行网关 |
| 加签：前 / 并 / 后；减签 | V1 仅前加签 + 后加签 | 并加签、减签（V2） |
| 审批人：上级 / 部门负责人 / 角色 / 指定 / 自选 / 表单内联系人 | V1：`to.kind=users\|roles\|departments` | 发起人自选、N 级上级（需组织关系字段，另号） |
| 实例页：左单据 + 右流程 + 底操作 | 实体抽屉=单据；进度面板=流程；待办可左右分栏 | 独立审批中心 SPA 替换 DefaultList |
| 消息卡片快捷同意/驳回 | Inbox 通知 + 待办页办理 | 机器人卡片秒批（无 Bot 协议） |
| 委托授权 | 不做 | 休假代理人 |

**吸收清单（本号界面补齐，不扩引擎）**

1. 设计器：画布节点可读摘要 + 右侧分组属性；XOR 用 ViewFilter 可视化；定义级 LockPolicy / StartFilter。
2. 审批界面：进度按**节点**展示（当前/已办/待办），不只是意见时间轴；主操作同意/驳回，更多含回退。
3. 待办办理：标题 / 摘要 / 发起附件 / 打开记录 同屏。

## 1. 流程设计器（对标飞书「流程设计」页签）

### 1.1 三栏骨架（现状 → 目标）

现状：顶栏选定义 → 中画布（FlowGram 固定布局）+ 工具条「在选中节点后插入」→ 右侧属性。XOR 仅文字提示；start/end 无配置；LockPolicy / StartFilter 无 UI。

目标布局（桌面 ≥1280）：

```
┌ 定义栏：下拉定义 | 名称 | 草稿/已发布 | 写锁策略 | 保存草稿 | 发布 ┐
├ 画布（Flex 1）                          ┤ 属性检查器（360px）┤
│  Start → [+] → 审批卡片 → [+] → … → End │  分组表单，按节点种  │
└ 底栏：校验错误列表（发布前拦截）          ┴────────────────────┘
```

- 画布仍是 FlowGram **固定布局**，禁止自由连线成环。
- **插入方式**对齐飞书：节点之间的 `[+]`（审批 / 知会 / 条件分流）。顶部工具条保留为窄屏与键盘可达的等价入口。
- `<1024`：只读链式预览（已有），属性检查器改为抽屉。

### 1.2 画布节点卡片（必须一眼可读）

飞书节点在画布上就能看出「谁批、什么方式」。Cube 现状卡片信息过少。

| 节点 | 卡片主文案 | 副文案 / 徽章 |
| --- | --- | --- |
| `oa.start` | 开始 | 有 StartFilter 则徽章「有发起条件」 |
| `oa.approve` | `data.name` | 徽章：或签/会签/依次；一行接收人摘要（如「角色·主管」「3 人」）；超时>0 显示「24h·自动通过」 |
| `oa.cc` | 知会 | 接收人摘要 |
| `oa.xor` | 条件分流 | 分支数 N；缺 default 红色「不可发布」 |
| `oa.end` | 结束 | — |

选中态描边用主题 `--color-primary-6`；未配置审批人的 `oa.approve` 用 warning 描边（与 `validateGraph` 一致）。

### 1.3 属性检查器分组

对齐飞书「点节点 → 右侧设置」，把散落字段收成组。**不增加** V1 未实现的引擎字段。

**定义级（未选节点或点空白）**

| 组 | 字段 | 说明 |
| --- | --- | --- |
| 基本 | Name、TypePath（只读，创建后不可改） | TypePath 改绑等于新定义 |
| 写锁 | `LockPolicy`：`full` / `nodeFields` | 对应 design §4 / §6.2 |
| 发起条件 | StartFilter：复用 OSC-0015 ViewFilter 构建器 | 空=全记录可发起 |
| 发布 | 版本号、上次发布时间 | 只读 |

**`oa.approve`**

| 组 | 字段 | 飞书对应 | V1 范围 |
| --- | --- | --- | --- |
| 审批人 | `to`：用户 / 角色 / 部门 | 指定成员 / 角色 | 不做上级/自选 |
| 审批方式 | or / and / sequence；and 时 quorum | 会签/或签/依次 | 已有 |
| 超时 | timeoutHours、timeoutAction、timeoutTransferTo | 近似自动通过/拒绝 | 已有；转交对象用同一 RecipientPicker |
| 操作权限 | allowAddSign、allowRollback、**allowTransfer**（缺则补图字段，默认 true） | 允许加签/回退/转交 | 转交开关现状无 UI，引擎默认允许 |
| 字段权 | writable ⊆ editForm；visible 固定 `*` | 节点字段可读/可编辑 | V1 不按抄送人拆字段矩阵 |

**`oa.cc`**：仅接收人。不做「仅同意时抄送」（V2）。

**`oa.xor`（本号必须补齐可视化，否则条件分流不可配置）**

- `cases[]`：每条「条件（ViewFilter）→ 目标节点」。
- `defaultTarget`：必填，发布校验已存在。
- 画布在 xor 后展示多后继；FlowGram 固定布局用分支槽，禁止手动画环。
- 条件求值主体仍是 **第一条 Subject 当前行**（design §4.4）。

**`oa.start` / `oa.end`**：V1 不配发起抄送/结束抄送（飞书有；本号用独立 `oa.cc` 节点表达）。文案说明「请在其后插入知会节点」。

### 1.4 设计器不做

- 办理人节点、并加签/减签、发起人自选、N 级上级、表单内联系人。
- 从自动化节点面板拖入 `notify`/`http`。
- 在设计器里预演运行时（无沙箱秒批）。
- 移动宽度下编辑。

## 2. 审批界面（对标飞书「审批详情」）

### 2.1 两种宿主，同一套面板

飞书只有一个审批详情页。Cube 有三条入口，必须共用 `WorkflowProgressPanel`（可拆成「单据摘要 + 节点流程 + 操作条」子块）：

| 入口 | 单据区 | 流程区 |
| --- | --- | --- |
| 实体列表「进度」/ RecordDrawer「审批」Tab | 已在抽屉里，是实体表单 | 进度面板（现 560px 抽屉或 Tab 内嵌） |
| 待办 / 已办 / 我发起的 | **缺**：现只有任务表 + 进度抽屉 | 目标：宽屏左右分栏（左记录只读摘要，右流程） |

宽屏（≥1100）待办点行：

```
┌ 左 420px：记录摘要（typePath + 主键 + 主字段）│ 右：节点流程 + 发起附件 + 操作 ┐
│ 「打开记录」跳实体详情                         │ 同意 / 驳回 / 更多              │
└ 摘要 Markdown；发起附件列表                    └ 意见弹层仍 modal                 ┘
```

窄屏：先进度抽屉，顶栏提供「打开记录」。

### 2.2 节点流程（替代纯意见时间轴）

飞书右侧是**按节点**的审批人列表（待处理/已同意/已驳回），意见是节点下的内容。现状 `a-timeline` 只铺 Comment，XOR 未到达节点、会签未投票人不可见。

目标时间轴（仍读 `GET /Instances/{id}`，前端组装，后端可后续加 `nodes[]` 投影）：

1. **发起**：标题、发起人、时间、发起意见、摘要折叠。
2. 每个 `oa.approve`（含加签临时节点）：节点名 + 模式徽章 + 每人状态（待处理/已同意/已驳回/已取消/已转办）+ 意见。
3. `oa.cc`：知会已送达（无同意按钮）。
4. `oa.xor`：显示命中分支名（运行时已选 target）。
5. **结束**：通过/驳回/撤回/作废。

当前用户待办节点高亮；操作条只在该节点出现。

意见时间轴可保留为「全部动态」次级折叠，默认收起。

### 2.3 操作条（对齐飞书详情底栏）

| 按钮 | 谁看见 | 现状 | 目标 |
| --- | --- | --- | --- |
| 同意 | 当前可见任务候选人 | 有 | 保持主按钮；弹层：意见（可选）+ 常用语 |
| 驳回 | 同上 | 有 | 保持；意见建议可选（与飞书一致，不强制） |
| 加签 | `allowAddSign` | 更多里 | 弹层：前加签 / 后加签（已有） |
| 转办 | 默认允许；若补 `allowTransfer=false` 则隐藏 | 有 | 保持单用户 |
| 知会 | 候选人 | 有 | 保持 |
| **回退** | `allowRollback` | **无 UI** | 更多中；选已办节点 |
| 撤回 | 发起人且无人同意 | 有 | 保持 |
| 并加签 / 减签 / 委托 | — | 无 | V2，不做 |

审批节点**不上传附件**（已落地产品决策）。发起附件在流程区「发起附件」只读列表，Category=`WorkflowComment`，Key=实例 Id。

### 2.4 提交抽屉（对标飞书「发起」而不是「填空表」）

飞书发起=填审批表单。Cube 发起=选中已有实体行。

视觉顺序（已部分落地，固化）：

1. 已选 N 条（>100 截断警告）
2. 审批流程（Published + TypePath）
3. 流程标题（无 placeholder）
4. 流程摘要（编辑 / 预览水平 Tab，Markdown）
5. 发起意见 + 常用语
6. 附件（可选，提交成功后挂实例）

不做：在提交抽屉里改业务字段（应先在列表/抽屉改完再提交；`nodeFields` 的改字段发生在审批中走 PATCH）。

### 2.5 列表与壳

- 工具栏文案「批量提交」（已改，不再用「提交审批」若与行操作「提交」混淆）。
- 行 `__wfStatus`：未发起 / 审批中 / 已通过 / 已驳回 / 已撤回。
- 审批中 / 已通过：禁再次发起（已落地）。
- 顶栏「审批」角标 = `Meta.todoCount` = 当前用户可见待办，**不含**他人任务。
- 待办 / 已办只列当前用户任务。

## 3. 与现状实现的差距（实施清单，不另开 OSC）

按对办理体验的阻塞排序。引擎已支持的标「补 UI」；需图字段的标「补字段」。

| # | 项 | 类型 | 说明 |
| --- | --- | --- | --- |
| D1 | XOR 可视化 cases + defaultTarget | 补 UI | 否则设计器无法配置分流 |
| D2 | 定义级 LockPolicy / StartFilter | 补 UI | 后端列已有 |
| D3 | 画布节点摘要徽章 | 补 UI | FlowGram 卡片 data |
| D4 | 节点间 `[+]` 插入 | 补 UI | 与工具条等价 |
| D5 | 进度按节点+候选人渲染 | 补 UI | 可先纯前端用 tasks+comments |
| D6 | 进度「更多」回退 | 补 UI | API 已有 Rollback |
| D7 | 待办宽屏左记录+右流程 | 补 UI | 摘要用 instance.summary / subjects |
| D8 | allowTransfer 图字段 | 补字段 | 默认 true，对齐飞书「允许转交」 |
| D9 | 摘要在进度区 Markdown 渲染 | 补 UI | 发起时已写入 Instance.Summary |
| D10 | 常用语管理入口 | 补 UI | API Phrases 已有；可放定义侧栏 |

**明确不做（对照飞书有、本号无）**：办理人、并加签、减签、委托、快捷卡片秒批、独立表单设计器、发起/结束节点抄送配置、审批人去重、空审批人自动转上级。
