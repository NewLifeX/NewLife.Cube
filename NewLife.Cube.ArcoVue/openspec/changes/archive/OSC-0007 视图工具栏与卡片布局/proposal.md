# OSC-0007 — 视图工具栏与卡片布局

## 1. 为何做

OSC-0006 已提供表格、树、卡片、看板、日历和甘特等视图，但工具入口分散、卡片布局固定，且表格批量操作的选择能力不完整。本变更统一列表页工具入口，补足表格选择与批量删除门禁，并让卡片布局可按记录内容调整。

## 2. 已锁定范围

| # | 决策 |
|---|------|
| 1 | **仅暂时移除图表入口按钮**；保留 `ListChartModal`、`chartVisible`、`chartList`、`openChart()` 和图表 API，后续以独立 OSC 完善图表区。 |
| 2 | 将现有导入、导出和批量删除集中到当前实体的「高级」下拉菜单；不新增跨实体、跨页或跨视图批处理。 |
| 3 | 表格视图默认显示左侧行勾选框和表头全选框；选择状态只影响批量删除可用性，不影响导入和导出。 |
| 4 | 批量删除须同时满足：当前为表格视图、视图允许删除、用户有删除权限、至少选中一行。 |
| 5 | 配置抽屉中的「顶部栏」改名为「工具栏」；移除“允许添加记录”“按钮文字”“自定义按钮”配置及运行入口。 |
| 6 | 工具栏仅在表格/树视图提供分组和排序开关/入口；卡片、看板、日历、甘特隐藏这两项。筛选和搜索保持现有语义。 |
| 7 | 卡片视图支持标准、偏大、整行三种布局；图片位置由布局自动决定，不单设位置开关。 |
| 8 | 卡片正文长字段独占整行；短字段继续双列排列。 |
| 9 | 建立可复用的语义字体 Token，并迁移本号触及的列表、工具栏、卡片和配置抽屉文本，避免继续散落临时字号/字重。 |

## 3. 做什么

- 在 `DefaultList.vue` 合并操作入口为「高级」菜单，删除两处图表按钮和独立 `.page-tools` 区。
- 让表格视图的 `ListTable` 始终传入行选择能力；表头选择框沿用 `ListTable`/VTable 的既有选择机制。
- 新增纯函数级批量删除门禁，基于 `resolveCrudFlags()` 的最终权限、`chrome.allowDelete`、当前视图类型和 `selectedKeys` 判断。
- 精简 `ViewConfigDrawer.vue` 的工具栏配置，并按视图类型决定分组/排序是否出现。
- 扩展 `CardMapping`，将布局持久化在 `NamedView.mapping`；扩展 `CardList`、`RecordCard`、`cardHelpers` 实现栅格、图片位置和长字段整行规则。
- 在 `theme/tokens.ts` 定义语义字体 Token，供上述组件通过 CSS 变量消费。
- 补充 mapping/门禁/卡片字段规则的 Vitest，执行 ArcoVue web 测试和构建。

## 4. 不做什么

- 不删除、不重构、不替换图表 Modal、图表状态或 `getChartData` API；不在本号新增任何图表能力。
- 不改变导入、导出、单条删除、详情、编辑的服务端 API/权限协议。
- 不实现跨页全量选择、跨实体操作、批量编辑或看板拖拽写回。
- 不新增后端字段、数据库迁移或 ViewProfile API。
- 不实现用户自定义图片位置；图片位置仅随三种卡片布局自动变化。
