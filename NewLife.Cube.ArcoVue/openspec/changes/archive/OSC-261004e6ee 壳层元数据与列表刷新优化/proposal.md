# OSC-261004e6ee — 壳层元数据与列表刷新优化

## 1. 目标愿景

让已登录用户在同一会话内切换实体页或刷新列表时，只请求确有变化的数据，不因壳层重复挂载或列表刷新重复加载稳定元数据。

- 目标 1：登录配置、AI 配置、用户偏好和租户清单在同一会话内已成功加载后复用缓存；首次并发调用共用同一 Promise，每个资源至多发出一个请求。
- 目标 2：审批待办数和站内信未读数不作为会话缓存数据，但同一时刻的重复刷新共用请求；审批操作、阅读站内信和显式刷新后仍能获取最新数值。
- 目标 3：实体页普通刷新只调用 `loadData()`，不得重新调用 `loadFields()`、`loadProfile()` 或 `bootstrap()`；同一实体的每个本地多维视图独立维护分组、排序、筛选和填色，且仅在完整请求签名一致时复用原始行，保证用户看到该视图的正确结果。
- 目标 4：切换租户、登出和显式强制刷新正确使相关缓存失效，绝不复用前一租户或前一用户的数据。

## 2. 为何做

开发者工具的 Fetch/XHR 过滤显示实体页冷启动约 15–18 个实际接口请求，其中壳层的 `Tenants` 存在重复加载路径；而总网络资源数约 467–474，主要是 Vite 开发模式的模块资源，不是数百个业务 API。

当前壳层由 `useShellAuth` 与 `useShellToolbar` 分别触发租户及角标加载。`appStore`、`tenantStore` 和 `userProfileStore` 缺少完整的 in-flight 去重与稳定数据缓存约束。实体页虽然已有 `GetPage` 短缓存且普通路径调用 `loadData()`，仍需通过测试锁定“刷新不重跑 bootstrap”的边界，防止后续改动回归。

## 3. 已锁定范围

| # | 决策 |
| --- | --- |
| 1 | 会话缓存资源仅包括 `LoginConfig`、`GetAiConfig`、`UserProfile`、`Tenants`；缓存仅在本次浏览器会话的 Pinia store 内存中保存，不写入新的 localStorage/sessionStorage 键。 |
| 2 | 每个缓存资源分别维护“已成功值”和“进行中的 Promise”。成功后返回缓存；进行中时返回同一 Promise；失败不得写入成功缓存，下一次调用可重试。 |
| 3 | `InboxUnreadCount` 与 `Workflow Meta` 为动态角标：只做 in-flight 去重，不做会话缓存。现有审批、阅读和显式刷新入口继续调用刷新方法，并须获得新的请求结果。 |
| 4 | `tenantStore.switchTo()` 成功后必须强制重新拉取租户清单；登出 `clear()` 必须同时清除成功缓存与进行中的引用。用户偏好重置和登录身份变化同理清理本资源状态。 |
| 5 | `useShellAuth` 与 `useShellToolbar` 继续保留各自职责；通过 store 去重收敛并发，禁止以删除顶栏租户/角标初始化为代价减少请求。 |
| 6 | `DefaultList` 的工具栏/分页/筛选等普通刷新只走 `loadData()`。`bootstrap()` 仅限首次挂载和 `typePath` 变化；切换实体仍需依次加载字段、视图配置和数据。 |
| 7 | 分组、排序、填色和筛选的运行态及持久化态均以 `typePath + activeViewId` 为键。预定义查询的“方案目录”仍是实体级，但其应用结果只写入当前视图；切换视图不得自动把另一视图的未保存筛选或已应用查询覆盖到当前视图。 |
| 8 | 多维视图切换仅当新旧服务端请求签名完全一致时才可 `loadData(true)` 复用原始行；签名至少包含实体、页码、页大小、排序、关键字、`viewFilter`、日历时间窗和租户上下文。任一不同必须调用 `loadData()` 重新查询。分组和填色不改变行集，可在签名一致时本地重绘。 |

## 4. 做什么

1. 为 app、tenant、userProfile 三个 store 补齐稳定元数据缓存、in-flight 去重、强制刷新与失效路径。
2. 为动态的审批/站内信角标补 in-flight 去重，保持每次显式刷新获取服务端最新结果。
3. 明确实体列表的初始化与普通刷新入口，必要时抽取可测试的刷新调度纯函数，防止 `loadData()` 路径回退到 `bootstrap()`。
4. 将多维视图的临时筛选与查询应用结果从实体级会话状态收敛为视图级状态；以完整请求签名决定是否可复用当前原始行。
5. 补 Pinia/Vitest 单元测试，测试并发、成功缓存、失败重试、登出/切租户失效，以及列表刷新/多视图隔离边界。
6. 在迁移方案与功能清单补充“开发模式资源总数不等于 API 数量”、壳层缓存策略和视图级查询隔离的事实说明。

## 5. 不做什么

- 不修改后端 API、响应协议或服务端缓存。
- 不将 Vite 开发模式的 ESM 模块资源数当作业务 API 性能指标，也不为降低该数字改变开发服务器。
- 不缓存站内信未读数、审批待办数等易变业务状态。
- 不合并 Widget 的多条 `Query` 请求；该扇出优化另立 OSC。
- 不改变实体切换、租户切换、登出、审批或站内信操作的既有可见行为。
- 不以“切换更快”为由复用筛选条件不同、分页范围不同或服务端排序不同的行集。
