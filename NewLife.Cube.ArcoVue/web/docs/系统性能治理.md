# 系统性能治理

> 权威来源：OSC-261001e9e2。本文是 ArcoVue 与 WebAPI `NewLife.Cube` 列表热路径的持久契约。后续涉及列表、元数据或写回的变更以本文为准。  
> 框架：页面壳用 [Arco Design Vue](https://arco.design/vue/docs/start)。列表绘制用 [VisActor VTable ListTable](https://visactor.com/vtable/option/ListTable)。缓存只用 XCode 已有实体缓存与按主键查找，不新写跨请求字典。

## 1. 愿景

打开实体列表时，请求停在「页面元数据、当前页、本页标签」三段里。写回一行时，当前结果集不变就只改这一行。图表和导出不再借用列表的取数方式。

## 2. 四条边界

### 2.1 一次打开的请求预算

列表页打开只有三段：

| 段 | 内容 | 本仓库已有落点 |
| --- | --- | --- |
| 页面元数据 | `GetPage` | 前端 `getPageCached`，同 `typePath` 30 秒 |
| 当前页 | `GetList` / `Index` | 现有分页 |
| 本页标签 | 地区 `Names`、值集 `BatchLabel` | 列表缺值并行；抽屉在本号与列表对齐 |

图表、自动化按钮、角色下拉不挂在每一次 `GetList` 成功之后。图表按部件自己的配置取数：没有筛选条件就是全部，有筛选条件就是用户写的条件。它不读当前列表页的行，洞察区不显示「当前页」。本号不改 `loadChart` 与 `GetChartData`。

本号不延长 `getPageCached` 的 30 秒，不增加服务端元数据缓存。

### 2.2 读路径分成三条

| 路径 | 数据从哪来 | 上限 |
| --- | --- | --- |
| 列表 | 当前页实体 | 分页 `pageSize`。`EnableTotalCount` 仍默认开启，本号不关 |
| 图表 | 部件配置：无筛选为全部，有筛选为自定义条件 | 与当前列表页无关。基类 `GetChartData` 的 `PageSize = 1000` 本号不改 |
| 导出 | `ExportData` 独立管道 | 硬顶 **1000000** 行。配置里的 `MaxExport` 更小则用配置；未配置、非正数或更大则用 1000000 |

洞察区不增加「当前页」或其它范围说明。新增的开发者图表在自己的 `OnGetChartData` 里按图表配置聚合，不把基类页大小再调大，也不改成只画当前列表页。

### 2.3 写路径按结果集是否变化分流

纯函数 `shouldReloadAfterWrite(fieldNames, sorts, filter, watchFields)`：

| 输入 | 结果 |
| --- | --- |
| `fieldNames` 去空白后为空 | 刷新 |
| 任一字段名与某条排序、某条筛选条件、或 `watchFields` 忽略大小写相等 | 刷新 |
| 其余 | 不刷新 |

`watchFields` 只放会让行离开当前视图窗口的字段：看板分组字段、日历开始字段、甘特计划/实际的开始与结束、甘特分组字段。表格和卡片不追加。

| 操作 | 视图 | 行为 |
| --- | --- | --- |
| 新增保存 | 全部 | 刷新当前页 |
| 编辑保存、流程可写字段保存 | 树 | 刷新当前页 |
| 编辑保存、流程可写字段保存 | 表格、卡片、看板、日历、甘特 | `shouldReloadAfterWrite` 为真才刷新；否则把提交字段写回主键相同的那一行 |
| 单行删除 | 树 | 刷新当前页 |
| 单行删除 | 其它 | 当前页删完后仍有行，或已在第 0 页：从 `tableData` 去掉该行；`total > 0` 时减 1。当前页被删空且 `pageIndex > 0`：页码减 1 后刷新 |
| 布尔徽标、看板跨列 | 保持 OSC-2609307879 | 仍用单字段判断，不整表刷新的条件不变 |
| 批量删除、批量启用/禁用、导入 | 全部 | 刷新当前页 |

本地写回时，行上已有该字段或它的首字母翻转键，就写到已有键上；两个都没有才用提交时的键名。不覆盖主键，不新增行。

### 2.4 缓存只用现有三级，并写明失效

- 小表继续 `FindAllWithCache` 或 `Meta.Cache`。按主键查找用 `Find` / `Unique.In`。
- 不新写 `ConcurrentDictionary`，不把静态字典当第二套缓存。
- 页面元数据的失效点维持今天：登录清理 `clearPageMetaCache`。改列配置后的主动失效不在本号。
- `List.*` 标签不再默认翻 20 页。见 §3.3。未翻译的键保持省略，调用方已有的标签缓存不因此清空。

## 3. 本号要落地的四件事

### 3.1 单行保存和删除

行为以 §2.3 的表为准。批量与导入仍整表刷新。

### 3.2 抽屉值集与列表对齐

抽屉打开详情或编辑时：

- 地区叶子仍走一次 `areaNames`，逻辑不变。
- 枚举不进 `BatchLabel`。
- 其余 `lovCode` 且列表控件为 `lov` 的字段：用与列表相同的缺值规则（`dataSource` 里已有的值不再请求）。按 `lovCode` 合并后 `Promise.allSettled`。
- 某个值集失败不影响其它值集，也不阻断开抽屉。

### 3.3 `List.*` 按键取标签

`Entity.*` 与 `Enum.*` 保持 OSC-260926c2b8 的按主键 / 反射翻译。

`List.*`：

| 条件 | 请求 |
| --- | --- |
| 某个搜索字段名与值字段忽略大小写相等 | 一次请求。额外参数的键是值字段，值是待翻译键的逗号拼接。只取第 1 页，页大小为 `min(500, 待翻译个数)`。不再翻页。第 4 页及以后的名称与第 1 页一样收录，不因页码省略 |
| 否则 | 沿用无过滤的翻页，最多 **10** 页，每页最多 500 行。凑齐待翻译键或本页不足页大小即停。不得在第 3 页停下。第 4 页到第 10 页里能对上的名称必须写入结果 |

只收录值落在待翻译集合内的行。集合外的键省略。单次待翻译键超过 500 时只取前 500 个。翻页模式不得在凑齐之前停在第 10 页以前，除非本页行数已经不足页大小。第 11 页及以后不再翻；这些名称由「值字段已列入搜索字段」的那一次按键请求负责，不按页码丢掉。

声明 `List.*` 且希望任意主键都能翻译时，把值字段列入搜索字段，并让该接口接受逗号分隔的多值。

### 3.4 图表与导出封顶

图表保持现有部件配置，本号不改取数，也不在洞察区渲染「当前页」。

`ExportData` 的实际上限由 `ResolveExportCap(requested, settingMax)` 决定：`requested > 0` 时用 `requested`，否则用 `settingMax`；结果非正或大于 1000000 时改为 1000000。`CubeSetting.MaxExport` 的属性默认值改为 1000000。设置页上的默认值与此相同。已保存的更大配置按 1000000 封顶；已保存的更小正数保留。备份上限 `MaxBackup` 不改。

## 4. 暂缓（后续单独变更）

下列事项本规范承认它们还在，本号不动：

- `Index` 整实体返回与列投影；`EnableTotalCount` 默认值。
- ArcoVue 全量注册与全量样式。
- `GetChartData` 基类的 1000 行样本改为 SQL 聚合。
- `BatchUpdateFields` / `DeleteSelect` 按主键一次 `IN`。
- `useCascaderField` 按叶子 `getDetail`。
- `GetPage` 服务端缓存、改列配置后失效前端 30 秒缓存。
- `MenuTree` 本次请求内的 `HashSet`、自动化按钮缓存、默认角色 500 行。

## 5. 后续变更准入

涉及列表、页面元数据或写回时，验收写明三件事：

1. 打开列表时新发出几路请求，分别属于 §2.1 的哪一段。
2. 这一路最多扫描或返回多少行。
3. 写成功后是否整表刷新；若刷新，对应 §2.3 的哪一行。

不另起监控系统。沿用现有日志和前端请求序号。
