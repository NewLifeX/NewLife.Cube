# 页面类型与骨架

> 每个页面必须归属以下四种类型之一。类型决定骨架结构，不需要每次重新设计布局。

## 四种页面类型

| 类型        | 用户目标                     | 最大宽度         | 骨架                     | 本项目对应                                                                         |
| ----------- | ---------------------------- | ---------------- | ------------------------ | ---------------------------------------------------------------------------------- |
| 详情/设置页 | 查看、编辑单个对象           | `max-w-[800px]`  | 卡片纵向堆叠             | `EditForm.vue`、个人设置页                                                         |
| 列表页      | 管理一批对象                 | `max-w-[1200px]` | 筛选栏 + 表格 + 分页     | `apps/*/src/views/{controller}/index.vue`（多数由 `DefaultEntity` 自动生成，见下） |
| 仪表盘      | 概览、监控                   | 不限宽，栅格     | 统计卡片 + 图表/列表网格 | `PageHome.vue`                                                                     |
| 全屏工作区  | 自由操作（画布/编辑器/终端） | 不限宽           | 自由布局                 | 富文本编辑、拓扑图类页面                                                           |

四种类型按用户目标分类：查看（详情）、管理（列表）、概览（仪表盘）、操作（工作区），覆盖工具型产品的全部用户目标。新页面若不属于任何一种，先在 `docs/standards/ui-spec.md` 标记"规范缺口"，不要凭感觉设计（见 [principles.md](./principles.md) 第六节）。

## 列表页：优先判断是否需要新写

本项目的列表页多数由框架 `DefaultEntity` 组件根据后端控制器元数据**自动生成**（表格列、搜索栏、分页、新增/编辑弹窗全部自动渲染），业务开发者通常**不需要**手写列表页骨架。

**先判断，再动手**：
1. 若字段/交互能被 `DefaultEntity` 默认渲染覆盖 → 不写页面代码，只配置字段元数据（见 `cube-add-page` 技能）
2. 若只需局部调整（搜索栏、工具栏按钮、表格列、详情头部）→ 使用 **Section 覆盖机制** 新建对应区块组件（见 `cube-page-override` 技能），而不是重写整页
3. 只有全新交互模式（仪表盘、工作区、非 CRUD 页面）才从零搭建骨架

## 外壳 / 子壳 / 内容三层

```
外壳（Shell）    = 顶部导航 + 侧边栏，由 core/layouts/{Layout} 提供，全站唯一
子壳（Sub-shell）= 页面内部的二级导航（如设置页的分类侧栏）
内容（Content）  = 当前页面的业务内容
```

**子壳判定标准**：
- 一组页面共享相同的二级导航（如设置页的多个分类）→ 需要子壳
- 用户需要在这组页面间频繁切换 → 需要子壳
- 内容少、分类 ≤ 2 个、或分类间无关联 → 不需要子壳，用 `el-tabs` 或卡片分区即可

**子壳实现方式（Vue 版本）**：子壳分类 = 独立路由 = 独立 `.vue` 页面（不要用 `v-show` 在一个大文件里切换面板）；子壳导航抽为共享组件（放该模块的 `components/XxxNav.vue`），所有子页面 `import` 同一份导航列表。原因：
1. 每个分类可独立打开、审查、分享 URL
2. 浏览器前进/后退天然可用
3. 与路由模型一一对应，避免单文件膨胀不可维护

新增一个分类只需两步：① 在共享导航组件的 `categories` 数组加一条；② 复制现有分类页面创建新路由。不需要改其他任何页面。

## 从零搭建页面骨架的顺序

1. **确定页面类型**（上表四选一），确定最大宽度和整体骨架
2. **确定是否需要子壳**，需要则先抽共享导航组件
3. **组件选型**：见 [component-decision.md](./component-decision.md)
4. **摆布局**：Tailwind utility class，见 [component-decision.md](./component-decision.md) 的"布局边界"
5. **加交互**：见 [interaction-patterns.md](./interaction-patterns.md)
6. **对照检查单**：见 [spec-checklist.md](./spec-checklist.md)
