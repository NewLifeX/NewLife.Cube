# ADR 0004：控制器优先提供 CRUD，业务差异按覆盖层级递进

**状态：已采纳**

## 背景

为每个实体手工创建列表、表单、路由和请求逻辑，会让前端交付速度随控制器数量线性下降，并使同类 CRUD 在权限、加载、错误和主题上逐渐失去一致性。项目已经具备菜单驱动路由、字段元数据和默认页面引擎。

## 决策

- 标准实体控制器、菜单与字段元数据必须是前端 CRUD 的首选入口。
- 业务差异按“元数据 → Section 覆盖 → 完整页面 → 框架能力回流”选择最小层级。
- 完整页面只用于默认 CRUD 无法承载的独特信息架构、连续工作流、复杂可视化或跨实体协调。
- 重复出现在多个业务页的需求必须评估回流 `core/views/`、共享组件或字段元数据契约。

## 后果

- AI 处理需求时先验证默认 CRUD，而不是默认生成 Vue 页面。
- 新增控制器的验收包括菜单直达、刷新、权限和 CRUD 闭环。
- Section 与整页覆盖仍是第一等扩展能力，但不能成为绕开默认引擎的捷径。
