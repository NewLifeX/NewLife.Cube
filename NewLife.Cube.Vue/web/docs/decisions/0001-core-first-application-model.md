# ADR 0001：以 `core/` 为框架引擎，`apps/` 为业务应用边界

**状态：已采纳**

## 背景

仓库同时存在 `core/`、`apps/` 和旧 `src/`。若不明确边界，默认模板改动容易误落在未被实际入口使用的代码中。

## 决策

- `core/` 是默认前端模板和共享框架的唯一实现位置。
- `apps/<app>/` 是消费 `core/` 的业务应用边界，负责自己的路由、视图和可选 Section 覆盖。
- 根 `index.html` 从 `/core/main.ts` 启动；根 `src/` 不参与当前默认模板运行。

## 后果

- 修改通用列表、表单、路由、布局、请求或主题机制时，优先修改 `core/`。
- 新业务页面和局部覆盖放在相应 `apps/<app>/src/views/`，而不是根 `src/`。
- 旧 `src/` 的代码只能作为迁移对象或独立清理任务处理，不能作为当前行为的文档来源。
