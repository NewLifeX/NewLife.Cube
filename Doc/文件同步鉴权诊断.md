# 文件同步鉴权诊断

工单详情使用 `ViewHelper.GetAttachmentShareUrl` 签发附件分享地址。分享令牌存储于 `UserToken`，绑定 `attachment:{附件ID}`。`CubeController.File` 与 `Image` 读取查询参数中的 token，并检查记录存在、启用、有效期和附件绑定；本次不放宽这些条件。

## HTTP 请求埋点

在已有下载请求 span 上追加 `attachmentId`、`attachmentTokenResult`、`tokenPresent`。匿名且校验不通过时追加 `attachmentAccess=unauthorized`、`httpStatus=401`。不新增探测请求，不记录 token 原文。

| attachmentTokenResult | 含义 | 处理方向 |
| --- | --- | --- |
| token_missing | 没有读取到令牌 | 检查实际发出的 URL 和代理查询串 |
| token_not_found | 当前节点查不到记录 | 对照签发节点与下载节点的 Cube 库及 UserToken 记录 |
| token_disabled | 记录已禁用 | 检查吊销或禁用操作，重新获取分享地址 |
| token_expired | 令牌到期 | 重新获取分享地址，并核对节点时钟和 ShareExpire |
| attachment_mismatch | 令牌绑定其他附件 | 检查 URL 中附件 ID 与签发记录 |
| accepted | 分享令牌有效 | 后续问题转查文件存在性与下载响应 |

这些标签位于服务端原 HTTP 请求埋点，使用请求 TraceId 关联客户端链路。并非修改 Stardust 内部 `FileStorage-FetchFile` span；该 span 的现有异常记录保留。

## 成功下载响应

当前使用的 `NewLife.Cube/Controllers/CubeController.cs` 的 File/Image 成功返回本地文件前统一调用现有 `SetFileHashHeaders`，提供 Digest、X-File-Hash、MD5 对应头及 ETag。此前这两个动作缺失 Hash 头，导致带预期 Hash 的多地址竞速下载即使取得 HTTP 200 也无法选中源节点。

## 定向验证

`AttachmentSaveFileTests.AttachmentDownload_ReturnsHashHeaders` 覆盖真实 SQLite 附件写入、本地落盘与 File/Image 动作返回；改前两条均因 Hash 头为空失败。

`AttachmentTokenDiagnosticTests` 覆盖各拒绝原因及小写 token 查询参数优先于 Authorization 的读取规则。

线上 401 的具体原因仍须在发布后的原请求埋点核实，不能仅凭源码认定为共享库或令牌缓存问题。
