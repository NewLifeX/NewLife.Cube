# 多租户改造验证清单

> 配套文档：《魔方多租户架构评审与改造建议.md》（原始方案）
> 本文按"设计改动 → 跟随调整"组织，供逐项验证。
> **修订（2026-08-16）**：①新增"显式标识优先校验"决策——显式携带租户标识时按所带租户校验成员（普通用户非成员→403，管理员上下文用所带租户），杜绝"请求 t2 被静默换 t1"；②状态码契约修正（Enforce 无标识：API 版 403 / NC 版 401，中间件不再拦）；③补充三轮场景 M6-M14（X-App-Id 三路径、Enforce 规则B 自救、刷新令牌、Query 源、禁用租户、首个管理员来源、SSO）。

## 零、前提认知（验证前必读）

仓库有两个同名工程 `NewLife.Cube`（API 版，输出 Bin3）与 `NewLife.CubeNC`（MVC 版，输出 Bin）。部分文件通过 csproj `<Compile Include>` 跨工程链接共享：`ManagerProviderHelper.cs`、`UserService.cs`、`DataScopeMiddleware.cs`、`ReadOnlyEntityController2.cs` 在 NC 目录但两工程共用；`Setting.cs`、`CubeService.cs`、`SsoController.cs`、`UserController.cs` 两工程各一份需同步。

**改共享文件必须两工程都编译验证。**

## 一、设计级改动（9 项）

### ① NRE 修复：GetTenantId 读 Cookie 判空（P0-1）

- 改动点：`NewLife.CubeNC/Membership/ManagerProviderHelper.cs`（GetTenantId 末尾）
- 改动前：`req.Cookies[key].ToString()` —— Cookie 不存在时直接 NullReferenceException
- 改动后：判空返回 -1（-1 = 无租户标识）
- 跟随调整：无新增文件；下游所有 `tenantId == 0 / > 0` 判断处逐步改用 `GetTenantMode()` 消化 -1（见 ⑦）

### ② 影子开关 TenantEnforceMode（核心决策开关）

- 枚举 `TenantEnforceModes { Shadow=0(默认), Enforce=1 }` → 定义在 `ManagerProviderHelper.cs` 底部（共享，两工程可见）
- 属性 `TenantEnforceMode` → `NewLife.Cube/Setting.cs` 和 `NewLife.CubeNC/Setting.cs` 各一份（必须同步）
- 改动前：无此开关，开启 EnableTenant 即严格校验
- 改动后：默认 Shadow（兼容观察期），可切 Enforce（严格 fail-closed）
- 跟随调整：三个校验层的规则A分支（见 ④）

### ③ 查询策略 TenantQueryPolicy

- 枚举 `TenantQueryPolicies { DenyWithEmpty=0(默认), ThrowOnMissingTenant=1 }` → 同样在 `ManagerProviderHelper.cs` 底部
- 属性 `TenantQueryPolicy` → 两份 Setting.cs 各一份
- 改动前：无租户上下文时一律 `1=0` 假空数据
- 改动后：默认 DenyWithEmpty（不变），可选 ThrowOnMissingTenant 显式抛错
- 跟随调整：`ReadOnlyEntityController2.cs / CreateWhere`（无上下文分支三分支之一）

### ④ 规则A：Shadow 期无租户标识放行（3 处，均带 [TenantCompat] 标签）

**认证层**：`ManagerProviderHelper.cs / ValidateTenant`

- 改动前：开启多租户即 fail-closed
- 改动后：Shadow 且无标识 → ChooseTenant 回落第一个绑定租户 + 放行 + 影子日志（已绑定用户回落租户而非空上下文，是最后一轮审计补的）

**中间件层**：`NewLife.CubeNC/WebMiddleware/DataScopeMiddleware.cs`

- 改动前：无标识时落空（后续被拒或报错）
- 改动后：Shadow → 不设上下文仅记日志；Enforce + 带令牌 → 400 拒绝

**数据层**：`NewLife.Cube/Common/ReadOnlyEntityController2.cs / CreateWhere`

- 改动前：无上下文 → `1=0`
- 改动后：Shadow → 不加过滤（等同改造前行为）；Enforce → 1=0 或抛错（按③）

### ⑤ 规则B：带租户标识自动绑定（含收紧）

- 改动点：`NewLife.CubeNC/Services/UserService.cs / EnsureTenantUser`
- 改动前：只经 GetTenantId 解析（不识别 X-App-Id）；任意用户可自建绑定加入任意租户（水平越权）
- 改动后：走 `ResolveTenantForLogin`（优先 X-App-Id → OAuth 配置租户，其次 X-Tenant/Query/Cookie）+ 收紧：仅"无任何 Enable=true 绑定"的用户才自动绑定 + 审计日志（XTrace + LogProvider）
- 跟随调整（单一解析入口，同文件 ManagerProviderHelper.cs）：
  - 新增 `ResolveTenant()`（单一入口）+ `TenantResolution`（结果对象）
  - 新增 `ResolveTenantByAppId()`（私有，含 IsValidTenant 校验）
  - `HasTenantIdentifier` / `ResolveTenantForLogin` 改为委托上述入口

**验证口径说明**

- "无租户过滤"仅出现在 **Shadow + 完全无标识 + 未绑定** 的过渡形态，是方案 5.2 显式接受的 fail-open，用于观察"哪些请求会被拒"；任何带有效标识的请求都按租户过滤。
- **Enforce 无租户标识**：管理员豁免（进管理后台）；普通用户被拒（须携带租户标识）。拒绝由认证层 `ValidateTenant` 统一产出（中间件不再拦截，避免依赖用户加载时机误拒刚登录的管理员）；状态码：API 版 403「无权限访问当前租户」、NC 版 401/302（契约差异列 P1）。
- **显式标识优先校验（2026-08-16 新增）**：只要请求显式携带了有效租户标识（X-Tenant/X-App-Id/Query/Cookie），就**按所带租户**校验成员——管理员豁免但上下文用所带租户；普通用户非成员 → 403；**仅无标识**时才回落第一个绑定租户（Shadow）或拒绝（Enforce）。杜绝"请求 t2 被静默换 t1"。
- 自动绑定只发生一次（首次带标识登录），之后同租户登录走"已绑定正常校验"路径，不重复插入。

**执行性/可观察性备注（API 版 CubeDemo）**

- `/Admin/Index`、管理后台"切换租户"、管理员表格中的场景 2/6 仅 NC（MVC）版适用；API 版用 `/Auth/Info` 等受保护接口等价验证状态码。
- CubeDemo 无 ITenantScope 实体列表接口 → "数据按租户过滤/未过滤/回落"只能由状态码+日志+DB 绑定表佐证，无法端到端看行数（若需验证，请用有 ITenantScope 实体接口的业务系统，或给学校实体补接口）。
- 注意信封式错误：业务拒绝可能返回 HTTP 200 + `code:-1`（如 Enforce 无标识注册），HTTP 状态码≠业务成功。
- 占位 admin/admin 会被"首个注册用户成为管理员"逻辑降级为游客并禁用（设计行为，非缺陷）；验证管理员场景请用首个真实注册的管理员账号。
- 环境注意：CubeDemo 接入星尘配置中心，云端配置可能覆盖本地默认值（干净库首启即可能 EnableTenant=true/Enforce）；本地 `Parameter` 表非空时以本地为准。验证时请确认 `Parameter` 表实际值。
- 环境注意：通过 sqlite 直接改库/插数据后，XCode EntityCache（默认 10s TTL）不会立即看到新数据，需等待 TTL 刷新或重启（如外部插入租户后带 X-Tenant 请求可能短暂报"租户不存在"）。
