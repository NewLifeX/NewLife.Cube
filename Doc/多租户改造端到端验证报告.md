# 多租户改造端到端验证报告（修订版）

- 验证对象：`CubeDemo`（API 版，含 Swagger），https://localhost:7116
- 验证方式：命令行 HTTP（curl）+ SQLite 库内数据 + 应用日志
- 数据：全新 SQLite（`Bin\Data\*.db`）；租户 t1/t2；管理员与普通用户（见"账号"）
- 模式切换：修改 `Parameter` 表 `Cube/EnableTenant`、`Cube/TenantEnforceMode` 后重启应用

> 修订说明：第一版报告计数有误（表格实为 17 行，误写 14）且缺注册/越权收紧/无效租户等场景；本轮补验并修正。另发现两个需注意的行为（见"重要发现"）。
>
> **修订说明 2（2026-08-16）**：下述实测均为"中间件含成员校验"旧代码的结果。中间件已移除成员校验（改由认证层 `ValidateTenant` 统一授权），且新增"显式标识优先校验"后，S3/S8/S8e/M5/A3 的行为已变化：S3（Enforce 无标识）→ API 版 403「无权限访问当前租户」（非 400）；S8/S8e（非成员租户）→ 403 由认证层产出（消息「无权限访问当前租户」）；M5 → **稳定 403**（不再"首请求 200 抖动"，重要发现 1 已解决）；A3（管理员 Enforce 无标识）→ **200 豁免**（非 400）。本报告保留旧结果仅作历史对照，验证请以检查清单为准。

## 账号（重要）

- 系统初始种子账号 `admin/admin` 是**占位管理员**。按"首个注册登录用户成为管理员"逻辑，第一个真实注册的用户会成为真正管理员，占位 admin 被降级为游客并禁用（日志：`Update User Set RoleID=4,Enable=0 Where ID=1` + `Insert Into User('user04'...,RoleID=1)`）。
- 本报告管理员场景使用**真实管理员 user04**（首个注册用户，角色=管理员）。

## 结论

**21 项场景验证，20 项符合预期，1 项（普通用户 Cookie=0）行为不稳定（见"重要发现 1"）**，覆盖三点验收标准。

## 三、重要发现

### 发现 1：普通用户访问"管理后台(租户0)"行为不稳定（需进一步调查）

- 现象：Enforce 下普通用户带 `Cookie: TenantId-CubeDemo=0` 访问，**令牌刚签发后的首次请求返回 200**（认证层 ChooseTenant 回落到其第一租户 t1），稳定后返回 **403**（中间件成员校验拒绝）。
- 根因分析：中间件的成员校验依赖 `ManageProvider.User` 在中间件阶段能加载到用户；新令牌刚签发后首个请求可能加载不到（疑似 XCode EntityCache 对刚插入的 UserToken 行存在刷新时序），导致成员校验被跳过、由认证层 ChooseTenant 兜底回落。
- 影响评估：**非越权**（回落的是用户自己的租户 t1，而非管理后台数据），但"租户0 拒绝"的校验时机不稳定。建议按 P2 排查（重点：中间件 `ManageProvider.User` 与 XCode 缓存时序）。

### 发现 2：S7"回落第一租户"仅由状态码+日志推断

- 中间件/认证层日志未记录落点租户 ID，200 只能证明"放行"；"回落 t1"是依据 `ChooseTenant` 逻辑推演 + 绑定表唯一性佐证，未端到端看到过滤后的数据行数。CubeDemo 无租户作用域（ITenantScope）列表接口，数据过滤层面无法在此端到端观察（属验证环境限制，非实现缺陷）。

### 发现 3：占位 admin 会被"首个注册用户"机制降级

- 属既有设计（登录页提示"首个注册登录用户成为管理员"）：第一个真实注册用户成为管理员，占位 admin/admin 被降为游客并禁用。**不是租户功能缺陷**，但验证时容易误判（第一轮报告即因此踩坑）。

## 六、复现步骤

1. 清理：删除 `Bin\Data\*.db`（干净数据）；注意 appsettings 相对路径 `..\Data` 实际落在 `Bin\Data`
2. 启动：`cd CubeDemo && dotnet run`（默认 EnableTenant=false）→ 端口 7116
3. 注册：`POST /Auth/Register` 无标识注册（首个用户成为管理员，占位 admin 随后被降级）
4. 开多租户：停应用 → sqlite 改 `Parameter` 表 `EnableTenant=true`、`TenantEnforceMode=Shadow` → 重启
5. 触发建表 + 建租户：`POST /Auth/Login` 带 `X-Tenant:t1`（触发 Tenant 建表）→ sqlite 插 `Tenant(Code='t1'/'t2')`
6. 按上文场景执行；切 Enforce：停应用 → 改 `TenantEnforceMode=Enforce` → 重启
7. 验证 Cookie 场景注意系统名：租户 Cookie 键为 `TenantId-{SysConfig.Name}`（本示例为 `TenantId-CubeDemo`）

## 七、验证环境限制（非缺陷）

- CubeDemo（API 版）无 MVC 管理页（`/Admin/Index`、租户切换按钮仅 NC 版适用）
- 无 ITenantScope 实体列表接口 → "数据是否按租户过滤/未过滤"无法端到端观察，只能验证状态码与日志
- 注册/登录错误以 HTTP 200 + 业务 code 返回为主（信封式），HTTP 状态码并非业务是否成功的唯一判据（如 M1 注册拒绝是 HTTP 200 code:-1）
