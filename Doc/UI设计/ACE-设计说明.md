# ACE 皮肤设计审查与改进说明

> 本文档配合 [`ACE-列表页.html`](ACE-列表页.html)、[`ACE-表单页.html`](ACE-表单页.html) 两份设计稿使用，说明审查结论、设计方案与落地映射。
> 状态：**设计稿待确认**（确认后实施）。
> 审查对象：MVC 版魔方（NewLife.CubeNC）ACE 主题皮肤，生产参考 https://sso.newlifex.com。

---

## 1. 审查背景

用户反馈：**列表页表格的分界线不明显、偏淡**。本次审查站在设计师视角，逐页面核对 ACE 皮肤（列表页 / 表单页 / 工作台 / 系统信息页 / 框架布局）的设计细节，判断该反馈属于设计缺陷还是个人偏好，并给出解决方案。

---

## 2. 分界线问题定性：部分偏好、部分瑕疵

| 维度 | 判断 | 依据 |
|------|------|------|
| 线的深浅值 | **偏好问题** | 极简轻线（Ant Design 派）与清晰网格各有拥趸，无唯一正确答案——不同用户群偏好不同，不应单方面改深或改浅 |
| 多机制弱化共存 | **客观瑕疵** | 现状同时使用 4 种分隔机制：行线 `#f0f2f5`、竖线 `#f0f2f5`、斑马纹 `#fbfcfd`、悬停 `#f7fafd`——全部处于"似有似无"状态，无主无次。设计上应"一主一辅"（以行线为主，或斑马纹为主） |
| 对比度 | **低于可辨阈值** | 行线 `#f0f2f5` 对白底对比度约 1.06:1，1080p 屏幕上基本不可辨，横向串行（读错行）风险客观存在 |

**结论**：深线浅线属偏好，但现状"多机制全弱化"叠加"对比度不足"构成实际体验问题。**解决方案：提供配置项（三档分隔样式），每档内部机制主次分明；默认"标准"档解决"看不清"问题**。

## 4. 设计方案（详见两份 HTML 设计稿）

### 4.1 表格分隔样式三档

| 变量 | 轻量 Light | 标准 Standard（默认） | 网格 Grid |
|------|-----------|----------------------|-----------|
| 行线 | `#eef1f4` | `#e5e9ee` | `#e2e7ec` |
| 竖线 | 无 | 无 | `#e2e7ec` |
| 斑马纹 | `#fbfcfd` | `#fafbfc` | 无（靠线分隔） |
| 悬停 | `#f5f9fc` | `#f0f6fb` | `#eef4fa` |
| 表头底线 | `#e4e6e9` | `#e0e5ea` | `#e2e7ec` |
| 定位 | 极简现代、快速扫读 | 平衡可读与轻盈（推荐） | 完整网格、数据密集/对账 |

三档共同保留：外框 `#e4e6e9` + 圆角 10px、表头底色 `#f5f8fc`（既有视觉不变）。

**设计原则（每档内部"一主一辅"）**：
- 轻量/标准档：**行线为主**（横向引导），斑马纹极浅为辅，无竖线；
- 网格档：**完整单元格网格**（横+竖）为唯一分隔机制，关闭斑马纹避免噪音叠加。

### 4.2 行高密度两档

| 档位 | 表头 padding | 单元格 padding | 定位 |
|------|-------------|---------------|------|
| 紧凑 Compact（默认） | 6px 8px | 4px 8px | 现状，一屏信息量大 |
| 适中 Normal | 9px 12px | 9px 12px | 呼吸感更强，长时间阅读更舒适 |

### 4.3 按钮语义修正（表单页）

三级视觉权重：**主操作（实底绿）＞ 警示（描边橙）＞ 次要（描边灰）**。
- 清空密码：`btn-success` → 描边警示样式（白底橙边橙字，hover 浅橙底）
- 取消：`btn-danger` → `btn-default` 中性色

## 6. 实施与验证记录（2026-09-10）

本设计稿已完成实施并通过端到端验证。

**实施产物**：详见 §5 落地映射——`CubeSetting.TableStyle/TableDensity` 配置项、魔方设置页下拉、`_Layout` body class 注入、`ace-ui.css` 三档+两密度样式、按钮语义修正。

**验证结果**：
- 构建：NewLife.CubeNC 全 TFM（net6.0~net10.0）0 警告 0 错误；
- 单元测试：`CubeSettingTableStyleTests` 2/2 通过；
- E2E（`E2EMvcTest/AceUiTests`）：`TC-ACE-041`（标准档单线行分隔）、`TC-ACE-046`（三档 CSS 生效）、`TC-ACE-047`（配置项存在）全部通过；
- 浏览器实测：本地 CubeSSO 在魔方设置页将 `TableStyle` 改为 `Grid` 后保存，服务端配置热重载（日志"配置改变，重新加载"），列表页 body class 与竖线样式实时生效；随后恢复 `Standard`。

**实施中发现并修复的既有缺陷**（非本设计稿引入）：
- NC 版登录模型 `CaptchaId/CaptchaCode/ChallengeId` 为非空声明，在 `Nullable` 标注下被 MVC 隐式推断为必填，导致密码登录 100% 被误拦（报 `The CaptchaId field is required.`）；已改为可空（与 API 版同名模型对齐，含注释说明原因）。
- User 表单"清空密码"按钮在 Add 页同样显示，且因 `Factory.Create(true)` 预分配主键（`IsNullKey=false`）而指向已存在实体 ID——**建议后续修复**（本稿仅修正了按钮视觉语义，未动该判定逻辑）。

**验证环境说明**：本地 E2E 须通过编排脚本 `dotnet run scripts/e2e-mvc.cs` 运行（脚本负责发布应用并隔离数据目录）；直接 `dotnet test` 会因应用接入星尘配置中心（生产下发的相对路径连接串）而连到非隔离数据库。

**后续建议**：
1. 其它 MVC 皮肤（layui / AdminLTE 等）如需跟进，可复用 `CubeSetting.TableStyle/TableDensity` 配置约定（当前仅 ACE 主题消费）；
2. E2E 既有失败用例建议另行处理：`TC-ACE-020`（Add 页按钮显示"保存"，与 isNew 判定相关）、`TC-ACE-003`（/Admin 首页无展开子菜单——新库未配置 StartPage 时无激活菜单，属环境数据差异）。

## 7. 风格边界原则（防止风格漂移）

> ACE 皮肤的定位是"经典默认皮肤"（老用户零适应）。现代化改造必须在明确边界内进行——本节为治理规则，后续任何视觉改动均须对照。

### 7.1 三层结构

| 层 | 范围 | 原则 |
|----|------|------|
| 品牌外壳层 | 顶栏（`#438eb9`）、侧栏布局形态、面包屑、品牌蓝语义 | **ACE 基因保留**——不做 reshape；仅允许"过渡带精修"级改动（阴影/分隔/交互过渡/活动指示） |
| 内容工作层 | 卡片、表格（三档）、表单、工作台、分页器 | **现代中性令牌**——主色 `#2b7dbc`（ACE 蓝同族深色）、小圆角、柔和阴影 |
| 组件桥接层 | 按钮、徽章、开关、下拉等控件 | 优先中性现代；**避免借用外部体系极端值**（如 Ant 的极浅表格线），取 Bootstrap/GitHub 系中庸值 |

### 7.2 过渡带精修（2026-09-10 实施）

在**不改静态色**（E2E 断言锁定 `#438eb9` / `#f2f2f2` / `#f8f8f8` 等）的前提下，以"层次 + 交互 + 指示"消解两代质感断层：

| 项 | 实现 |
|----|------|
| 顶栏 | 底部柔和投影（`0 1px 4px rgba(0,0,0,.08)`），与内容区形成层次 |
| 侧栏 | 右侧中性分隔线 `#e4e6e9`（原为皮肤蓝调边框） |
| 一级菜单 | hover 浅蓝反馈 `#edf3f9` + 主色文字（对齐 ACE 原生 `li:hover` 触发方式，`!important` 覆盖）；活动项左侧 3px 主色指示条（inset 阴影实现，不占布局） |
| 二级菜单 | hover 浅蓝、当前项浅蓝底 `#e8f1f9` + 主色文字加粗 |
| 动效 | 菜单项背景/文字 0.15s 过渡 |

### 7.3 维护规则

1. 改动框架区（顶栏/侧栏）前，先核对 `AceUiTests` 中 `TC-ACE-002/003` 的静态色断言（锁定外壳基线）；
2. 内容区新增组件遵循"现代中性令牌"，主色/圆角/边框取既有 `--cube-*` 变量；
3. 视觉风格如需全面换代（含外壳），应新建/切换皮肤（如 Tabler 等），而非突破本节边界改造 ACE。

## 8. 设计稿对齐修复记录（2026-09-10 第二轮）

按两份设计稿复核真实页面（本地 CubeSSO）时发现实现与设计稿的四处不一致，均已修复并以 E2E 锁定。

### 8.1 问题与根因

| 现象 | 根因 |
|------|------|
| 表单页聚焦态呈 ACE 原生**橙色边框**（`#f59942`）且无光圈，与设计稿的主色光圈不符 | `ace.min.css` 用 `input[type=text]:focus` 等（特异性 0,2,1）压过原规则的 `.form-control:focus`（0,2,0） |
| 日期/邮件/手机控件"**左侧图标直角四方 + 右侧输入框圆角**"错位 | `ace.min.css` 的 `.input-group .input-group-addon{border-radius:0!important}` 压过无 `!important` 的覆盖规则；输入框侧则被基础圆角规则给了四角圆角 |
| 列表页关键字输入框与查询按钮**紧贴**（实测间距 −1px） | 原样式把两者做成拼接式 `input-group`（输入框右侧直角 + 按钮左侧直角），与设计稿"两个独立控件 + 间距"不符 |
| 表单输入框偏高（34px）、边框色偏深（`#d5d5d5`） | ACE 元素+属性选择器（`input[type=text]`）胜过类选择器 `.form-control` |

> 共性根因：ACE 皮肤用**元素 + 属性**选择器与 `!important` 锁定了输入类控件的圆角、边框色与聚焦态，常规类选择器覆盖无效。

### 8.2 改动清单（`ace-ui.css`）

- **聚焦态**：选择器提升为 `input/textarea/select.form-control:focus`（0,2,1）并加 `!important` → 主色边框 `#2b7dbc` + `0 0 0 2px rgba(43,125,188,.15)` 柔光圈；
- **输入组拼接**（全局生效）：`.input-group > .input-group-addon:first-child` 改为左圆角且去掉右侧边框（`border-right-width:0`），紧随其后的输入框/按钮改为 `0 6px 6px 0`，形成单线无缝拼接；
- **列表页搜索区**：关键字输入框与"查询"按钮改为两个独立控件，按钮单元左侧留 12px（实测视觉间距 11px），两者各自保持完整圆角；
- **表单控件尺寸**：`.form-horizontal` 内 `input/select.form-control` 统一 30px 高（`multiple` 多选框除外）、边框色统一 `#d5dbe3`。

### 8.3 验证

- **渲染实测**（Playwright 采集计算样式）：聚焦态 `rgb(43,125,188)` + `rgba(43,125,188,.15) 0 0 0 2px`；addon `border-radius:6px 0 0 6px`、`border-right-width:0`；输入框 `0 6px 6px 0`、高度 30px；搜索框与按钮间距 11px；
- **E2E**：新增 `TC-ACE-048`（表单控件规范：聚焦态/高度/输入组拼接）、`TC-ACE-049`（搜索框与按钮分离）；`AceUiTests` 全量 18/20 通过（2 个既有失败见 §6）；
- **浏览器实测**：独立实例逐页复核列表页、表单页、系统日志页（含日期区间搜索）视觉一致。

### 8.4 维护要点

后续再调整输入类控件样式时，须以 `input.form-control`、`.input-group > …` 这类**同等或更高特异性**的选择器书写；否则会被 `ace.min.css` 的元素+属性选择器与 `!important` 规则压过（聚焦态与 addon 圆角均属此类陷阱）。
