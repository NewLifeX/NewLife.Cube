# 魔方皮肤设计规范

> 版本：v2.0 | 日期：2026-08-29
>
> 本规范定义魔方所有皮肤（第二代 MVC 主题 + 第三代 SPA 前端）应遵循的统一设计理念，确保任何皮肤给用户带来一致的使用体验。
> 各皮肤实现现状的合规评估见《[皮肤现状审计](皮肤现状审计.md)》，本规范正文只写要求，不随现状频繁改动。
> **核心读者是 AI**：开发者借助 AI 实现新的魔方皮肤时，按本规范逐模块核对，可快速落地各项魔方功能、避免遗漏。

---

## 1. 目的与适用范围

### 1.1 目的

魔方经历了第一代 MVC 版本（NewLife.CubeNC，第二代魔方）和第三代 API 前后端分离版本（NewLife.Cube），无论哪一代都拥有多种皮肤。为了让这些皮肤具有相同的设计理念，特制定本规范。

### 1.2 适用范围

| 代际 | 类型 | 皮肤 |
|------|------|------|
| 第二代（MVC） | 主题皮肤 | AdminLTE / Tabler / Metronic / Metronic8 / LayuiAdmin / ElementUI |
| 第三代（API） | SPA 前端皮肤 | Vue / React / NaiveUI / ArcoVue / Vuetify / TDesign / MUI / Shadcn / Angular / Svelte / Blazor |

### 1.3 规范层级

| 级别 | 含义 |
|------|------|
| **【必须】** | 所有皮肤都必须满足，不满足即视为缺陷 |
| **【推荐】** | 建议满足，皮肤可按自身框架能力渐进实现 |
| **【按配置】** | 后端能力通过配置启用时，皮肤需提供对应界面 |
| **【自由】** | 不约束，各皮肤自行决定 |

### 1.4 规范边界【重要】

1. 本规范只约定【必须】项与推荐的能力项，**规范约定之外的内容，各皮肤可以自由发挥**。
2. 例如：登录页除了登录/注册等功能外是否显示其它内容（宣传语、公告、演示入口、备案信息等）、如何定制登录页，都可以由各皮肤自行决定；后端登录配置（`LoginConfig`）提供一部分支持。
3. 视觉风格、配色、动效、组件库选择等均不约束，皮肤按自身框架特点实现，**只要满足本规范的功能能力与交互理念即可**。

> **遵循原则**：皮肤可以有自己的视觉风格与技术实现，但功能能力与交互理念必须一致。规范的最终目标是"任何皮肤都能完成同样的管理操作，且方式一致"。

### 1.5 AI 使用说明

本规范核心读者是 AI。当 AI 协助实现新皮肤时：

1. 按 §2~§9 逐模块核对功能点，**优先满足【必须】项**
2. 使用 §10 的"AI 实现检查清单"逐项勾选，避免遗漏
3. 所有后端能力均已实现，AI 直接调用后端接口，不重新发明

## 2. 登录页规范

登录页是用户接触系统的第一界面，也是各皮肤差异最大的地方。按能力完整度分为三档。

### 2.1 基础要求【必须】

无论何种皮肤，登录页都必须支持以下三种能力：

1. **密码登录**：支持用户名/邮箱/手机号 + 密码登录
2. **用户注册**：支持用户名 + 密码注册
3. **第三方登录**：系统配置了 OAuth 平台（微信/钉钉/GitHub/QQ/支付宝等）时，登录页显示对应第三方登录入口

> 对应后端能力：`AuthController.Login` / `Register` / `OAuth`。

### 2.2 高级要求【按配置】

以下能力后端已具备，当系统通过配置启用时应提供对应界面（建议按后端能力配置驱动 UI 渲染，而非硬编码）：

1. **手机验证码登录 / 注册**：`category=mobile`，发送短信验证码后登录或注册
2. **邮箱验证码登录 / 注册**：`category=mail`，发送邮件验证码后登录或注册
3. **手机 / 邮箱密码找回**：忘记密码流程，通过手机或邮箱验证码重置密码
4. **图片验证码**：`login.captcha=true` 时显示 SVG 图形验证码，防止自动化攻击

> 对应后端能力：`AuthController.Login`（category 区分）、`Register`、`DrawingCaptchaService`（SVG 图形验证码）、`AUTH-验证码服务.md`。

### 2.3 密码传输安全【按配置】

登录密码的非对称加密传输，**是否强制由后端配置决定**，皮肤按配置实现：

| 后端配置 `AllowPlainPassword` | 行为 | 皮肤要求 |
|------|------|----------|
| `true`（默认） | **同时支持明文登录与非对称加密登录** | 优先使用非对称加密；用户环境不支持时可用明文兜底 |
| `false` | **仅支持非对称加密，拒绝明文登录** | 必须调用后端 `Challenge` 接口获取公钥与一次性 `challengeId`，加密密码后提交 |

- **非对称加密方案**：Challenge-Response，RSA-OAEP/SHA-256，`challengeId` 限时一次性防重放（后端 `AuthController.Challenge`，对应需求 AUTH-4）
- **实现方式**：前端通过后端登录配置感知是否强制加密，需要时调用后端加密能力，**不在前端自行实现加密算法**
- **失败提示**：登录失败需给出明确提示；连续失败触发账号/IP 封禁时，提示用户稍后再试

### 2.4 完整能力矩阵与实现指引

下表为登录页完整能力矩阵，供皮肤自查：

| # | 能力 | 级别 | 后端能力 |
|---|------|------|----------|
| 1 | 密码登录（用户名/邮箱/手机） | 【必须】 | `AuthController.Login` |
| 2 | 用户名密码注册 | 【必须】 | `AuthController.Register` |
| 3 | 第三方登录入口 | 【必须】 | OAuth 配置 |
| 4 | 手机验证码登录/注册 | 【按配置】 | `Login(category=mobile)` / `Register` |
| 5 | 邮箱验证码登录/注册 | 【按配置】 | `Login(category=mail)` / `Register` |
| 6 | 手机/邮箱密码找回 | 【按配置】 | `ForgotPassword` 流程 |
| 7 | 图片验证码 | 【按配置】 | `DrawingCaptchaService`（SVG） |
| 8 | 密码非对称加密传输 | 【按配置】 | `AuthController.Challenge`（RSA-OAEP），`AllowPlainPassword` 控制是否强制 |
| 9 | MFA 二次验证 | 【按配置】 | `TotpMfaService` / `MfaController` |
| 10 | 账号未激活重发激活 | 【按配置】 | `AccountActivateService` |

**实现指引（能力开关驱动 UI）**：推荐前端先请求后端登录配置（如 API 版 `LoginConfig`），按返回的能力开关渲染对应输入区，避免硬编码，也避免后端禁用某能力时前端仍显示入口。可参考：
- React 皮肤 `web/src/pages/Login`（`useLoginConfig` 能力开关 + Challenge 加密 + MFA + 激活重发）
- Vue 皮肤 `LoginPage.vue` + `LoginForm.vue`
- 设计稿：`Doc/UI设计/登录页-API版.html`、`登录页-MVC版.html`

### 2.5 登录页自由定制【自由】

- 除上述功能外，登录页**是否显示其它内容**（系统介绍、公告、备案信息、演示账号提示等），由各皮肤自行决定
- 登录页的整体视觉、布局、动效自由设计
- 后端登录配置提供部分支持（能力开关、默认标题/Logo 等），皮肤应优先读取后端配置渲染，减少硬编码

## 3. 后台布局规范

### 3.1 布局形态【必须】

登录成功进入管理后台后，页面布局常见以下三种形态，皮肤可根据自身框架能力选择其一或组合：

1. **左右布局**：左侧是菜单，右侧是内容区。菜单可能不止两级，可能有三四级，需支持多级菜单的展开/收起。
2. **上下布局**：上方是菜单栏，下方是子菜单（一级菜单在上方横向排列，子菜单在下方）。
3. **混合布局**：当菜单比较多时，上方导航栏列出各个模块，进入某个模块后，左侧切换该模块底下的不同菜单。

### 3.2 用户信息区【必须】

不管采用哪种布局，页面右上角、左下角或其它合适位置**必须有用户信息区**：

1. **头像 + 昵称**：显示当前登录用户的头像与昵称（或用户名）
2. **退出登录【必须】**：提供退出登录（注销）功能，退出后回到登录页
3. **可选能力**：
   - 跳转工作台首页（推荐有，点击 Logo 或"首页"入口）
   - 显示用户角色
   - 个人设置、修改密码、安全中心等（与《魔方用户手册》1.2.1 保持一致）

### 3.3 首页【推荐】

不管哪一种皮肤，都建议将首页设计为**工作台**（Dashboard），登录后首先看到工作台页面，而非某个具体功能页。工作台规范见下一节。

### 3.4 移动端兼容【推荐】

各皮肤布局应对**手机和平板**有比较好的兼容：

| 设备 | 要求 |
|------|------|
| 手机 | 优先适配。窄屏下菜单收敛为抽屉/弹出层，内容区自适应，不横向溢出 |
| 平板 | 自适应。侧边栏可收起/半展开，内容栅格响应式 |
| 折叠屏 | 折叠屏手机展开后宽度相当于平板，布局应随之自适应（栅格响应式、侧边栏可收起） |

- 表格在窄屏下不破版（允许横向滚动）
- 查询区、表单在窄屏下自适应换行，不挤压
- 常用操作（退出登录、菜单切换）在移动端可达

## 4. 工作台规范【推荐】

> 工作台作为**推荐**能力（而非必须）。建议所有皮肤都支持；若皮肤暂不实现，也应保证登录后能进入可用的管理页面。

### 4.1 卡片类型

工作台（Dashboard）是登录后的首页，集中展示系统概况与快捷入口，由若干卡片组成。卡片类型与 MVC 版 `WidgetTypes` 对应：

| 类型 | 说明 | MVC 对应 | 示例 |
|------|------|----------|------|
| 指标卡（KPI） | 大数字 + 标签 + 图标，展示统计指标 | `Kpi` | 用户总数、今日登录、在线用户、24h 日志 |
| 图表卡（Chart） | 定时轮询接口渲染图表 | `Chart` | CPU/内存实时曲线 |
| 列表卡（Content） | 展示数据列表局部视图 | `Content` | 最近登录、快捷链接 |
| HTML 卡（Html） | 直接渲染 HTML 内容 | `Html` | 自定义富文本 |
| 自定义卡（Kv/自定义） | 键值表或自定义组件 | `Kv` | 服务器信息、个人信息 |

### 4.2 卡片能力【建议】

工作台卡片**建议**支持以下三种交互能力（非必须）：

1. **拖动排序**：用户可拖动卡片调整布局顺序
2. **保存顺序**：排序结果持久化保存（按用户保存到服务端，重新登录/刷新后保持）
3. **隐藏**：用户可隐藏不需要的卡片，可再次开启

### 4.3 卡片元数据规范（MVC 积累）

从 MVC 版 Widget 体系（`WidgetAttribute` / `WidgetManager`）沉淀的卡片元数据，供各皮肤设计工作台数据契约时参考：

| 元数据 | 说明 |
|--------|------|
| 标题 / 图标 | 卡片头显示，图标随皮肤图标体系 |
| 栅格宽度 | 1~12 栅格，控制卡片占宽；≤3 时按 KPI 小卡渲染 |
| 排序 | 越小越靠前，运行时可由用户布局覆盖 |
| 分类 | 系统 / 个人 / 业务模块，同组卡片聚合显示 |
| 可见角色 | 逗号分隔的角色名，空表示所有登录用户可见 |
| AdminOnly | 仅系统角色可见，常用于系统监控类卡片 |
| KPI 配色 | 蓝/绿/青/橙/红/紫/灰，语义区分 |
| 图表刷新 | 数据接口 + 刷新间隔（秒），定时轮询追加数据 |

**卡片权限**：按角色 + 管理员标志过滤——管理员显示系统监控/日志卡片，普通用户显示个人相关卡片。

### 4.4 后端接口

| 版本 | 接口 | 说明 |
|------|------|------|
| MVC 版 | `WidgetManager` 扫描注册 / `WidgetController` 启停 / `SaveOrder` 保存排序 | `Parameter` 表按用户持久化（分类 `Widget.Enable` / `Widget.Layout` / `Widget.Group`） |
| API 版 | `IndexController.Workbench` 聚合端点 + `MonitorData` 监控端点 | 前端直接消费，不自行实现存储 |

### 4.5 设计参考

工作台的内容布局可参考 MVC 版工作台设计稿（视觉较完善）：
- 设计稿：`Doc/UI设计/工作台.html`
- 说明文档：`Doc/UI设计/工作台设计说明.md`

**各皮肤应参考其内容布局，使用自己皮肤的视觉风格去实现**——布局理念一致，视觉随皮肤风格。

典型布局层次（自上而下）：
1. 欢迎横幅：问候 + 日期 + 系统状态 + 操作按钮
2. KPI 指标行：多张彩色图标指标卡
3. 主内容区：大图表卡 + 快捷链接
4. 底部信息区：日志中心、服务器信息、个人信息、最近登录等

## 5. 菜单规范

### 5.1 权限过滤【必须】

左侧（或上方）菜单栏显示当前用户**有权限访问**的菜单，无论是父级还是子级，都要根据当前用户的权限进行过滤：

1. **父级 + 子级都过滤**：无权限的父级菜单及其子菜单都不显示
2. **多角色取并集**：一个用户具有多个角色，每个角色有自己的菜单、范围各不相同，最终显示的是这些角色菜单的**并集**
3. **使用后端可用菜单接口**：MVC 版与 API 版都有方法直接返回当前用户的可用菜单，皮肤直接调用，不在前端自行拼装

> **实现指引**：参考后端菜单接口（`ManageProvider.Menu` / `Menu.FindAllWithCache` 按权限过滤），API 版可通过用户信息接口获取可用菜单树。菜单树的构建、权限判断由后端完成，前端只负责渲染与交互。

### 5.2 菜单图标【必须】

每个菜单项必须显示图标，帮助用户快速识别功能。跨皮肤图标兼容说明：

- 数据库菜单图标目前采用图标字体命名（如 FontAwesome `fa-table`），不同皮肤框架的图标体系各不相同，可能不适用
- **推荐方案**：以 Element Plus 图标命名为跨皮肤标准（`Monitor` / `UserFilled` / `Odometer` / `DataBoard` / `CirclePlus` 等），各皮肤建立自己的图标映射表，兼容 Element Plus + FontAwesome（`fa-*`）+ 本框架图标（如 antd `XxxOutlined`）
- 皮肤需自行处理映射或兼容，保证菜单图标在各皮肤下都能显示

> **实现指引**：参考 React 皮肤 `web/src/utils/icon.tsx` 的 `ICON_MAP`（兼容 Element Plus + FontAwesome + antd），图标选择器存入的值也采用 Element Plus 名（跨皮肤兼容），渲染时经映射转为当前皮肤图标。

### 5.3 多级菜单与选中态【推荐】

从 MVC 版菜单视图（`_Left` / `_Layout_Menu`）积累的交互细节：

1. **多级菜单**：支持多级菜单的展开/收起，子菜单缩进或分级呈现
2. **当前菜单高亮**：当前页面所属菜单项高亮显示（父级同时展开）
3. **面包屑导航**：内容区顶部显示层级路径（首页 > 一级 > 二级 > 当前页），可点击返回（与《魔方用户手册》1.2.3 一致）

### 5.4 快捷入口与常用菜单【推荐】

工作台或顶部可提供快捷入口/最近访问。注意过滤掉后端区域根菜单（URL 形如 `~` 或 `~/xxx`，如 `~/Ai`、`~/Sso`），否则点击会 404。

## 6. 路由与多标签规范

### 6.1 URL 路由【必须】

点击菜单切换页面时，**地址栏 URL 必须跟随切换**（History 路由模式）：

1. **URL 跟随**：切换不同页面时，地址栏 URL 同步变化
2. **分享直达**：复制地址栏 URL 发给他人，对方打开该地址即可直接访问对应页面（刷新不 404）

> **实现指引**：SPA 皮肤使用 History 路由（react-router / vue-router history 模式），后端通过 `MapFallbackToFile("index.html")` 实现回退路由（对应需求 SPA-3）。MVC 版天然满足。

### 6.2 多标签【推荐】

很多皮肤的菜单与内容页支持**多标签（Tabs）**访问，规范要求：

1. **标签名与菜单关联**：打开新标签时，标签页名称应与菜单名称关联（默认取菜单名）
2. **允许自定义**：允许用户自定义标签名称
3. **禁止统一显示默认页面**：不允许所有标签都显示"默认页面"这种无意义名称

## 7. 列表页规范

菜单点开的页面默认就是该实体控制器的**列表页**。列表页一般分为**工具栏** + **查询区域** + **数据表格区域** + **分页**，可选**图表区域**。

### 7.1 页面结构【推荐】

参考 MVC 版 `List.cshtml` 的页面结构：

```
┌─────────────────────────────────────────────┐
│ 导航视图（可选，自定义页面顶部）               │
├─────────────────────────────────────────────┤
│ 工具栏：添加 | 批量操作 | 自定义 | 搜索 | 高级  │
├─────────────────────────────────────────────┤
│ 图表区域（可选，表格上方）                     │
├─────────────────────────────────────────────┤
│ 查询区域（搜索条件）                          │
├─────────────────────────────────────────────┤
│ 数据表格（核心，占主要空间）                   │
├─────────────────────────────────────────────┤
│ 分页                                        │
└─────────────────────────────────────────────┘
```

### 7.2 查询区域【必须】

1. **布局与尺寸**：查询区域一般占据 100% 宽度，高度不要太高（紧凑的横向表单）
2. **元素与设计**：左侧（或区域内）可放置按钮（新增/导出等），皮肤根据情况设计
3. **交互优化**：如果查询条件太多，支持折叠（展开/收起），避免查询区过高挤压表格
4. **常用查询控件**（MVC 积累）：关键字搜索、日期范围（含快捷区间）、枚举下拉、多选搜索

### 7.3 数据表格区域【必须】

数据表格是列表页的核心，必须让它**显示得尽量完整，不被其他内容挤压**：

1. 表格区域尽量占满剩余空间，不被查询区、分页区过度挤压
2. 列宽根据字段类型和内容长度控制（见 7.5）
3. 表格支持排序、分页等标准交互

### 7.4 单元格类型渲染【推荐】

> 以下细节源自 MVC 版视图 10 年打磨（`_List_Data_Item.cshtml`），各皮肤**强烈建议**按同理念实现，保证数据可读性。

| 字段类型 | 渲染规范 |
|----------|----------|
| 主键 / ID | 居中对齐，简洁显示 |
| Boolean | 居中对齐，用图标（✓/✗）或开关表示；`Enable` 等启停字段可点击直接切换（需后端支持） |
| 日期时间（字段名以 Date 结尾） | `yyyy-MM-dd` 日期格式 |
| 日期时间（其它） | 完整日期时间格式（到时分秒） |
| Decimal | 右对齐，两位小数（`n2`） |
| Double / Single | 默认右对齐；百分比字段（ItemType=percent）按百分比格式显示 |
| 百分比 | 按字段精度格式化（`p{scale}`），注意字段描述中"十分之一/百分之一/千分之一/万分之一"的量级说明，需换算后展示 |
| 整数（Int 系列） | 右对齐，千分位分隔（`n0`） |
| 枚举 | 居中，显示枚举描述而非数字 |
| 外键 ID（如 CreateUserID） | 显示关联对象名称（用户名），而非编号 |
| 外键映射（MapField） | 居中，可点击链接跳转详情 |
| IP 地址 | 居中，悬浮显示 IP 归属地 |
| 大文本 | 限制最大宽度（如 600px），超长省略号 + 悬浮完整内容 |
| 超链接列 | 自定义列（ListField.Url + 模板参数），点击跳转 |
| 按钮列 | 行内操作按钮（查看/编辑/删除等），危险操作二次确认 |
| 彩色文字 | 按值动态着色（如超期红色、正常绿色），通过单元格样式类实现 |
| 彩色行底色 | 按行状态着色（如异常行红色底色），通过行样式回调实现 |
| 统计行 | 表格底部总计行（主键列显示"总计"，数值列显示合计，金额用货币格式） |

### 7.5 列宽规范【必须】

每列的宽度要根据字段类型和内容长度控制好，**宁可显示横向滚动条，也不要把各列压得很挤导致列头/数据完全看不到**：

| 字段类型 | 建议最小宽度 | 说明 |
|----------|-------------|------|
| ID / 数字 / 枚举预期类型 | ≥ 80px | 短内容，够用即可 |
| 时间类型（带时间） | ≥ 140px | 需完整显示日期时间（MVC 实测 Date 80px / 完整时间 134px） |
| 字符串类型 | 按内容长度自适应 | 根据字段长度微调，长文本可留更多空间或截断 |

> **原则**：前端各皮肤尽量做到较好的**自适应**，不需要做太多设置；当列数多、宽度不足时，允许表格出现横向滚动，而不是把列挤压到无法阅读。

### 7.6 表格与图表视图【推荐】

MVC 版受限于服务端渲染，只能在表格**上下两侧**放置图表（`Charts` / `Charts2`），属于无奈之举。API 前后端分离版应有更好的布局设计：

1. **视图切换**：提供**数据表视图**与**图表视图**的切换（如 Tabs / Segmented），图表独立成视图，不与表格争抢空间
2. 图表视图可复用后端图表数据接口（`GetChartData` / `MonitorData`），前端用 ECharts 等渲染
3. 图表自适应容器宽度，窗口缩放时自动重绘

### 7.7 分页【必须】

数据表格下方提供分页控件：当前页码、总页数、上一页/下一页、每页条数选择、总记录数显示（与《魔方用户手册》2.1.1 一致）。

### 7.8 工具栏与高级菜单【必须】

**工具栏**包含：添加按钮、批量操作区、自定义按钮、搜索、高级菜单。

**高级菜单**（MVC 版 `_List_Toolbar_Adv.cshtml` 积累）：

| 功能 | 级别 | 说明 |
|------|------|------|
| 导出 Excel | 【必须】 | 中文表头，含扩展属性，用于 Excel 查看 |
| 导出 Csv | 【必须】 | 英文表头，快速导出，用于数据传输 |
| 导出 Xml / Json / Zip | 【必须】 | 多种导出格式（Zip 为打包导出） |
| 导入 Excel / Json / Zip | 【必须】 | 文件上传导入（accept 限制格式） |
| 删除选中（批量删除） | 【必须】 | 配合表格多选，二次确认 |
| 删除全部 | 【必须】 | 删除当前查询的所有数据，二次确认 |
| 备份 / 还原 | 【按需】 | 全表备份到服务器本地目录 / 还原 |
| 备份导出 | 【按需】 | 备份全表并下载 |
| 分享 | 【按需】 | 把当前页数据分享给其他人 |
| 同步 | 【按需】 | 清空并从主服务器同步数据 |

### 7.9 操作列【必须】

表格最后一列（有权限时显示）为**操作列**：

1. **查看**：有查看权限时提供（只读控制器或无可编辑权限时）
2. **编辑**：有编辑权限时提供
3. **删除**：有删除权限时提供，危险操作二次确认
4. **软删除恢复**：实体含 `Deleted/IsDelete` 软删除字段时，已删除行显示"恢复"而非"删除"

## 8. 表单页规范

表单页用于新增、编辑、查看（详情）实体数据。进入表单页的形式各皮肤自己处理。

### 8.1 进入形式【自由】

各皮肤可按自身框架能力选择，均可：

1. **跳转独立页**：新增/编辑/详情为独立路由页面
2. **弹出模态窗**：在列表页上弹出 Modal 表单
3. **右侧抽屉**：手风琴/抽屉式面板从右侧滑出
4. **列表页就地编辑**：简单页面可在列表页内联编辑（行内编辑）

> 复杂表单建议独立页或大抽屉；简单表单可模态窗或就地编辑。各皮肤自行权衡。

### 8.2 布局【推荐】

1. **分组展示**：字段按分类（Category）分组，多分组时用 Tabs 或分组卡片展示
2. **响应式栅格**：普通字段占约 1/3 宽（栅格自适应，如 `col-12 / col-sm-6 / col-lg-4`），窄屏自动换行
3. **全宽字段**：大文本、HTML 编辑器、Markdown 编辑器占整行（全宽），提升编辑体验
4. **隐藏自动维护字段**：主键、自增 ID、创建/更新时间等自动维护字段不在表单显示

### 8.3 字段类型渲染【推荐】

> MVC 版表单视图（`_Form_Editor` / `_Form_Group` / `_Form_Item`）已打磨完整，各皮肤按同理念实现，可用自己框架的表单组件。

| 字段 | 编辑形式 | 展示形式（详情） |
|------|----------|------------------|
| 单行文本 | Input | 文本 |
| 大文本 | Textarea | 多行文本 |
| 布尔 | 开关 / Checkbox | 图标（✓/✗） |
| 整数 / 小数 | InputNumber | 千分位 / 小数位 |
| 日期 / 时间 | DatePicker / DateTimePicker | 格式化日期时间 |
| 下拉选择 | Select（枚举 / 外键 / 数据源 DataSource） | 显示选项文本 |
| 多选 | 多选下拉（ListBox / 标签多选） | 逗号分隔 |
| 模糊搜索 | 搜索建议（Suggest，输入联想） | 显示选中文本 |
| 树选择 | 树形下拉（父级选择，排除自身分支） | 树路径文本 |
| 用户 / 部门选择 | 选择器（SelectUser / SelectDepartment） | 名称 |
| 文件上传 | 文件选择（accept 按类型过滤）+ 下载链接 | 下载链接 |
| HTML 编辑器 | 富文本编辑器（只读时原样渲染） | 富文本 |
| Markdown 编辑器 | Markdown 编辑器 | 渲染后的 Markdown |
| 外键映射 | 下拉或模糊搜索（MapField） | 关联对象名称/链接 |

### 8.4 表单交互【必须】

1. **必填标记**：必填字段明确标记（红星等）
2. **校验错误**：提交时校验错误就地提示（字段下方红色提示）
3. **只读字段**：详情/只读场景以纯文本展示，编辑场景不可编辑
4. **字段说明**：字段描述（Description）以提示形式显示（悬浮或字段下方）
5. **提交/保存**：新增/编辑提供保存按钮；详情提供返回按钮
6. **保存反馈**：保存成功/失败明确反馈

## 9. 主流后台 UI/UX 补充规范【推荐】

> 参考 Ant Design 5 等主流后台管理系统的常见设计，各皮肤结合自身框架能力采纳。

### 9.1 状态反馈

| 状态 | 要求 |
|------|------|
| 空状态 | 列表/卡片无数据时显示引导（图标 + 文案 + 可选操作按钮），而非空白 |
| 加载状态 | 数据加载中显示 loading（骨架屏或 spinner），避免白屏 |
| 错误状态 | 接口失败显示错误提示与重试入口 |
| 操作反馈 | 保存/删除等操作后给出成功/失败消息提示（Toast/Message） |

### 9.2 交互细节

1. **危险操作二次确认**：删除、清空、批量操作等危险操作必须弹确认（Popconfirm/Modal）
2. **按钮权限**：无权限的操作按钮不显示或禁用（与后端权限联动）
3. **表格密度/列设置**（可选）：支持表格密度切换、列显示/隐藏配置
4. **主题切换**（可选）：支持明/暗主题切换，皮肤应预留设计令牌（CSS 变量）便于换肤

### 9.3 信息与可用性

1. **统一间距与留白**：页面间距、卡片间距统一，信息不过度拥挤
2. **键盘操作**：表单支持 Tab 导航、Enter 提交（需避免误触，如登录页用户名校验）
3. **语义化标题**：页面标题层级清晰（页面标题、区块标题、表单标签）
4. **长内容处理**：长文本统一省略策略（ellipsis + title），不撑破布局
