## 1. 审计说明

### 1.1 审计原则（一视同仁，无豁免）

依据规范 §1.3"规范层级与适用范围"执行：

- **按条款适用范围逐条对照**：所有皮肤对【全皮肤】条款一视同仁，不因任何皮肤是老实现而豁免
- **【SPA 专属】条款**：仅 SPA 皮肤参与对照（MVC 架构不适用，标注 "—"）
- **【必须】项不满足 = 缺陷**；【推荐】项不满足 = 缺口

### 1.2 ACE 闭环审计（规范 ↔ 实现校验）

本次以 ACE 皮肤为基准对规范做了**闭环校验**：逐条对照 ACE 实际实现，发现规范 §3.4 移动端原要求（手机优先/折叠屏深度适配/抽屉菜单）超出 MVC 服务端渲染架构能力边界 → **修正规范**（§3.4 升级为屏幕宽度兼容：3.4.1 基础兼容【全皮肤】覆盖 2K/4K/常规/平板/手机，3.4.2 深度适配【SPA 专属】）→ 重新审计。修正后规范各条款均落在各代际架构能力边界内，**ACE 全部满足（必须项 ✅、全皮肤推荐项 ✅、SPA 专属项不参与）**，闭环成立。

### 1.3 审计维度

登录（基础/高级/安全）、布局（形态/用户区/移动端/工作台）、菜单与路由（权限/图标/多级/URL/多标签）、列表页（查询/表格/单元格/列宽/图表/高级菜单/操作列）、表单页、通用体验。
