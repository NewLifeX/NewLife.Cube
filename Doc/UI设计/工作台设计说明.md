# 工作台（Dashboard）UI 设计说明

> 本文档配合 [`工作台.html`](工作台.html) 设计稿使用，说明现状、痛点、设计方案与落地映射。
> 状态：**UI 草稿，待确认后实施**。

---

## 1. 现状分析

当前工作台为 `Areas/Admin/Views/Index/Dashboard.cshtml` + `Widgets/` 组件体系：

```
Areas/Admin/Views/Index/Dashboard.cshtml   ← 工作台主视图
Areas/Admin/Views/Widgets/*.cshtml          ← 各组件局部视图（7 个）
Widgets/                                   ← 组件扫描/元数据/数据（WidgetManager）
wwwroot/Content/ace-ui.css                 ← 工作台样式（.cube-workbench 等）
```

**现有组件（WidgetManager 扫描自动注册）**：

| Widget | 数据 | 说明 |
|--------|------|------|
| StatCards | CPU/内存/磁盘/运行时长 | 4 个横排小统计 |
| Monitor | ECharts 曲线 | CPU/内存实时曲线，5s 轮询 |
| QuickLink | 快捷链接列表 | 管理员/普通用户按 AdminOnly 过滤 |
| Profile | 个人信息 | 头像 + 账号信息表 |
| SysInfo | 服务器信息 | 键值表 |
| Log | 日志统计 | 24h 摘要 + 7 天迷你柱 + 最近异常 |
| LoginLog | 登录日志 | 最近登录列表 |

**机制**：卡片墙 flex 布局，按 `Sort` 排序，jquery-ui 拖拽排序（每用户 Cookie 保存），`Cols` 控制宽度（12 栅格），`AdminOnly`/`Permission` 控制可见性。

## 2. 痛点分析

1. **视觉平铺无层次**：7 张同质化灰卡平铺，无主次、无聚焦，KPI 数字不醒目，缺少运营感。
2. **头部简陋**：仅标题 + 欢迎 + 两个按钮，无个性化问候、日期、状态摘要。
3. **卡片高度参差**：Profile/SysInfo 表格卡矮、Log/Monitor 卡高，同行不齐。
4. **管理员/普通用户差异不足**：普通用户也平铺看到服务器信息等无关注卡片，主次不分。
5. **统计数字缺上下文**：KPI 无环比趋势、无可点击跳转，信息密度低。

## 3. 设计方案（详见 工作台.html）

### 3.1 布局（管理员视图，自上而下 5 个层次）

```
┌─────────────────────────────────────────────────────────────┐
│ ① 欢迎横幅：渐变主色 · 问候+日期+系统状态 · 操作按钮          │
├──────┬──────┬──────┬──────┬──────┬──────┐                    │
│ ② KPI 指标行 ×6：彩色图标 + 大数字 + 标签 + 趋势/链接         │
├──────────────────────────────┬──────────────────────────────┤
│ ③ 性能监控大卡（8列）        │ ④ 快捷链接（4列，2×3 网格）   │
├──────────────────────────────┴──────────────────────────────┤
│ ⑤ 日志中心（7列）+ 服务器信息（5列）                          │
├──────────────────────────────────────────────────────────────┤
│ ⑥ 个人信息（6列）+ 最近登录（6列）                            │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 视觉规范（对齐 ace-ui.css 设计令牌）

| 令牌 | 值 | 用途 |
|------|-----|------|
| 主色 `#2b7dbc` | 图标/链接/KPI 主色 | 品牌色 |
| 白卡片 + `--cube-radius-lg`(10px) + 柔和阴影 | 卡片容器 | 与全站一致 |
| 背景 `#f0f2f5` | 页面底色 | 与全站一致 |
| KPI 图标彩色系 | 蓝/绿/青/橙/红/紫 | 语义区分：用户/登录/在线/日志/异常/CPU |

### 3.3 管理员 vs 普通用户

| 区块 | 管理员 | 普通用户 |
|------|--------|----------|
| 欢迎横幅 | 问候 + 系统状态 + AI 诊断 | 问候 + 个人操作 |
| 指标 | 用户总数/今日登录/在线/日志/异常/CPU（6 卡） | 我的登录次数/角色/注册天数/待办（4 步） |
| 性能监控 | ✅ 全宽曲线 | ❌ 隐藏 |
| 快捷链接 | 系统功能（6 项） | 个人功能（8 项，4 列） |
| 日志/服务器信息 | ✅ | ❌（无关注） |
| 个人信息/最近动态 | ✅ 双栏 | ✅ 个人版 |

> 差异通过现有 `AdminOnly`/`Permission` 机制即可实现，无需新增权限模型。

## 5. 实现映射（两种落地路线，待确认）

### 路线 A：保留卡片墙，仅升级各组件内部视觉 + 调整排序/宽度（小改）

- 保留 `Dashboard.cshtml` 拖拽/排序机制与 `Widgets/*.cshtml` 分片。
- 主要工作：① 重写头部为横幅（`.workbench-header` → `.wb-banner`）；② 重写 StatCards 为 6 KPI 卡；③ 微调各组件内部样式（统一卡片高度、键值表、列表样式）。
- **优点**：改动小、保留拖拽自由度、逐组件迭代。
- **缺点**：仍是无层次的卡片平铺，视觉提升有限。

### 路线 B：固定分区的布局模板 + Widget 映射到分区（中改，推荐）

- `Dashboard.cshtml` 改为**固定布局模板**：定义横幅/KPI/主图/内容区/边栏等**槽位**。
- 每个槽位指定一个或多个 Widget（按 `Category`/`Name` 匹配），未匹配的 Widget 收进"更多"折叠区。
- 保留 Widget 数据源与权限过滤（`WidgetManager.GetWidgets` + `AdminOnly`），不再需要拖拽（布局由模板决定）。
- **优点**：达到设计稿的层次感；数据/权限体系完全复用；普通用户自动降级（无 AdminOnly 组件）。
- **缺点**：布局改动较大；失去拖拽（可由"模板选择"替代）。

### 路线 C：完全手写 Dashboard（大改）

- 放弃通用 Widget 墙，按设计稿手写区块，直接调用各 Widget 的数据类。
- **优点**：像素级还原设计稿。
- **缺点**：破坏组件化，后续新增组件需要改工作台代码。

> **建议**：路线 B。它把"布局"从"组件"中分离——组件仍自治（数据+权限+局部视图），布局由模板决定，兼顾设计稿效果与体系可扩展性。
