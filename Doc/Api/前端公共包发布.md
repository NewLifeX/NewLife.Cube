# 前端公共包发布

本文档说明 `packages/` 下 5 个前端公共 TypeScript 包如何发布到公有 npm 源，供仓库外的其它项目引用。

## 包清单与命名

| 包名 | 用途 | 依赖 |
|------|------|------|
| `@newlifex/api-core` | 框架无关 API 层（axios 封装、Token、加密、类型） | — |
| `@newlifex/page-utils` | 页面工具函数（URL、导出、菜单权限） | — |
| `@newlifex/field-mapping` | `DataField` 元数据 → UI 控件映射引擎 | api-core |
| `@newlifex/auth-logic` | 认证业务逻辑 + Pinia/Zustand 适配器 | api-core, page-utils |
| `@newlifex/page-logic` | 列表页业务编排 + Pinia/Zustand 适配器 | api-core, field-mapping, page-utils |

> **命名说明**：早期仓库内使用 `@cube/*`，因 npmjs 的 `@cube` scope 已被他人占用、且 GitHub Packages 强制包 scope 匹配 GitHub 组织名，统一改名为 `@newlifex/*`（同时匹配 npmjs 组织与 GitHub 组织 `NewLifeX`）。

## 发布目标（双源）

- **npmjs.org**（`https://registry.npmjs.org`）—— 公有源，其它项目 `pnpm add` 即可引用
- **GitHub Packages**（`https://npm.pkg.github.com`）—— 组织内分发，`@newlifex` scope 匹配组织 `NewLifeX`

## 版本约定

- **semver**，5 个包**锁步同版本**（一起发版、一起 bump）
- 稳定版：如 `0.1.0`、`0.2.0`
- 预发布：`0.1.0-beta.20260831153000`（CI 自动追加时间戳）

## 发布方式（GitHub Actions 自动）

工作流 `.github/workflows/publish-npm.yml`：

| 触发 | 发布类型 | npm dist-tag |
|------|---------|-------------|
| 打标签 `v*` | 稳定版 | `latest` |
| master 分支推送（`packages/**` 等变更） | 预发布 | `beta` |
| 手动 `workflow_dispatch` | 按当前分支 | master→beta，其余→latest |

流程：`pnpm install --frozen-lockfile` → 运行 api-core/field-mapping 单测 → 计算 dist-tag → （beta 时）`scripts/set-beta-version.mjs` 加时间戳版本 → 发布 npmjs → 发布 GitHub Packages。

> 标签 `v*` 与 .NET 侧 `publish.yml` 共享：一个标签同时触发 NuGet 与 npm 发布。

## 发版步骤（维护者）

1. **稳定版**：统一 bump 5 个包版本（如 `0.1.0` → `0.2.0`）→ 提交 → 打标签 `v0.2.0` → 推送
2. **预发布**：push 到 master（自动）
3. 核对：`https://www.npmjs.com/package/@newlifex/api-core` 与 GitHub Packages 页面

## 前置条件（一次性）

1. npmjs `@newlifex` 组织成员生成 **publish token**（细粒度，含 `@newlifex/*` 写权限）
2. 仓库 Secrets 增加 `NPM_TOKEN`（GitHub Packages 用 `GITHUB_TOKEN`，无需额外配置）

## 包发布配置要点

`packages/*/package.json` 已内置：

- **`prepare: pnpm build`**（替代原 `postinstall`）：本地 install / 发布前自动构建；消费者从 registry 安装时**不会**触发构建（`postinstall` 会导致消费者安装失败——tsup 在 devDependencies，消费者不安装）
- `publishConfig.access = "public"`：scoped 包发布到 npmjs 必须显式公开
- `files: ["dist", "README.md"]`：只发布构建产物
- `repository` / `homepage` / `bugs` / `keywords`：npm 页面元数据
- 内部依赖使用 `workspace:*`，`pnpm publish` 时自动改写为实际版本

## 消费者使用

```bash
# npmjs（公有）
pnpm add @newlifex/api-core @newlifex/auth-logic @newlifex/page-logic @newlifex/field-mapping @newlifex/page-utils

# 预发布版本
pnpm add @newlifex/api-core@beta
```

```ts
import { createCubeApi } from '@newlifex/api-core';
import { createZustandAuthStore } from '@newlifex/auth-logic/zustand';
import { createPageStore } from '@newlifex/page-logic/zustand';
```

### GitHub Packages 源（可选，需鉴权）

项目 `.npmrc`：

```ini
@newlifex:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

> 本仓库内 10 套皮肤继续用 `workspace:*` 引用，不受发布影响；皮肤包均为 `private: true`，不会被误发布。
