# 前端公共包发布

本文档说明 `packages/cube`（`@newlifex/cube`）如何发布到公有 npm 源，供仓库外的其它项目引用。

## 包入口

只发布一个包，用子路径区分是否需要框架适配器：

| 入口 | 用途 | 需要的 peer 依赖 |
|------|------|------------------|
| `@newlifex/cube` | 框架无关核心：API 调用层（axios / Token / 加密 / 类型）、页面工具函数、字段映射引擎、认证与列表页业务编排 | — |
| `@newlifex/cube/pinia` | Vue 系（Pinia）适配器 | `pinia`、`vue` |
| `@newlifex/cube/zustand` | React 系（Zustand）适配器 | `zustand` |

> **命名与拆分说明**：早期拆成 api-core / page-utils / field-mapping / auth-logic / page-logic 5 个包，因从未对外发布、且 5 包需锁步发版维护成本高，已合并为单包 `@newlifex/cube`（与皮肤包 `@newlifex/cube-vue` 等同属 `cube-*` 一族）。`@cube/*` 为更早期命名，npmjs 的 `@cube` scope 已被他人占用，故统一用 `@newlifex/*`（同时匹配 npmjs 组织与 GitHub 组织 `NewLifeX`）。

## 发布目标（双源）

- **npmjs.org**（`https://registry.npmjs.org`）—— 公有源，其它项目 `pnpm add` 即可引用
- **GitHub Packages**（`https://npm.pkg.github.com`）—— 组织内分发，`@newlifex` scope 匹配组织 `NewLifeX`

## 版本约定

- **semver**，单包走自己的版本号（不再多个包锁步）
- 稳定版：如 `0.1.0`、`0.2.0`
- 预发布：`0.1.0-beta.20260831153000`（CI 自动追加时间戳）

## 发布方式（GitHub Actions 自动）

工作流 `.github/workflows/publish-npm.yml`：

| 触发 | 发布类型 | npm dist-tag |
|------|---------|-------------|
| 打标签 `v*` | 稳定版 | `latest` |
| master 分支推送（`packages/**` 等变更） | 预发布 | `beta` |
| 手动 `workflow_dispatch` | 按当前分支 | master→beta，其余→latest |

流程：`pnpm install --frozen-lockfile` → 显式构建 `@newlifex/cube`（单测直接 `require('../dist/index.cjs')`，dist 不入库）→ 运行 `@newlifex/cube` 单测 → 计算 dist-tag → （beta 时）`scripts/set-beta-version.mjs` 加时间戳版本 → 校验 token（`npm whoami`）→ 发布 npmjs → 发布 GitHub Packages。

> CI 使用 Node 22：单测脚本是 `node --test "tests/**/*.test.cjs"`，glob 形式要求 Node 21+（Node 20 会把通配符当字面路径）。

> 标签 `v*` 与 .NET 侧 `publish.yml` 共享：一个标签同时触发 NuGet 与 npm 发布。

## 发版步骤（维护者）

1. **稳定版**：bump `packages/cube/package.json` 版本（如 `0.1.0` → `0.2.0`）→ 提交 → 打标签 `v0.2.0` → 推送
2. **预发布**：push 到 master（自动）
3. 核对：`https://www.npmjs.com/package/@newlifex/cube` 与 GitHub Packages 页面

## 前置条件（一次性）

1. npmjs `@newlifex` 组织成员生成 **Granular Access Token**：Packages and scopes 选 `@newlifex` 的 **Read and write**，并勾选 **Bypass 2FA**（classic「Publish」类型 token 不绕过 2FA，CI 发布必定被拒）
2. 仓库/组织 Secrets 增加 `NPM_TOKEN`（GitHub Packages 用 `GITHUB_TOKEN`，无需额外配置）

> 实测（2026-10-28）：token 能通过 `npm whoami`，但发布报 `E403 ... Two-factor authentication or granular access token with bypass 2fa enabled is required to publish packages` —— 即 token 类型/绕过 2FA 未开启，与代码、构建与打包无关（本地 `publish --dry-run` 正常）。
>
> npm 已公告：绕过 2FA 的 token 从 2026-08 起限制「账号变更」类操作，直接 publish 的限制从 2027-01 开始；到时可改用 Trusted Publishing（GitHub OIDC，无需 token）。

## 包发布配置要点

`packages/cube/package.json` 已内置：

- **`prepare: pnpm build`**（替代原 `postinstall`）：本地 install / 发布前自动构建；消费者从 registry 安装时**不会**触发构建（`postinstall` 会导致消费者安装失败——tsup 在 devDependencies，消费者不安装）
- `publishConfig.access = "public"`：scoped 包发布到 npmjs 必须显式公开
- `files: ["dist", "README.md"]`：只发布构建产物
- `exports`：`.` / `./pinia` / `./zustand` / `./package.json`，每个入口同时提供 `types` / `import` / `require` 三份（`main` 指向 CJS 兼容老工具链，`module` 指向 ESM）
- `sideEffects: false`：合并成单包后便于打包工具按需 tree-shaking
- `pinia` / `vue` / `zustand` 声明为 **可选 peer 依赖**（`peerDependenciesMeta.optional`）：只有用到适配器入口才需要安装
- `repository` / `homepage` / `bugs` / `keywords`：npm 页面元数据
- 仓库内消费方（9 套皮肤）仍用 `workspace:*` 引用，`pnpm publish` 时会自动改写为实际版本

## 消费者使用

```bash
# npmjs（公有）
pnpm add @newlifex/cube

# 预发布版本
pnpm add @newlifex/cube@beta
```

```ts
import { createCubeApi, resolveWidgets } from '@newlifex/cube';
import { createPiniaAuthStore, usePageLogic } from '@newlifex/cube/pinia';
import { createZustandAuthStore, createPageStore } from '@newlifex/cube/zustand';
```

### GitHub Packages 源（可选，需鉴权）

项目 `.npmrc`：

```ini
@newlifex:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

> 本仓库内 10 套皮肤继续用 `workspace:*` 引用，不受发布影响；皮肤包均为 `private: true`，不会被误发布。
