# 通知接口

> 路由前缀：服务控制器不带 `/api` 前缀，例如 `POST /Notify/Read`；前端请求层按部署环境统一拼接 `/api`。管理端接口位于 `/api/Admin/NotificationSend/*`。
> 所有接口返回统一信封 `{ code, message, data }`，`code=0` 表示成功。

## 1. 用户侧接口（NotifyController）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/Notify/Count` | 当前用户未读站内信数量 |
| GET | `/Notify/Recent?size=10` | 最近未读站内信，铃铛下拉 |
| GET | `/Notify/List?pageIndex=1&pageSize=20&category=&read=&key=&start=&end=` | 分页查询站内信 |
| GET | `/Notify/Detail?id=` | 站内信详情 |
| POST | `/Notify/Read` | 标记已读。参数 `bizId`、`id`（BizId 为空时用）、`channel` |
| POST | `/Notify/ReadAll` | 全部已读。只处理个人消息，团队共享消息需显式处理 |
| POST | `/Notify/Handle` | 处理通知。参数 `bizId`、`result` |
| POST | `/Notify/Delete` | 软删除站内信。参数 `id`；团队共享消息仅管理员可删 |
| GET | `/Notify/Incremental?lastId=&size=20` | 增量拉取，SSE 断线后的轮询兜底 |
| POST | `/Notify/StreamTicket` | 签发 SSE 一次性票据，60 秒有效 |
| GET | `/Notify/Stream?ticket=&lastId=` | SSE 实时通知流，`text/event-stream` |
| GET | `/Notify/Preferences` | 当前用户分类偏好 |
| POST | `/Notify/SavePreferences` | 保存分类偏好，参数 `category`、`channels`（逗号分隔） |
| POST | `/Notify/RegisterDevice` | 登记移动端设备，参数 `token`、`platform` |
| POST | `/Notify/UnregisterDevice` | 注销移动端设备，参数 `token` |

### 1.1 列表项

```json
{
  "id": 1876543210123456789,
  "bizId": "task:20261123123045:9f3a",
  "shared": false,
  "title": "部署完成",
  "content": "生产环境部署已经完成，请查看",
  "category": "Task",
  "level": "Info",
  "link": "/tasks/123",
  "read": false,
  "readTime": null,
  "readChannel": null,
  "handled": false,
  "handledBy": 0,
  "handledTime": null,
  "createTime": "2026-11-23 12:30:45"
}
```

### 1.2 标记已读

```http
POST /Notify/Read
Content-Type: application/json

{ "bizId": "task:20261123123045:9f3a", "channel": "AppPush" }
```

返回：

```json
{
  "code": 0,
  "data": {
    "id": 1876543210123456789,
    "bizId": "task:20261123123045:9f3a",
    "read": true,
    "readBy": 42,
    "readChannel": "AppPush"
  }
}
```

`bizId` 非空时按业务消息批量处理：同一 `BizId` 下的全部渠道记录都会标记已读；`Shared=true` 会同步全组站内信行；`CancelOnRead=true` 时尚未发送的外部渠道会置为 `Skipped`。`channel` 记录触发渠道，用于分析“用户在哪个终端读的”。

### 1.3 SSE 连接

1. `POST /Notify/StreamTicket` 获取票据：

```json
{ "code": 0, "data": { "ticket": "8f3a...", "expiresIn": 60 } }
```

2. 建立连接：

```js
const es = new EventSource('/Notify/Stream?ticket=8f3a...&lastId=123');
es.addEventListener('notification', (e) => {
  const item = JSON.parse(e.data);
});
```

服务端事件：

```text
id: 124
event: notification
data: {"id":124,"bizId":"...","title":"...","content":"...","read":false}

event: count
data: {"count":3}

```

`notification` 推送新站内信；`count` 每 10 秒检查一次未读数变化，用于其它终端已读/团队处理后的铃铛同步。

票据一次性、绑定用户与 IP；`Stream` 允许匿名访问但只认票据，访问令牌不进入 URL。连接失败时前端自动降级为 60 秒轮询 `/Notify/Count` + `/Notify/Recent`。

## 2. 管理端接口（NotificationSendController）

需要 `Insert` 权限。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/Admin/NotificationSend/Send` | 发布通知 |
| POST | `/api/Admin/NotificationSend/Retry?id=` | 重试失败的外部渠道记录 |
| GET | `/api/Admin/NotificationSend/Records?...` | 查询投递记录 |
| GET | `/api/Admin/NotificationSend/Templates` | 查询通知模板 |
| POST | `/api/Admin/NotificationSend/SaveTemplate` | 保存通知模板 |
| POST | `/api/Admin/NotificationSend/DeleteTemplate?code=` | 删除通知模板 |

### 2.1 发布请求

```json
{
  "tenantId": 0,
  "bizId": "approval:20261123:8f3a",
  "scope": "Each",
  "userIds": [42, 43],
  "roleIds": [],
  "departmentIds": [],
  "all": false,
  "action": "Notify",
  "category": "Business",
  "level": "Info",
  "templateCode": "approval.pending",
  "title": "待审批",
  "content": "您有一条待审批单据",
  "link": "/approvals/123",
  "data": { "name": "采购申请" },
  "channels": ["InApp", "AppPush", "Mail"],
  "channelDelays": [0, 30, 60],
  "cancelOnRead": true,
  "expireTime": "2026-12-31T23:59:59",
  "senderId": 0
}
```

| 字段 | 说明 |
|------|------|
| `scope` | `Each` 每人独立已读；`Any` 团队任一已读/处理即全组闭环 |
| `bizId` | 可选。不传则服务端生成；相同 `BizId` 5 分钟内重复发布会被跳过 |
| `channels` | `InApp`/`Mail`/`Sms`/`AppPush`/`Webhook`/`DingTalk`/`WeCom`；为空时取模板或默认 InApp |
| `channelDelays` | 与 `channels` 对应的延迟秒数；InApp 始终立即，外部渠道到点才发送 |
| `cancelOnRead` | 任一渠道已读/处理后取消未发送渠道，默认 true |
| `all` | 全员广播。与 `scope=Any` 互斥，单次最多 1000 人 |
| `toAdmins` | 发送给系统管理员。与 `all` 互斥；按 `Role.IsSystem` 解析收件人，生成管理员个人站内信 |

发布结果：

```json
{
  "code": 0,
  "data": {
    "bizId": "approval:20261123:8f3a",
    "recipients": 2,
    "records": 8,
    "bizIds": ["approval:20261123:8f3a:42", "approval:20261123:8f3a:43"],
    "skipped": false
  }
}
```

### 2.2 渠道顺序与 BizId 幂等

- `channels` 的顺序即投递顺序，`channelDelays` 对应每个渠道的延迟秒数。示例 `[0,30,60]` 表示站内信立即、APP 30 秒、邮件 60 秒。
- `cancelOnRead=true` 时，任一渠道标记已读或处理，会把同 `BizId` 下当前用户（团队共享则全组）全部记录标记已读，并把尚未发送的外部渠道置为 `Skipped`；调度器发送前也会再次检查，已读后不会继续发。
- `bizId` 同时承担 5 分钟幂等：调用方显式传入相同 `BizId` 重复发布时整批跳过并返回 `skipped=true`。不传则每次生成新值。
- 同一业务对象的不同事件用不同 `BizId`，如 `order:123:paid`、`order:123:shipped`。
- 软幂等，不是唯一约束；强幂等需业务侧发件箱/唯一状态配合。

### 2.3 投递记录筛选

`GET /api/Admin/NotificationSend/Records` 支持：

| 参数 | 说明 |
|------|------|
| `bizId` | 业务消息编号 |
| `channel` | 渠道 |
| `userId` | 用户 |
| `category` / `level` | 分类 / 级别 |
| `read` / `handled` / `success` | 已读 / 已处理 / 发送成功 |
| `start` / `end` | 时间范围 |
| `key` | 关键字 |
| `pageIndex` / `pageSize` | 分页 |

## 3. 模板结构（SaveTemplate）

```json
{
  "code": "task.done",
  "title": "任务{name}已完成",
  "content": "任务{name}已于 {time} 完成，请查看",
  "smsContent": "{name}完成",
  "pushContent": "{name}已完成",
  "link": "/tasks/{id}",
  "channels": "InApp,Mail,Sms,AppPush"
}
```

- `{key}` 用发布请求的 `data` 属性替换；模块级 `NotifyRequest.Items` 也会合并进 `data` 参与渲染。
- 模板存 `Parameter`：`UserId=tenantId`、`Category=NotifyTemplate`、`Name={code}`；通知内容单语言，不再按语言分模板。
- 短信内容只做摘要，点击链接回到站内信正文；短信模板编号在 `SmsConfig.NotifyTemplateCode` 配置，模板参数取 `data` + `content`。

## 4. 错误码

| code | 说明 |
|------|------|
| 0 | 成功 |
| 400 | 请求为空或缺少标题/内容 |
| 403 | 未登录、票据无效或超出权限 |
| 404 | 记录不存在或无权访问 |
| 500 | 发布失败、收件人超过 1000 人、广播 + Any 等业务校验失败 |
