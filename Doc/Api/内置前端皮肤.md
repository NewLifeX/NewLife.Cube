# 内置前端皮肤

> 状态（2026-10-30）：React 皮肤源码维护在独立仓库 [NewLife.Cube.React](https://github.com/NewLifeX/NewLife.Cube.React)，本仓库不再包含 `NewLife.Cube.React`，但两个皮肤包都发布 NuGet 并可同时引用（见「多皮肤包共存与切换」）。当前仓库内置皮肤以 Vue 为官方，另有 8 个 SPA 参考实现（见 README）。

## 概述

第三代魔方（WebAPI 版）提供内置前端皮肤包，用户只需引用 NuGet 包即可获得完整的管理后台前端界面，无需任何前端开发知识。

**可选皮肤包**：

| NuGet 包 | 前端技术栈 | 原始项目 |
|----------|-----------|---------|
| `NewLife.Cube.Vue` | Vue 3 + Element Plus + Vite | [QuickVue](https://github.com/NewLifeX/NewLife.QuickVue) |
| `NewLife.Cube.React` | React 19 + Ant Design 6 + Vite | [CubeAntd](https://github.com/NewLifeX/NewLife.CubeAntd) |

## 快速开始

### 1. 安装 NuGet 包

在 WebAPI 项目中引用 `NewLife.Cube` 和任一前端皮肤包：

```xml
<!-- 二选一 -->
<PackageReference Include="NewLife.Cube.Vue" Version="1.0.*" />
<PackageReference Include="NewLife.Cube.React" Version="1.0.*" />
```

### 2. 注册中间件

在 `Program.cs` 中注册前端皮肤：

```csharp
// 注册魔方
services.AddCube();

var app = builder.Build();

// 使用魔方
app.UseCube(app.Environment);

// 使用 Vue 前端皮肤（二选一）
app.UseVue(app.Environment);
// 或使用 React 前端皮肤
// app.UseReact(app.Environment);

app.Run();
```

同时引用多个皮肤包时，改用统一入口（详见下文「多皮肤包共存与切换」）：

```csharp
app.UseCubeSkin(app.Environment);   // 读设置项 SpaSkin，可在管理后台切换
```

### 3. 运行

```bash
dotnet run
```

浏览器访问即可看到完整的管理后台界面，包含登录页、动态菜单、列表页、表单页等。

### 4. NuGet 发布说明

- `NewLife.Cube.Vue`（本仓库）与 `NewLife.Cube.React`（独立仓库）均由 CI 先执行 `pnpm build` 产出前端，再 `dotnet pack` 把 `wwwroot` 嵌入 DLL 后发布，引用 NuGet 包即得完整前端，无物理文件依赖。
- 打包排除 `*.map`，单个 TFM 的 DLL 约 7MB；未构建前端（缺 `wwwroot/index.html`）时打包直接报错，避免发布空壳包。
- Vue 包与同批次的 `NewLife.Cube` 版本号对齐（如 `1.0.2026.1030` 依赖 `NewLife.Cube 6.16.2026.1030`）。

## 多皮肤包共存与切换

下游项目可以同时引用 `NewLife.Cube.Vue` 与 `NewLife.Cube.React`，控制器仍然只有 `NewLife.Cube` + 业务项目一套——皮肤包只提供静态前端，不携带控制器（React 包附带一个皮肤设置控制器，与 Vue 不冲突）。

```csharp
app.UseCube(builder.Environment);
MapControllerRoute(...);
app.MapControllers();

// 统一入口：自动发现已引用的皮肤包，按设置项选择当前皮肤
app.UseCubeSkin(builder.Environment);
```

切换方式与优先级（高 → 低）：

| 方式 | 说明 |
|------|------|
| `app.UseCubeSkin(env, "React")` | 代码强制指定，优先级最高 |
| 设置项 `CubeSetting.SpaSkin` | 管理后台「系统设置」中以下拉选择皮肤，保存后**刷新页面即生效，无需重启** |
| 内置默认 | 未配置时优先 `Vue`，否则按皮肤名排序取第一个 |

实现要点：

- `CubeSkinFileProvider` 在**每次请求**按当前皮肤解析静态资源与 `index.html`，因此切换只需要改设置，不需要重启进程。
- 重复调用 `UseCubeSkin`（或同时调用 `UseVue` + `UseReact`）只会注册一次静态文件与 SPA 回退路由，不会出现路由歧义。
- `UseVue` / `UseReact` 仍保留，语义为「强制指定该皮肤」；需要配置切换时请使用 `UseCubeSkin`。
- 不支持同一进程内 `/vue` 与 `/react` 两套皮肤同时在线（两个 SPA 都使用根路径），每次部署只启用当前设置的那一套。
- React 包自带的「React skin settings」菜单在 Vue 皮肤下也会出现，属无害项。

### 后端 API 支持

前端皮肤包依赖以下后端 API（均由 `NewLife.Cube` 提供，无需额外开发）：

```
GET  /{area}/{controller}              # 列表查询（含分页/排序/搜索/统计行）
GET  /{area}/{controller}/{id}         # 查看详情
GET  /{area}/{controller}/meta         # 页面元数据（视图自描述 + entity + toolbar）
POST /{area}/{controller}              # 新增
PUT  /{area}/{controller}/{id}          # 编辑
DELETE /{area}/{controller}/{id}       # 删除单条
DELETE /{area}/{controller}?ids=       # 批量删除选中（逗号分隔，≤100）
DELETE /{area}/{controller}?<条件>     # 按搜索条件删除全部匹配行
GET  /{area}/{controller}/export       # 导出（?format=Excel/Csv/Json/Xml/Zip）
POST /{area}/{controller}/import       # 导入文件
POST /{area}/{controller}/attachments  # 上传附件
GET  /{area}/{controller}/charts       # 图表数据（ECharts option JSON）
GET  /Cube/MenuTree                   # 菜单树
GET  /Auth/Info                       # 当前用户信息
GET  /Cube/Site                       # 站点信息（品牌/语言/功能开关）
GET  /Auth/LoginConfig                # 登录能力（兼容接口，含风险验证码判定）
GET  /Cube/Lookup?codes=              # 字典查询
```

## 工作原理

### 嵌入式静态资源

前端编译产物（HTML/JS/CSS）作为嵌入式资源打包到 .NET 程序集中。运行时通过 `CubeEmbeddedFileProvider` 从程序集中读取并响应 HTTP 请求。

```
用户请求 → StaticFiles 中间件 → CompositeFileProvider
                                  ├── PhysicalFileProvider (wwwroot/, 优先)
                                  └── CubeEmbeddedFileProvider (程序集嵌入)
```

**物理文件优先**：如果 `wwwroot/` 目录下存在同名文件，将优先使用物理文件。这允许在不修改程序集的情况下覆盖个别资源文件。

### 动态页面渲染

前端通过 `meta` API 获取页面元数据（页面开关 + 字段集合），根据元数据动态渲染列表和表单页面。新增 Controller 和菜单后，前端自动适配，无需额外开发。

### 本地开发

> 说明：仓库根目录已改为“默认不全量递归编译皮肤”。根目录 `pnpm build` 仅构建 `packages/` 公共模块；如需编译指定皮肤，请使用根目录 `pnpm build:vue`、`pnpm build:react` 等专用脚本，或直接进入对应 `web/` 目录执行 `pnpm build`。

#### Vue 皮肤

```bash
cd NewLife.Cube.Vue/web
pnpm install
pnpm dev          # 启动开发服务器
pnpm build        # 构建 → ../wwwroot/
```

#### React 皮肤

```bash
cd NewLife.Cube.React/web
pnpm install
pnpm dev          # 启动开发服务器
pnpm build        # 构建 → ../wwwroot/（max build）
```

### 根目录快捷命令

```bash
pnpm build          # 仅构建 packages/ 共享包
pnpm build:vue      # 仅构建 Vue 皮肤
pnpm build:react    # 仅构建 React 皮肤
pnpm build:all      # 显式构建全部 workspace 前端
pnpm dev:vue        # 仅启动 Vue 皮肤开发服务器
pnpm dev:react      # 仅启动 React 皮肤开发服务器
pnpm dev:all        # 显式启动全部 workspace 开发任务
```

### 构建流程

前端构建产物输出到 `../wwwroot/` 目录，.NET 项目通过 `EmbeddedResource` 将其嵌入程序集：

```xml
<EmbeddedResource Include="wwwroot\**\*" />
```

修改前端代码后执行 `pnpm build`，再执行 `dotnet build` 即可将最新前端打入程序集。

## 与 MVC 皮肤的区别

| 维度 | MVC 皮肤（AdminLTE/Tabler） | 前端皮肤（Vue/React） |
|------|--------------------------|---------------------|
| 依赖 | NewLife.CubeNC (MVC) | NewLife.Cube (API) |
| 渲染 | 服务端 Razor | 客户端 SPA |
| 包含 | Razor Views + CSS/JS | 编译后的 SPA 产物 |
| 定制 | 覆盖 Razor 视图 | Fork 前端源码 |
| 技术栈 | .NET 开发者即可 | 需要前端开发知识 |
| 功能覆盖 | 100%（基准线） | 90%+（动态列表/表单/CRUD/导入导出/图表） |
| 登录页 | 服务端渲染 | 动态配置（`/Cube/Site` + `/Auth/LoginConfig`） |
| 列表功能 | 搜索/排序/分页/导出/导入/图表 | 搜索/排序/分页/导出/导入/图表/批量操作 |
| 性能 | 每次操作需服务端渲染 | SPA 无刷新，体验更流畅 |

### 自定义图表

后端控制器可通过重写 `OnGetCharts` 方法为列表页提供 ECharts 图表：

```csharp
protected override Object[] OnGetCharts(IEnumerable<MyEntity> data)
{
    // 构建 ECharts option 对象，前端自动渲染
    return [new { title = new { text = "统计" }, series = ... }];
}
```
