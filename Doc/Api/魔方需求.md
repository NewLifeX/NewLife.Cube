# API 魔方（前端皮肤对接）需求文档

> 版本：v2.0 | 日期：2026-10-22

本文档描述 API 魔方（前端皮肤对接）的愿景、核心目标和功能方向。完成状态在[功能清单](../功能清单.md)中追踪，详细设计在[架构设计](../架构设计.md)与[核心接口架构](核心接口架构.md)中展开。需求范围限 NewLife.Cube 第三代 WebAPI 主线，是各前端皮肤接入的统一契约来源。

---

## 1. 背景与愿景

### 1.1 系统定位

API 魔方是面向前端皮肤（Vue / React / Angular / Svelte / Blazor / MVC Razor 等）的后台管理 API 能力层，为所有皮肤提供稳定的后台管理接口契约，定义“必要接口最小集 + 高级接口增强集”两层边界。

- **统一契约**：认证、菜单、CRUD、站点信息的路径与语义固定，跨皮肤行为一致
- **最小接入**：新皮肤只对接必要接口即可跑通登录、导航与数据管理
- **不绑定前端**：平台只约定接口语义，不干预组件库、路由与状态管理选型

### 1.2 愿景

同一套后端语义驱动所有前端皮肤——新增皮肤只实现 UI，不再重复定义协议，也不因皮肤差异产生接口分叉。以“必要性”划界：必要接口长期稳定，让新皮肤在 1 天内完成最小可运行接入；高级接口在真实接入诉求出现时渐进补齐，不作为最小闭环的阻塞项。

## 2. 核心目标

| 编号 | 目标 | 所属层级 | 一句话描述 |
|------|------|----------|------------|
| API | 接口契约 | 契约基础 | 统一响应结构、分页与错误码语义，跨皮肤一致 |
| AUTH | 认证接入 | 最小接入 | 登录闭环、多形态登录与注册、OAuth 流程与传输安全 |

## 3. 功能需求

### 3.1 API — 接口契约

- **API-1 统一响应协议**：所有接口统一返回 `ApiResponse<T>`（`code`/`message`/`data`/`page`/`stat`），列表接口固定使用 `pageIndex`/`pageSize`/`totalCount` 分页语义。
- **API-2 错误码语义**：错误响应提供稳定的 `code` 与消息结构，前端可统一拦截与提示，不依赖 HTTP 状态文本。

### 3.2 AUTH — 认证接入

- **AUTH-1 认证最小闭环**：提供 `/Auth/Login`、`/Auth/Refresh`、`/Auth/Info`、`/Auth/Logout`，登录返回 token 对，过期可刷新，登出可清理登录态。
- **AUTH-2 登录分类规范**：`/Auth/Login` 以字符串 `category` 区分登录方式，`""` 为密码登录、`mobile` 为手机验证码、`mail` 为邮箱验证码，所有分类由同一端点处理。
- **AUTH-3 密码传输挑战应答**：`/Auth/Challenge` 下发带时效且一次性的 `challengeId` 与 `publicKey`，`AllowPlainPassword=false` 时拒绝未携带有效挑战的明文登录。
- **AUTH-4 注册分类规范**：`/Auth/Register` 以字符串 `category` 区分注册方式，`""` 为用户名密码、`mobile` 为手机验证码、`mail` 为邮箱验证码、`oauth` 为 OAuth 回跳绑定。
- **AUTH-5 OAuth 登录与注册分离**：已绑定用户直接登录并返回 token，未绑定用户经 `/Auth/OAuthPendingInfo` 与 `Register(category=oauth)` 完成注册，两条流程互不耦合。
- **AUTH-6 登录能力配置**：`/Auth/LoginConfig` 返回登录方式、OAuth 提供商与风险自适应验证码等登录能力，站点展示信息以 `/Cube/Site` 为准。

### 3.3 SITE — 站点与语言

- **SITE-1 站点信息接口**：匿名 `GET /Cube/Site`（兼容别名 `/Cube/SiteInfo`）返回名称、标题、Logo、Favicon、版权、备案、页脚、版本、`tenantCode`、`language` 与 `features.ai`；品牌字段为租户合并后的有效值，响应带 `ETag` 与 `Cache-Control` 并按租户与语言区分。
- **SITE-2 界面语言选择**：`POST /Auth/SetLanguage` 匿名可用并持久化选择（Cookie 与登录用户偏好）；`/Cube/Site` 的 `language` 返回 `current`/`default`/`locked`/`options:[{code,label,rtl}]`；登录页与后台在登录前后均可切换语言，界面文案与后端消息语言保持一致。

### 3.4 PERM — 菜单权限

- **PERM-1 菜单权限聚合**：`GET /Cube/MenuTree` 返回当前用户可访问的菜单树，多角色权限合并结果稳定。

### 3.5 DATA — 实体数据

- **DATA-1 实体 CRUD 最小集**：定义实体即获得 `GET`/`POST`/`PUT`/`DELETE /{type}` 与 `GET /{type}/{id}` 标准接口，覆盖列表、详情、新增、编辑、删除。
- **DATA-2 列表查询条件**：列表接口支持关键字 `Q`、时间区间 `dtStart`/`dtEnd`、排序与分页参数，各皮肤使用同一套查询语义。
- **DATA-3 批量与条件删除**：`DELETE /{type}` 支持 `ids=1,2,3` 或重复 `ids` 参数批量删除，单批上限 100 个主键；按搜索条件删除时必须至少一个过滤条件，禁止裸删全表。

### 3.6 EXT — 扩展能力

- **EXT-1 页面元数据**：`GET /{type}/meta` 返回页面设置与五区字段元数据（登录即可），前端按元数据渲染列表与表单。
- **EXT-2 数据导入导出**：提供 `export`/`import` 实体数据导入导出接口，导出支持分片与条数上限。
- **EXT-3 附件上传**：提供 `attachments` 附件上传接口与表单绑定流程（新增或修改权限）。
- **EXT-4 图表数据**：提供 `charts` 图表数据接口，供各皮肤渲染统计图表。

### 3.7 SEC — 安全底线

- **SEC-1 匿名接口收敛**：仅站点信息、登录等明确公开的端点允许匿名访问，端点清单、服务器信息与任意枚举查询一律要求认证。
- **SEC-2 认证接口限流**：登录、发码、注册与字典查询按 IP 与账号维度限流，超限返回 429。

## 5. 不做什么

- **不绑定前端框架**：不为任何单一前端框架引入特化接口或字段，平台保持后台快速开发 API 能力层的定位。
- **不规定前端实现方式**：组件库、路由、状态管理由各皮肤自行决定，本需求只约定接口契约。
- **不做无过滤条件的整表删除**：删除接口必须携带主键集合或至少一个搜索条件。
- **不新增 MVC 专属接口语义**：MVC 兼容由 NewLife.CubeNC 独立维护，本篇只约束 WebAPI 主线。
