# 页面呈现架构

Cube 的页面呈现采用「后端声明、前端渲染」：实体页面由 `/meta` 自描述字段与视图，前端按元数据渲染列表、表单、搜索和工具栏；只有元数据表达不了的交互才写前端页面。

目标开发者主要是后端与 AI：优先改 `Model.xml` 和字段集合，其次用插槽/渲染器，避免复制整页组件。

## 1. 三种页面模式

| 模式 | 是否请求 `/meta` | 谁写页面 | 适用场景 |
|---|---|---|---|
| **M1 动态页** | 是 | 框架 | 标准 CRUD、查询区、列表列、表单字段、工具栏按钮 |
| **M2 混合页** | 是 | 框架 + 区块插槽 | 整块表单布局、个别特殊单元格 |
| **M3 自定义页** | 按需 | 业务/AI | 地图、看板、连续录入、跨实体工作流 |

判定只看「有无自定义视图 + 是否包裹 `CubeTable`」：没有自定义视图为 M1；有 `views/<path>/index.vue` 且内部用 `CubeTable` 为 M2；不使用 `CubeTable` 为 M3。不新增模式开关。

## 2. 后端扩展梯

| 层 | 手段 | 能表达 | 说明 |
|---|---|---|---|
| B0 | `Model.xml` | `ShowIn`、`ItemType`、`Category`、Map、枚举、长度 | **首选**，改一处列表/表单/搜索/详情同时生效 |
| B1 | `ListFields` / `FormFields` / `SearchFields` / `Toolbar` | 页面级增删字段、顺序、标题、链接、数据源、工具栏按钮 | 页面级例外 |
| B2 | Area/项目基类 + `OnGetFields` + `OnActionExecuting` | 按请求参数/用户/数据量动态调整字段、权限、导航、排序 | 一片页面的统一规则 |
| B3 | 重写 `Meta()` | 追加自定义块 | 可用但不鼓励 |
| B4 | 自定义 Action + M3 页面 | 任意业务交互 | 复杂交互的唯一出口 |

B2 的统一配置应在请求期执行，不依赖派生控制器是否声明静态构造函数；静态构造函数只适合与字段集合同层的固定配置。

> API 版与 MVC 版的字段模型已经拆成两份：`NewLife.Cube/ViewModels` 持有 API 专属实现，`NewLife.CubeNC/ViewModels` 保持 MVC 原实现。通用语义改动需要两边同步，API 专属能力只改 API 副本。

## 3. 前端扩展梯

| 层 | 手段 | 能表达 |
|---|---|---|
| F0 | 无 | 默认渲染 |
| F1 | 页面呈现配置（preset） | 宽度/对齐/固定、表头文案、列序、隐藏列、表单列数、条件显隐、行按钮 |
| F1.5 | 全局渲染器注册 | 单元格/搜索/表单控件 |
| F2 | `CubeTable` 具名插槽 | `#form`、`#col-Prop`、`#search`、`#toolbar-extra` |
| F3 | 整页自定义 | 任意页面 |
| F4 | 回流 `core/` | 让默认引擎支持新能力 |

插槽与 MVC 视图的对应关系：

| MVC 自定义视图 | API 落点 |
|---|---|
| `_List_Search.cshtml` | `SearchFields` + `ShowIn(Search)` + 字段 `view`；不需要页面级插槽 |
| `_List_Data.cshtml` | `ListFields` + `ShowIn(List)` + `ItemType`；列宽/列序用 preset 或用户列偏好 |
| 单元格特殊渲染 | `#col-Prop` 插槽或全局单元格渲染器 |
| `_List_Toolbar_Custom.cshtml` | `meta.toolbar` 的 `link`/`request`/`upload`；`custom` 用前端 `registerToolbarRenderer` |
| `_List_Toolbar_Batch.cshtml` | `meta.toolbar` + `request` + `include: ["keys"]` |
| `_Form_Body.cshtml` | `#form` 插槽 |
| `Index.cshtml` | M3 整页自定义 |
| `NavView`（服务端局部视图） | 前端注册导航组件名，或 M3 |

## 4. `/meta` 契约

### 4.1 响应结构

`/meta` 返回统一信封，`data` 为页面自描述：

```json
{
  "code": 0,
  "data": {
    "entity": { "name": "Student", "displayName": "学生", "primaryKey": "Id" },
    "setting": {
      "enableAdd": true, "enableToolbar": true,
      "menuId": 12,
      "requiredPermissions": { "add": 2, "update": 4, "delete": 8 }
    },
    "list": [
      { "name": "Id", "displayName": "编号", "typeName": "Int32", "primaryKey": true, "readOnly": true },
      { "name": "Name", "displayName": "姓名", "typeName": "String", "length": 50 },
      { "name": "Remark", "displayName": "备注", "typeName": "String", "visible": false },
      { "name": "DetailLink", "virtual": true, "displayName": "明细", "typeName": "String", "url": "/School/StudentDetail?studentId={Id}", "text": "查看" }
    ],
    "form": [
      { "name": "Name", "displayName": "姓名", "typeName": "String", "required": true },
      { "name": "OrgRange", "virtual": true, "displayName": "组织范围", "typeName": "String", "view": "orgPicker", "props": { "group": ["FirstId", "LastId"] } }
    ],
    "search": [
      { "kind": "keyword", "name": "q", "displayName": "关键字", "typeName": "String" },
      { "name": "ClassId", "displayName": "班级", "typeName": "Int32", "itemType": "singleSelect", "dataSource": { "1": "一班", "2": "二班" } },
      { "kind": "range", "name": "dtStart", "end": "dtEnd", "field": "CreateTime", "displayName": "创建时间", "typeName": "DateTime" }
    ]
  }
}
```

结构规则：

1. **视图自描述**：`list` / `form` / `add` / `detail` / `search` 各自完整可渲染，消费端零合并。
2. `add` / `detail` 与 `form` 完全相同则省略该视图；不同则输出完整字段数组。
3. `list` 是**全部可用列**；`visible: false` 表示默认隐藏但可通过表格设置打开；控制器可写 `(ListFields.GetField("Remark") as ListField).Visible = false`。列顺序和用户显隐由前端 `localStorage` 保存，不在 `/meta` 下发 `order` / `hidden`。
4. `virtual: true` 表示非实体列；单对象页（`ObjectController` / `ConfigController`）只有 `form`。
5. 结构只做**加法**：新增能力加可选字段，不改已有字段语义，不引入契约版本号。
6. 各视图字段集已由 `ShowIn` 与字段集合决定，`/meta` 只负责序列化与少量推导（`kind`、`virtual`、`view`）。
7. `setting.enableAdd` 是页面能力；`requiredPermissions` 是动作所需权限位，不是当前用户的有效权限。前端用 `menuId` + `UserInfo.permission` 计算按钮显隐，`/meta` 因此可以安全缓存。

### 4.2 字段属性

| 属性 | 来源 |
|---|---|
| `name` / `typeName` / `length` / `precision` / `scale` / `nullable` / `primaryKey` / `readOnly` | 实体字段 |
| `displayName` / `description` / `category` | 模型 + 本地化 |
| `visible` | 列表字段默认显隐；`false` 时设置面板仍可选择 |
| `itemType` | 模型列 `ItemType` / 控制器覆盖 |
| `required` | 模型约束 / 控制器 |
| `dataSource` / `lovCode` / `multiple` / `parentField` | 控制器 / 枚举 / 值集 |
| `url` / `target` / `text` / `title` / `header` / `dataAction` / `valueField` / `textAlign` / `maxWidth` | 控制器 |
| `view` | 控制器（前端渲染器名） |
| `props` | `DataField.Properties`（扩展口，核心不解释） |
| `virtual` | `/meta` 构建器 |

### 4.3 查询项

| `kind` | 语义 | 提交参数 |
|---|---|---|
| `keyword` | 跨字段关键字模糊匹配 | `q` |
| `range` | 主时间字段区间 | `name` 与 `end`（缺省 `dtStart` / `dtEnd`） |
| `text` / 缺省 | 普通单字段查询 | 字段名 |

顺序为 `keyword` → `SearchFields` 顺序 → 主时间区间。主时间字段单独输出为 `dtStart` / `dtEnd`，从普通搜索项中移除。查询项只是控件清单，高级查询仍由控制器 `Search` 解析。

- API `FieldCollection` 默认添加虚拟 `Q` 搜索项；不需要关键字搜索的页面在控制器 `SearchFields.RemoveField("Q")` 关闭。
- `q` 使用 `kind: "keyword"`，不要改成 `text`：`text` 是普通字段查询，`keyword` 才表示跨字段关键字并占用搜索条首行。
- 主时间区间由 `Factory.MasterTime` 自动生成；控制器可重写 `EnableTimeRange` 关闭。

### 4.4 表单分组

`DataField.Category` 作为字段分组的稳定键下发。前端 `FormContent` 默认 `groupBy: auto`：

- 字段存在多个非空 `Category` 时，按分类渲染分组区块；
- 只有一个分类或没有分类时保持平铺；
- 未分类字段归入“其他”；
- 分组只影响布局，不改变字段顺序、校验和提交模型。

需要页签或特殊布局时，用业务页 `#form` 插槽替换整块表单，不在核心元数据中新增布局 DSL。

### 4.5 远程模糊与多选

远程选择优先复用 LOV，不为每个页面新增接口：

```csharp
// 表单多选
formField.ItemType = "multipleSelect";
formField.LovCode = "List.Cube.User";

// 搜索多选
searchField.ItemType = "multipleSelect";
searchField.Multiple = true;
searchField.LovCode = "List.Cube.User";
```

- 列表型值集用 `[LovList]` 声明，支持 `SearchFields`、分页和远程模糊搜索；前端 `LovSelect` / `LovSelectTable` 已按这套契约渲染。
- 多选数组在查询参数中统一转逗号分隔；后端默认 `Search` 对 `SearchField.Multiple` 使用 `In`，逗号拼接字符串字段由业务 `Search` 使用 `Contains`。
- 无法表达为 LOV 的特殊控件才使用字段 `view` + `props` 注册渲染器，不把页面专属接口塞进 `/meta`。

## 5. 工具栏按钮

MVC 的工具栏视图由 `meta.toolbar` 声明，后端声明、服务端按权限过滤，前端只负责渲染。

```csharp
static OrderController()
{
    Toolbar.AddLink("导入数据", "/Biz/Forecast/Import", target: "_blank");
    Toolbar.AddUpload("导入 Excel", "ImportExcel", accept: ".xlsx", permission: PermissionFlags.Update);
    Toolbar.AddAction("批量刷新", "Refresh", method: "POST", include: ["keys"]);
    Toolbar.AddLink("地图", "/Base/Org/Map", appendQuery: true, target: "_blank");
    Toolbar.AddCustom("高级导入", "advancedImport");
}

// 或标在动作上，权限自动取同方法的 EntityAuthorize
[ToolbarButton("批量刷新", PermissionFlags.Update, Method = "POST")]
public ActionResult Refresh([FromForm] String keys) { ... }
```

规则：

- 只下发当前用户有权限的按钮；权限优先级为按钮显式 `permission` → 动作 `[EntityAuthorize]` → 控制器级 `[EntityAuthorize]` → 不限。
- `include` 默认 `["keys"]`；包含 `keys` 时要求先选中数据，前端据此禁用按钮。
- `request` 使用 `application/x-www-form-urlencoded` 提交；`upload` 使用 `multipart/form-data`。
- 响应沿用统一信封：`message` 提示、`data.refresh` 刷新、`data.url` 跳转、`data.time` 延迟刷新。
- 区域/项目级统一追加按钮时重写 `OnBuildToolbar(ToolbarCollection)`；该方法在权限过滤前执行，追加的按钮同样受权限控制。

实现位置：控制器能力在 `ReadOnlyEntityController` 的工具栏 region，收集与权限过滤在 `ToolbarBuilder`，模型在 `ToolbarItem`/`ToolbarCollection`，动作特性为 `ToolbarButtonAttribute`。这些类型只存在于 API 版项目，不影响 MVC。

## 6. 关键机制

### 6.1 字段显隐：`ShowIn`

`ShowIn` 用五区三态描述字段在 **List / Detail / AddForm / EditForm / Search** 的显示策略，未指定即 Auto。

| 写法 | 示例 |
|---|---|
| 具名列表（推荐） | `List,Search` / `-EditForm,-Detail` / `All,-Detail` / `None,Search,Add` |
| 管道 5 段 | `Y\|Y\|N\|\|A` |
| 5 字符掩码 | `110A?` |

列表/表单/详情在 `FieldCollection` 构造时按 `ShowIn` 过滤；搜索区由 `SearchBuilder` 优先读 `ShowIn.Search`，再叠加默认算法。因此「字段不要出现在某区域」应优先改 `Model.xml`，控制器 `RemoveField` 只处理页面级例外。

### 6.2 搜索区默认算法

`SearchBuilder` 与实体代码生成共用同一口径：

1. 索引列参与高级查询模板；主键、自增、`Master` 字段排除。
2. `ShowIn.Search` 优先：`Show` 强制加入，`Hide` 强制排除。
3. 特殊字段自动加入：枚举、带 `Map` 的整型、布尔型（`enable`/`isDeleted` 除外）、`Properties["Type"]` 指定类型。
4. `enable` / `isDeleted` 排在最后。
5. 主时间字段单独作为 `dtStart` / `dtEnd` 区间，从普通搜索项移除。
6. Flags 枚举输出多选。

控制器 `SearchFields` 只做例外：补索引外字段、移除不搜索字段、加虚拟查询项、指定 `DataSource` 或 `ItemType`。

### 6.3 `ItemType`

`ItemType` 是控件与格式化的统一声明位。取值以 CubeNC（`_Form_Item` / `_List_Data_Item` / `ViewHelper.FormatValue`）与 XCode（`BindColumn.ItemType`）已实际使用的全集为准：

| 类别 | 取值 | 表单 | 列表 |
|---|---|---|---|
| 文本 | `password`、`phone`、`fax`、`mobile`、`email`、`mail`、`url`、`textarea` | 遮蔽/电话/邮箱/网址/多行 | 文本 |
| 数值 | `percent`、`Percentage`、`money`、`number`、`decimal(p,s)` | 数值输入（带 `¥`/`%` 前后缀） | 百分比（按描述单位缩放）、金额千分位、按小数位补零 |
| 日期时间 | `Date`、`date`、`time`、`time-<.NET 格式>` | 日期（不带时分秒） | `time` 完整时间；`time-<格式>` 按格式串输出 |
| 时长 | `TimeSpan`、`TimeSpan:<格式>`、`Time`、`Time:<格式>` | 时间选择（`TimeSpan` 类型列） | 秒/毫秒/分/小时换算后按默认或自定义格式输出 |
| 容量 | `GMK` | 数值输入 | 1024 进制人类可读（`1.00K`/`3.50M`） |
| 选择 | `singleSelect`、`multipleSelect`、`lovTable`、`lovTableMulti` | 下拉 / 多选 | 值集翻译 |
| 区域 | `area`、`area1`~`area4` | 级联 | 文本 |
| 文件 | `image`、`image-*`、`file`、`file-*`、`avatar`、`attachment` | 图片/附件上传（按后缀限制） | 缩略图 / 下载链接 |
| 富文本 | `html`、`richtext`、`markdown` | 富文本编辑器 | 截断摘要 |
| 其他 | `json`、`color`、`icon`、`code` | 专用控件 | 摘要 / 色块 / 图标 |

前端用 `core/utils/fieldControl.ts` 一张 `itemType → 控件` 映射表统一处理（大小写与首尾空格归一），未知类型回退按 `TypeName` 推断的默认控件，不白屏。新增类型只改映射表和模型。

`TimeSpan` 的换算单位由字段描述决定：含「毫秒 / ms」按毫秒，含「小时 / hour」按小时，含「分 / minute」按分钟，其余按秒——与后端 `ViewHelper.FormatValue` 同口径。

### 6.4 字段级自定义视图

后端下发 `view` 名和 `props`，前端按名注册组件：

```csharp
var df = SearchFields.AddDataField("selectRange") as SearchField;
df.View = "selectRange";   // meta: { "name":"selectRange", "view":"selectRange", "props":{...} }
```

```ts
registerToolbarRenderer('advancedImport', { component: AdvancedImportButton }); // 工具栏 custom 按钮
```

多字段合并（MVC `GroupView`）用「虚拟字段 + `view` + `props.group`」表达；渲染器未注册时降级为默认控件并告警一次。

### 6.5 链接占位符

| 占位符 | 含义 |
|---|---|
| `{字段名}` | 当前行值 |
| `{page:参数名}` | 当前页面查询参数（下钻保上下文） |

### 6.6 页面呈现配置（preset）

preset 是纯前端配置，只做元数据没覆盖到的呈现打磨，合并到 `/meta` 结果上；不写组件、不发请求、不改后端。

```ts
interface PagePreset {
  setting?: Partial<PageSetting>;
  list?: {
    remove?: string[];
    patch?: Record<string, FieldPresetPatch>;
    append?: DataField[];
    order?: string[];
    actions?: RowAction[];
  };
  form?: {
    remove?: string[];
    patch?: Record<string, FieldPresetPatch>;
    append?: DataField[];
    columns?: 1 | 2 | 3;
    groupBy?: 'category' | ((f: DataField) => string);
  };
  search?: { remove?: string[]; append?: SearchItem[] };
}

interface FieldPresetPatch {
  label?: string;
  width?: number | 'auto';
  align?: 'left' | 'center' | 'right';
  fixed?: 'left' | 'right';
  renderer?: string;
  hidden?: boolean;
  visibleWhen?: (model: Record<string, unknown>) => boolean;
  requiredWhen?: (model: Record<string, unknown>) => boolean;
}
```

合并顺序：`/meta` → preset → 用户列偏好（`order` / `hidden`，优先级最高）。preset 表达不了时用 F2 插槽。

## 7. 定制决策树

```
需求：改变页面某处
│
├─ 某字段在列表/表单/搜索/详情不该出现？
│   └─ Model.xml 的 ShowIn（首选）→ 页面例外再用 ListFields.RemoveField
├─ 字段要换控件或显示格式？
│   └─ Model.xml 的 ItemType（首选）→ 控制器覆盖
├─ 搜索区要加/减条件？
│   └─ ShowIn(Search)（首选）→ SearchFields（页面例外）
├─ 列表要调列序/宽度/表头？
│   └─ ListFields（列集合）+ preset / 用户列偏好（呈现）
├─ 值依赖业务上下文（掩码、关联名、下钻链接）？
│   └─ ListField.Url / AddListField
├─ 一片页面需要同样的规则？
│   └─ Area/项目基类
├─ 需要自定义控件（组织选择器/级联/标签）？
│   └─ 后端 view 名 + 前端全局注册器
├─ 工具栏要加按钮？
│   ├─ 跳转/请求/上传 → Toolbar.Add* 或 [ToolbarButton] → meta.toolbar
│   └─ 弹窗/图表 → kind: custom + registerToolbarRenderer
├─ 整块表单体布局？
│   └─ F2 #form 插槽
├─ 信息架构不同（地图/看板/工作流）？
│   └─ F3 整页自定义
└─ 同类需求已在 3 个页面出现？
    └─ F4 回流 core
```

## 8. 默认规则

原则：能用 `Model.xml` 表达的，不写控制器代码。

0. **能力与权限分离**：`enableAdd` / `isReadOnly` / `enableSelect` 是页面能力；编辑、删除、批量删除再按当前用户权限过滤。不要把有效权限写进可缓存的 `/meta`。
1. **优先 `ShowIn`**：新增/维护页面时先在模型声明五区显隐；控制器 `RemoveField` 只处理页面级例外。
2. **列表默认隐藏扩展与审计定位字段**：`Ex1`~`Ex6`、`CreateIP`、`UpdateIP`、`CreateUserID`、`UpdateUserID`；表单与详情不受影响。
3. **TraceId 自动追踪链接**：配置 `CubeSetting.StarWeb` 时自动生成链接列，支持 `{traceId}` 占位符；控制器显式设置 `Url` 时以控制器为准。

## 9. MVC 能力对照

**可直接复刻**：

| MVC 能力 | API 等价物 |
|---|---|
| `ListField.View` / `SearchField.View` / `FormField.ItemView` | 字段 `view` + 全局渲染器 |
| `FormField.GroupView` | 虚拟字段 + `view` + `props.group` |
| `ListField.Url` 的 `{字段}` / `{page:参数}` | 前端模板替换 + 当前查询上下文 |
| `ListField.ValueField` | 前端单元格取值优先 |
| `_List_Search.cshtml` | `SearchFields` + `ShowIn(Search)` |
| `_List_Data.cshtml` | `ListFields` + `ShowIn(List)` + `ItemType` |
| 工具栏视图 | `meta.toolbar`（`link`/`request`/`upload`）；`custom` 用渲染器 |
| `_Form_Body.cshtml` | `#form` 插槽 |
| `Index.cshtml` | M3 前端页面 |

**保留但不推荐**：`GetValue`、`DataVisible`、`ListField.GetClass`、`FieldCollection.GroupVisible`。表达力强但逐行委托、难以静态化，优先用渲染器或 `visibleWhen`。

**不复刻**：`FormField.Expand`（用 M3）、`NavView` 服务端局部视图（用前端组件或 M3）、`{page:$BaseUrl(...)}`、多命名视图（kanban/calendar/gallery）、服务端视图继承补丁。
