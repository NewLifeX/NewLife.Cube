# 魔方 WebAPI 核心接口架构（前端皮肤对接标准）

> 版本：2026-10-22  
> 适用范围：NewLife.Cube 第三代（WebAPI 主线）

---

## 1. 文档目标

本文档用于统一各前端皮肤（Vue/React/Arco/Naive/TDesign 等）对接 NewLife.Cube 的 API 规范，重点定义：

1. 最小可运行接入所需接口（必要接口）。
2. 可选增强能力接口（高级接口）。
3. 认证、CRUD、OAuth 的统一语义与参数约定。

## 2. 必要接口与高级接口

### 2.1 必要接口（最小可运行集合）

> 最小接入可硬编码站点名称与密码登录；需要动态品牌/语言/租户上下文时接入 `/Cube/Site`（高级），需要验证码/OAuth/注册能力时接入 `/Auth/LoginConfig`（高级）。

| 模块 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 认证 | POST | `/Auth/Login` | 密码登录（`category` 为空表示密码登录） |
| 认证 | POST | `/Auth/Refresh` | 刷新令牌 |
| 认证 | GET | `/Auth/Info` | 当前用户信息 |
| 认证 | POST | `/Auth/Logout` | 登出 |
| 菜单 | GET | `/Cube/MenuTree` | 当前用户可访问菜单树 |
| 实体 | GET | `/{type}` | 列表查询（分页/筛选/排序） |
| 实体 | GET | `/{type}/{id}` | 详情 |
| 实体 | POST | `/{type}` | 新增 |
| 实体 | PUT | `/{type}/{id}` | 编辑 |
| 实体 | DELETE | `/{type}/{id}` | 单条删除 |

> 实体接口的 `/{type}` 是 `/api/{area}/{controller}` 的简写；端点、权限、写操作语义与响应细节统一见 [第36章 WebAPI接口规范](WebAPI接口规范.md)。

### 2.2 高级接口（按需实现）

| 模块 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 站点 | GET | `/Cube/Site` | 站点品牌、语言选项、AI 开关、租户上下文（匿名、可缓存；可选） |
| 登录配置 | GET | `/Auth/LoginConfig` | 登录方式、OAuth 提供商等登录能力与租户开关 |
| 安全增强 | GET | `/Auth/Challenge` | Challenge-Response 公钥与 challengeId |
| 验证码 | POST | `/Auth/SendCode` | 发送手机/邮箱验证码 |
| 验证码登录 | POST | `/Auth/Login` | 统一登录，需传 `category: "mobile"` 或 `"mail"` |
| 忘记密码 | POST | `/Auth/ResetPassword` | 验证码重置密码 |
| 注册 | POST | `/Auth/Register` | 统一注册 |
| OAuth 注册辅助 | GET | `/Auth/OAuthPendingInfo` | OAuth 回跳预填信息 |
| 微信登录（小程序） | POST | `/Sso/WxMiniLogin` | `{ code, appId? }`，appId 也可走 `X-App-Id` 头 |
| 微信登录（App） | POST | `/Sso/WxAppLogin` | 同上 |
| 元数据 | GET | `/{type}/meta` | 页面字段元数据（登录即可） |
| 导出 | GET | `/{type}/export` | 数据导出 |
| 导入 | POST | `/{type}/import` | 数据导入 |
| 上传 | POST | `/{type}/attachments` | 附件上传（Insert 或 Update） |
| 图表 | GET | `/{type}/charts` | 图表数据 |
| 批量删除 | DELETE | `/{type}?ids=1,2,3` | 逗号分隔或重复参数 `?ids=1&ids=2`，单次最多 100 个 |

```text
Step 1  POST /Auth/Login
```

## 4. 认证接口规范（AuthController）

### 4.1 登录（必要）

```http
POST /Auth/Login
Content-Type: application/json
```

请求示例：

```json
{
  "username": "admin",
  "password": "admin",
  "category": "",
  "challengeId": "",
  "captchaId": "",
  "captchaCode": "",
  "remember": false
}
```

字段说明：

| 字段 | 必填 | 说明 |
|------|------|------|
| `username` | 是 | 用户名 |
| `password` | 是 | 密码明文，或加密密文；验证码登录时承载验证码 |
| `category` | 否 | 字符串枚举：`""`（密码）、`mobile`、`mail`（`oauth` 仅用于注册） |
| `challengeId` | 否 | 走 Challenge-Response 时传入 |
| `captchaId` | 否 | 图片验证码编号。登录返回 `code=-6` 时携带 |
| `captchaCode` | 否 | 图片验证码内容。登录返回 `code=-6` 时携带 |
| `remember` | 否 | 记住登录状态，延长令牌有效期 |

### 4.2 验证码登录（高级）

验证码登录与密码登录共用 `/Auth/Login` 接口，区别在于 `category` 字段取值不同：

```http
POST /Auth/Login
Content-Type: application/json
```

请求示例（手机验证码）：

```json
{
  "username": "13800138000",
  "password": "123456",
  "category": "mobile"
}
```

说明：
- `category` 在验证码登录场景仅允许 `mobile` 或 `mail`。
- `password` 字段承载验证码。

### 4.3 Challenge（高级）

```http
GET /Auth/Challenge
```

响应示例：

```json
{
  "code": 0,
  "data": {
    "challengeId": "a3f2c8e1-4b7d-11ef-9012-0800200c9a66",
    "publicKey": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----"
  }
}
```

> 本文档不提供前端加密代码示例。

### 4.4 发送验证码（高级）

```http
POST /Auth/SendCode
Content-Type: application/json
```

请求示例：

```json
{
  "channel": "Sms",
  "username": "13800138000",
  "action": "Login"
}
```

### 4.5 忘记密码（高级）

```http
POST /Auth/ResetPassword
Content-Type: application/json
```

请求示例：

```json
{
  "username": "13800138000",
  "code": "123456",
  "newPassword": "NewPass@2026",
  "confirmPassword": "NewPass@2026"
}
```

- 先调 `POST /Auth/SendCode`（`action: "reset"`）发码；账号按格式分发到短信/邮件通道，因此站点需开启 `EnableSms` 或 `EnableMail`。
- 登录页「忘记密码」入口仅在上述通道至少一个开启时展示（`login.sms || login.mail`）。
- 站点禁止明文密码（`AllowPlainPassword=false`）时需携带 `challengeId` 与密文；官方前端库 `@newlifex/cube` 的 `user.resetPassword()` 会自动取 Challenge 加密后提交，不可达时降级明文。

### 4.6 统一注册（高级）

```http
POST /Auth/Register
Content-Type: application/json
```

`category` 使用字符串枚举：

- `""`：用户名密码注册（默认）
- `mobile`：手机验证码注册
- `mail`：邮箱验证码注册
- `oauth`：OAuth 回跳后绑定注册

#### 注册示例 1：用户名密码

```json
{
  "category": "",
  "username": "newuser",
  "email": "newuser@example.com",
  "password": "Strong@2026",
  "confirmPassword": "Strong@2026"
}
```

#### 注册示例 2：手机验证码

```json
{
  "category": "mobile",
  "mobile": "13800138001",
  "username": "13800138001",
  "code": "123456",
  "password": "Strong@2026",
  "confirmPassword": "Strong@2026"
}
```

#### 注册示例 3：邮箱验证码

```json
{
  "category": "mail",
  "email": "newuser@example.com",
  "username": "newuser@example.com",
  "code": "123456",
  "password": "Strong@2026",
  "confirmPassword": "Strong@2026"
}
```

#### 注册示例 4：OAuth 绑定注册

```json
{
  "category": "oauth",
  "oauthToken": "6d58fdf6...",
  "username": "newuser",
  "password": "Strong@2026",
  "confirmPassword": "Strong@2026"
}
```

#### 多租户请求头契约

开启多租户（`CubeSetting.EnableTenant=true`）后，以下请求头用于定位/校验租户（注册、微信登录及所有受保护接口）：

| Header | 语义 | 说明 |
|--------|------|------|
| `X-Tenant` | **租户编码（Code）** | 按 `Tenant.FindByCode` 解析（旧的 `X-Tenant-Id` 数字ID头已随影子期结束移除） |
| `X-App-Id` | OAuth 应用 AppId | 注册时按 `OAuthConfig.FindByAppId` 定位其所属租户（优先于 X-Tenant）；微信登录在请求体未传 appId 时兜底 |

- 多租户开启时，注册必须携带 `X-App-Id` 或 `X-Tenant`，否则拒绝注册。
- 伪造、不存在或已禁用的租户会被拒绝（400/403）。
- 未开启多租户时不校验租户，与旧逻辑一致。

### 4.7 刷新令牌（必要）

```http
POST /Auth/Refresh
{ "userName": "admin", "refreshToken": "<refreshToken>" }
```

响应 `data` 同时提供新旧两套字段名（旧字段保留一个兼容周期）：

```json
{ "accessToken": "...", "refreshToken": "...", "expireIn": 7200, "token": "..." }
```

- **令牌归属校验**：刷新令牌内嵌用户名必须与请求 `userName` 一致，且该用户启用、`UserToken` 记录未被吊销且未过期，否则统一返回 `CubeCode.LogOff(-4)`，不下发新令牌。
- **令牌轮换**：刷新成功即吊销旧令牌，旧令牌再次使用按重放拒绝；服务端另以 SHA-256 指纹维护短期黑名单。
- 单设备模式下吊销全部旧令牌的逻辑见 AUTH-12。

## 5. OAuth 流程（登录与注册分离）

### 5.1 OAuth 已绑定用户：直接登录

```text
Step 1  前端跳转 /Sso/Login/{provider}?r=/admin/index
Step 2  后端重定向到 OAuth 提供商，用户完成授权
Step 3  回跳后端，识别到已绑定用户
Step 4  直接颁发 accessToken/refreshToken
```

### 5.2 OAuth 首次用户：进入注册

```text
Step 1  前端跳转 /Sso/Login/{provider}?r=/auth/register
Step 2  后端重定向到 OAuth 提供商，用户完成授权
Step 3  回跳后端，识别到未绑定用户，返回 oauthToken
Step 4  前端调用 GET /Auth/OAuthPendingInfo?token=xxx 获取预填信息
Step 5  前端提交 POST /Auth/Register（category=oauth）
Step 6  注册成功后颁发 accessToken/refreshToken
```

## 7. 页面元数据（高级）

```http
GET /api/{area}/{controller}/meta
```

用于返回页面设置与字段元数据（视图自描述，`list/form/add/detail/search` 各自完整字段数组 + `entity` + `toolbar`）；单对象页只返回 `entity/setting/form`。`@newlifex/cube` 的 `getPage` 会展开为 `list/addForm/editForm/detail/search + toolbar`。列表字段带 `visible`，搜索项用 `kind: keyword/range` 描述关键字与主时间区间；`setting` 只下发页面能力和静态的 `menuId`/`requiredPermissions`，有效权限由前端结合用户信息计算，避免 `/meta` 缓存旧权限。需要公开页匿名访问时，在控制器重写 `Meta()` 并标注 `[AllowAnonymous]`。响应结构见 [第36章 36.10](WebAPI接口规范.md)。

## 8. 菜单与公共接口

### 8.1 菜单树（必要）

```http
GET /Cube/MenuTree?module=Admin
```

### 8.2 字典查询（高级）

```http
GET /Cube/Lookup?codes=NewLife.Cube.Enums.AuthCategory,EnableFlag
```

- 需登录：匿名访问返回 401。
- `codes` 仅接受已加载程序集中的枚举类型全名，最多 20 个且总长度不超过 2000，超限返回 `CubeCode.ParamError(-2)`。
- 解析走 `LovRegistry.FindEnumType`（已加载程序集索引 + 进程缓存），不做按程序集限定名的动态加载。

### 8.3 健康检测（必要）

```http
GET /Cube/Health?state=probe-1
```

- 匿名可访问，仅返回 `{ status, time, state }`，用于负载均衡与探针，不暴露操作系统、端口与版本指纹。
- 服务注册中心（`RegisterService`）的健康地址应指向本端点；服务器详情见仅管理员可用的 `/Cube/Info`。

## 11. 响应与错误模型

### 11.1 统一响应包

`ApiResponse<T>` / `ApiListResponse<T>` 的字段、序列化规则与成功判定见 [第36章 36.3](WebAPI接口规范.md)。新接口一律使用统一响应包。

### 11.2 业务码

通用码沿用 `CubeCode`（`0` 成功；`-1`~`-7` 通用失败/参数错误/远程调用/重新登录/内部错误/图片验证码/需要二步验证），与全局 `ApiCode` 的分层及实际返回见 [第36章 36.4](WebAPI接口规范.md)。

规划分段（新增码写入本节与 OpenAPI）：

| 区间 | 领域 |
|------|------|
| 1000–1999 | 认证与账号（MFA、激活、令牌） |
| 2000–2999 | 租户与权限 |
| 3000–3999 | 实体 CRUD 与导入导出 |

> MFA 已改为结构化返回：账密正确但用户开启 MFA 时返回 `code = CubeCode.MfaRequired(-7)`，`data.mfaToken` 为挂起令牌；`message` 仍保留 `mfa_required:{token}` 供旧客户端解析。前端应优先按 `code` 分支，携 `mfaToken + code` 调用 `POST /Mfa/Verify` 完成登录。

### 11.3 HTTP 状态

- 现状：业务错误统一 HTTP 200，客户端以响应体 `code` 为准；实体控制器与访问规则已对 401/403 同步 HTTP 状态；`/Cube/Info`、`/Cube/Apis` 已要求系统管理员（默认关闭接口浏览器）。
- 迁移期开关：`CubeSetting.EnableHttpStatusCodes`（默认 false）开启后，401/403/404/409/422/429/500 同时写入对应 HTTP 状态，业务码（0 与负数）仍为 200。
- 目标：协议层错误使用对应状态码，业务层错误仍用 200 + `code`：

| 状态 | 场景 |
|------|------|
| 401 | 未登录或令牌失效 |
| 403 | 已登录但无权限/租户不匹配 |
| 404 | 资源不存在 |
| 409 | 并发冲突或重复提交 |
| 413 / 415 / 422 | 体积超限 / 类型不支持 / 校验失败 |
| 429 | 触发限流（配合 `Retry-After`） |

迁移期内客户端应同时判断 HTTP 状态与 `code`，服务端保证两者不矛盾。

### 11.4 分页、排序与筛选

参数、`PageModel` 字段与排序限制见 [第36章 36.5](WebAPI接口规范.md)（分页排序）与 36.6（搜索过滤）。

- 排序必须带唯一键兜底（如 `Id`），避免翻页重复/遗漏。
- 导出与导入应设置独立上限，超过上限返回明确业务码，不静默截断。

### 11.5 幂等与限额

- 注册：用户名/邮箱/手机号唯一；重复提交返回同一业务错误，不重复建号。
- 发码：同一账号/手机/邮箱在冷却窗口内拒绝重复发送。
- 导入/上传：体积上限取 `CubeSetting.UploadMaxSize`（MB，默认 20，0 不限制），超限返回明确业务码；扩展名黑名单禁止可执行文件。
- 幂等：导入（`/import`）与附件上传（`/attachments`）支持可选请求头 `Idempotency-Key`，同一用户+路径+键在 10 分钟内重复提交时直接重放首次成功结果；未携带头时行为不变。
- 限流：`CubeSetting.EnableRateLimit`（默认开启）对登录、刷新、发码、字典与站点接口按「接口 + IP」固定窗口计数，超限返回 HTTP 429 与 `Retry-After`；发码窗口更严（10 次/分钟）。
- 批量删除：必须带至少一个筛选条件；不允许空条件清空全表。

## 12. 站点配置（`/Cube/Site`）

### 12.1 定位

`/Cube/Site` 是**高级/可选**接口，提供登录页与后台外壳可选的站点品牌、语言与站点级能力。匿名可访问、结果可缓存。

- 最小接入可硬编码站点名称与密码登录；需要动态品牌、语言选项、AI 开关或租户上下文时接入本接口。
- 所有品牌字段都是**服务端按当前租户合并后的有效值**，前端不做二次覆盖。
- `tenantCode` 仅表示当前是租户上下文（非空）还是非租户上下文（空），不返回完整租户对象。
- 登录能力（登录/注册/安全/OAuth）由 `/Auth/LoginConfig` 提供，本接口不返回。

### 12.2 请求

```http
GET /Cube/Site?tenant={id|code|name}
```

- `tenant` 可选，支持租户 ID（数字）、Code 或名称；为空时使用当前请求上下文已解析的租户（`X-App-Id`/`X-Tenant`/`tenantId`/Cookie）。
- 响应头：`ETag`、`Cache-Control: public,max-age=60`、`Vary: Accept-Language, X-Tenant, X-App-Id, Cookie`。

| `name` | 站点名称；按语言的租户覆盖 → 租户名称 → 全局显示名 |
| `logo` | 站点 Logo；按语言的租户覆盖 → 租户 Logo → 登录页 Logo 配置，为空时前端使用内置默认 |
| `loginBackground` / `loginTip` | 登录页背景与提示；取站点设置 |
| `copyright` / `registration` | 版权与备案号；支持 `{now:yyyy}` 等变量，前端直接渲染 |
| `version` / `buildTime` | 站点版本与构建时间，用于缓存对齐与排障 |
| `tenantCode` | 当前租户编码；为空表示非租户上下文 |
| `language` | 语言选择所需的最小信息，用法见第 13.4 节 |
| `features.ai` | AI 助手开关、主辅色与 Mermaid 地址；后续站点级能力在此扩展 |

### 12.5 租户与缓存

租户语言与品牌通过**字典参数**配置，无需新增表：参数分类 `TenantSite`、名称=租户编码、长值为 JSON：

```json
{
  "defaultLanguage": "zh-Hans",
  "languages": [ "zh-Hans", "en-US" ],
  "names": { "zh-Hans": "租户甲" },
  "logos": { "zh-Hans": "/logo-a.png" }
}
```

- 合并优先级：租户+语言覆盖 → 租户默认 → 站点默认；`languages` 非空时作为白名单，当前语言不在其中则回退默认语言。
- `language.locked` = 站点已配置受支持的界面语言（此时全站锁定，前端隐藏语言切换入口）。
- 管理员可在「参数管理」中维护；未配置时行为与全局站点配置一致。

- 品牌合并：`name` / `logo` 按语言覆盖 → 租户级 → 站点级；其余品牌字段取站点设置；登录提示只取站点设置，不公开租户 `Remark`。
- 缓存：`ETag` 由响应内容哈希生成，`Cache-Control: public, max-age=60`；配置修改后由客户端条件请求自然失效，无需主动清缓存。
- 风险自适应验证码等随请求环境变化的字段不进入本接口；登录失败时由 `/Auth/Login` 返回 `code=-6` 及验证码信息。

### 12.6 与 `/Auth/LoginConfig` 的职责边界

| 能力 | `/Cube/Site` | `/Auth/LoginConfig` |
|------|--------------|---------------------|
| 名称/Logo/版权/备案/登录提示 | ✅ | — |
| 语言选项 | ✅ | — |
| 站点级能力（AI） | ✅ | — |
| 登录/注册/安全/OAuth 能力 | — | ✅ |
| 租户上下文 | `tenantCode` | — |
| 租户开关与编码（登录页） | — | `enableTenant` + `code` |

`tenantCode` 表示“当前请求处于哪个租户上下文”，用于界面标识或链接；`enableTenant`/`code` 表示“登录页是否需要显示租户选择”，两者语义不同。`/Auth/LoginConfig` 不返回任何站点品牌字段，未接入 `/Cube/Site` 时前端使用内置默认品牌。

## 13. 语言约定

### 13.1 优先级

```
?lang= 显式参数
  > Accept-Language
  > 租户默认语言
  > 站点默认语言（NewLife.Setting.Language）
  > 英文源文
```

- 第三代 SPA 只依赖 `Accept-Language`；`?lang=` 用于显式链接。
- MVC 与整页跳转场景可继续使用 Cookie `.AspNet.Culture`，不属于 SPA 契约。
- `NewLife.Setting.Language` 留空表示自动跟随请求语言，配置受支持语言即全站锁定（忽略上述来源）。

### 13.2 存储

| 层 | 用途 |
|---|---|
| `localStorage['cube-language']` | SPA 界面语言；换浏览器/电脑允许不同 |
| `Accept-Language` 请求头 | 每次 API 请求携带当前选择，服务端据此返回本地化消息 |
| Cookie `.AspNet.Culture` | 仅 MVC/整页跳转；SPA 不依赖 |

不做用户 `Parameter`：跨设备一致性价值低，且引入登录态依赖与数据库写入。

### 13.3 切换语言

前端切换时：

1. 更新 `vue-i18n`/`react-i18next` 的 locale。
2. 设置 `<html lang>` 与 `dir`。
3. 写入 `localStorage['cube-language']`。
4. 更新 HTTP 客户端默认 `Accept-Language`，后续请求自动携带。

不需要调用后端接口。若页面已展示服务端下发的文本（如 `loginTip`），可重新请求 `/Cube/Site` 获取新语言内容。

恢复自动：删除 `localStorage['cube-language']`，使用 `navigator.language`，并同步更新请求头。

### 13.4 `language` 怎么用

| 字段 | 含义 | 前端动作 |
|------|------|----------|
| `current` | 服务端按 13.1 解析的本次语言 | 启动兜底；`localStorage` 有值时以本地为准 |
| `default` | 站点/租户默认语言 | 浏览器语言不受支持时的兜底 |
| `locked` | 是否锁定语言 | `true` 时隐藏语言切换器 |
| `options` | 可选语言列表 | 渲染下拉；`nativeName` 为母语名称；`dir` 由语言代码推导（如 `ar`/`he`/`fa`/`ur` 为 RTL） |

前端四步：

1. **启动**：读取 `localStorage['cube-language']`；有值则写入 HTTP 客户端 `Accept-Language`，否则用浏览器语言。`/Cube/Site` 可选，用 `current` 校验。
2. **渲染**：用 `options` 生成语言下拉；`locked=true` 时不显示。
3. **切换**：按 13.3 更新本地与请求头；不需要调用后端。
4. **恢复自动**：删除 `localStorage`，使用 `navigator.language` 并更新请求头。

> 服务端按 `Accept-Language` 解析；前端只需保证请求头与 `localStorage` 一致。

### 13.5 租户语言

- 租户可配置默认语言、允许语言白名单、是否锁定（规划中的 `TenantSetting`）。
- 浏览器选择的语言不在当前租户白名单时回退租户默认语言，且不覆盖本地选择（切换租户后仍保留）。
- `language.options` 返回「站点全集 ∩ 租户白名单」；`default` 取租户默认；`current` 为本次请求解析结果。

### 13.6 网站页与后台

- 后台 SPA：语言来自 `localStorage` + `Accept-Language`，不依赖 Cookie。
- 对外网站页面（服务端渲染）：语言应进入 URL（`/en/...` 或子域）并输出 `hreflang`，Cookie 仅用于记忆选择；`localStorage` 不能作为唯一来源。
- 服务端主动消息（站内信、告警、批量邮件）按**收件人**语言渲染，不依赖请求语言。

## 14. 安全约定

1. **令牌传输**：新前端只使用 `Authorization` 请求头（`Bearer` 令牌方案），禁止在 URL 查询串传递访问令牌/刷新令牌；服务端 `/Sso/UserInfo`、`/Sso/Auth`、`/Sso/Verify` 已改为**优先读 Authorization 头**，仅当头缺失时才回退到查询串并输出 `Warning` 头与日志（兼容期）；`LoadToken()` 现状仍兼容 `X-Token`、`?token=` 与 Cookie，仅作兼容、不得新增使用。
2. **匿名面最小化**：`/Cube/Apis`（端点清单）需登录 + 系统管理员且 `CubeSetting.EnableApiExplorer=true`（默认关闭）；`/Cube/Info`（服务器信息）仅系统管理员；`/Cube/Lookup`（枚举字典）需登录、仅接受已加载程序集枚举并限 20 项；匿名健康检测改用 `/Cube/Health`。
3. **对象级授权**：所有按 ID 访问的接口必须校验数据归属与租户归属；租户校验失败按 fail-closed 处理。
4. **批量赋值**：新增/编辑只接受字段白名单，忽略未知字段；密码、角色、租户等敏感字段不参与批量绑定。
5. **限流**：登录、发码、刷新、字典查询与站点配置按 IP 维度限流，超限返回 429 + `Retry-After`（`CubeSetting.EnableRateLimit`，默认开启）。
6. **上传/导入**：校验体积与扩展名；禁止可执行文件；体积上限取 `CubeSetting.UploadMaxSize`（MB，默认 20）。
7. **错误信息**：对外消息不包含堆栈、物理路径、SQL 与内部地址；详细原因写入日志，统一响应包的 `Json` 结果已附带 `traceId`。
