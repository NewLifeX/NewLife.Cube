# 安全防御

魔方内置的 WAF 化安全防御体系：在[访问规则](PERM-访问规则.md)基础上，增加内置威胁检测、持久化自动封禁与安全事件审计。默认以观察模式运行，评估误报后一键切换拦截模式。

---

## 设计原则

- **零新表**：基于访问规则表扩展（新增 `ExpireTime` 列），封禁以"自动封禁规则"形式持久化；安全事件写入系统审计日志表
- **两代共享**：核心代码位于 `NewLife.CubeNC/Services/`，以文件链接被第三代（`NewLife.Cube`）与第二代（`NewLife.CubeNC`）同时引用
- **观察优先**：默认观察模式（`SecurityMode=1`），检测命中仅记录安全事件不拦截
- **误报出口**：访问规则的放行（Pass）规则可豁免内置检测，富文本等业务场景按需配置

## 核心组件

| 组件 | 位置 | 说明 |
|------|------|------|
| `ThreatDetector` | `NewLife.CubeNC/Services/` | 内置威胁检测引擎（特征库 + 匹配） |
| `BlockService` | `NewLife.CubeNC/Services/` | 封禁服务：内存快照、阶梯时长、写入与解封、过期清理 |
| `SecurityEventService` | `NewLife.CubeNC/Services/` | 安全事件写入（去重）与封禁告警（节流） |
| `AccessService` | `NewLife.CubeNC/Services/` | 决策编排：封禁快照 → 规则匹配 → 威胁检测 |
| `MiddlewareHelper.ReadRequestBodyAsync` | `WebMiddleware/` | 中间件读取请求体（仅文本类内容，超限不读）用于检测 |

## 请求处理流

```text
请求 → ① IP规范化（可信代理链解析）
     → ② 封禁快照检查（内存，命中即拦截）
     → ③ 表规则匹配（Pass豁免 / Block拦截 / Limit限流）
     → ④ 内置威胁检测（URL + Query + Body + UserAgent）
     → ⑤ 处置：观察=记录事件；拦截=拦截+累计（连续触发自动封禁）
响应 → ⑥ 响应码追踪（404 等超阈值 → 自动封禁 + 事件 + 告警）
```

### ① IP 规范化

`WebHelper2.GetUserHost` 统一出口，防止转发头伪造：

- 配置 `TrustedProxies` 后，仅当直连来源在可信列表内才采信转发头，否则直接使用直连地址
- 转发头链（X-Forwarded-For）从右向左跳过可信代理，取第一个不可信地址
- 未配置时兼容旧行为（信任转发头取链首），并折叠多值为单一 IP
- 可信列表支持精确 IP、`*` 通配与 IPv4 CIDR 网段（如 `10.0.0.0/8`）
- `X-Remote-Ip` 单值内部约定头保持最高优先级

### ② 封禁快照

自动封禁以"访问规则"持久化（名称前缀"自动封禁"），`BlockService` 每 30 秒刷新内存快照：

- **重启不丢失**：封禁写入数据库，重启后立即恢复
- **多实例**：各实例独立快照，最迟 30 秒跨实例生效；封禁/解封在本实例立即刷新
- **自动清理**：过期的封禁记录每小时清理一次，避免表膨胀

### ③ 规则匹配

静态规则匹配逻辑见[访问规则](PERM-访问规则.md)。要点：

- 封禁快照检查先于一切规则
- 自动封禁规则不参与常规规则遍历（仅通过快照生效）
- 命中放行（Pass）规则时豁免后续规则与威胁检测
- 限流（Limit）规则未超限时不再直接放行，而是继续评估后续规则与威胁检测

### ④ 内置威胁检测

检测位置：URL（解码后，含双重解码检测）、查询字符串、请求体（表单/JSON，≤64KB）、User-Agent。

| 类别 | 内容 | 等级 |
|------|------|------|
| 扫描器 | sqlmap、nikto、nmap、masscan、fscan、nuclei、gobuster 等 29 种工具指纹 | 2 |
| SQL注入 | union select、or 1=1、sleep()、information_schema、into outfile 等 | 2 |
| XSS | script 标签、javascript:、事件属性、document.cookie | 2 |
| 路径遍历 | 多级 ../、编码变体、/etc/passwd 等敏感文件（2）；单级 ../（1） | 2/1 |
| 命令注入 | 分隔符接命令、/bin/sh（2）；子shell（1） | 2/1 |
| 文件包含 | php://、file://、data:// 等协议封装 | 2 |
| Log4j | ${jndi: 及大小写绕过变体 | 2 |
| XXE / SSRF | <!ENTITY、云元数据地址 | 2 |
| 反序列化 | Java 序列化头 rO0AB（2）；PHP 序列化（1） | 2/1 |
| 蜜罐路径 | .env、.git、wp-*、phpmyadmin、actuator、druid 等 34 条敏感路径 | 2 |
| 危险后缀 | .php/.jsp/.asp 等脚本后缀（魔方为纯.NET体系） | 2 |
| 协议异常 | 空字节（2）；双重编码、超长URL、控制字符（1） | 2/1 |

**等级说明**：2=拦截级（拦截模式下拦截）；1=可疑级（仅记录安全事件）。

### ⑤ 处置模式

| 模式 | SecurityMode | 行为 |
|------|-------------|------|
| 关闭 | 0 | 不执行内置检测（表规则不受影响） |
| 观察（默认） | 1 | 命中仅记录安全事件，请求放行 |
| 拦截 | 2 | 2 级命中拦截（403），同一 IP 300 秒内累计 3 次触发自动封禁 |

### ⑥ 自动封禁与阶梯时长

- **触发来源**：连续威胁命中、响应码超阈值（如 404 扫描检测规则）
- **阶梯时长**：按该 IP 近 7 天封禁次数递增：60秒 → 5分钟 → 30分钟 → 2小时 → 24小时
- **持久化**：写入访问规则表（`ExpireTime` 为解封时间），重启不丢失
- **解封**：后台访问规则列表点击"解封时间"列即可解除（见下文）
- **告警**：站内信通知管理员，每小时最多一条

## 安全事件审计

所有检测命中与封禁动作写入系统审计日志：

- **类别**：`安全防御`；**动作**：威胁类别（如 SQL注入/扫描器/自动封禁/扫描探测）
- **成功状态**：已拦截=true / 观察记录=false
- **详情**：命中特征、位置、片段、URL、User-Agent
- **去重**：同 IP 同动作 5 分钟窗口内只记录一次，防止扫描期间日志爆炸
- **查看**：系统管理 → 日志，按类别"安全防御"筛选

## 配置项

| 配置 | 默认 | 说明 |
|------|------|------|
| `SecurityMode` | 1 | 0=关闭 / 1=观察 / 2=拦截 |
| `BlockDurations` | 空 | 自动封禁时长档位（逗号分隔秒数），空值用默认 60,300,1800,7200,86400 |
| `TrustedProxies` | 空 | 可信代理列表（逗号分隔，支持通配与 IPv4 CIDR）；空值兼容旧行为 |

## 运营流程（推荐）

1. **观察期**：保持默认观察模式运行 3~7 天，定期查看"系统管理 → 日志"中类别为"安全防御"的事件
2. **误报评估**：对正常业务被记录的特征（如富文本提交含 `<script>`），配置放行规则：
   ```
   Name:       富文本豁免
   ActionKind: Pass
   Url:        /Admin/Page/Edit
   ```
3. **切换拦截**：确认误报可控后，将 `SecurityMode` 调整为 2
4. **日常运营**：关注封禁告警站内信；误封时在访问规则列表解除

## 管理操作

- **查看封禁**：系统管理 → 访问规则，名称含"自动封禁"的行即自动封禁记录
- **手动解封**：点击自动封禁行的"解封时间"列（显示为解封链接）
  - 第二代（MVC）：带确认弹窗的链接
  - 第三代（API/React）：点击执行后返回列表
- **调整策略**：修改配置项即时生效，无需重启

## 已知行为与注意事项

- 富文本/备注类内容包含 HTML 特征（如 `<script>`）会被记录（拦截模式下会被拦截），建议为对应页面配置放行规则
- 响应码检测触发的封禁时长采用阶梯档位，不再等于规则的 `LimitCycle`
- 单级 `../` 为可疑级（仅记录），多级 `../../` 为拦截级
- 文件上传（multipart）请求体不参与载荷检测，上传安全由附件模块的校验规则负责
- 第三代（API/React）列表的"解封时间"列对非自动封禁行也显示链接，点击后提示"不是自动封禁规则"，无副作用
