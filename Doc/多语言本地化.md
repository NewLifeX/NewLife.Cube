## 3. 工作方式

1. `NewLife.Core` 包内的源生成器读取 `Locales/*.yml`，编译期生成压缩语言表与自动注册代码。
2. `NewLife.Cube` 与 `NewLife.CubeNC` 共用 `NewLife.Cube/Locales`（NC 通过 `AdditionalFiles` 挂载），词表只有一份事实源。
3. 请求进入 `UseCube` 后由 `UseCubeLocalization()` 写入 `CurrentUICulture`；未配置固定语言时 `Localization.Culture` 保持 `null`，避免进程级覆盖；`Localization.LogCulture` 固定为站点默认语言或启动时的系统语言，避免服务端日志随请求语言混杂。SPA 不保存用户语言偏好，请求语言来自 `Accept-Language`。服务端日志模板统一用 `L.TLog("English template", args)`，按 LogCulture 翻译（缺失翻译回退英文源文），中文（简/繁）已就绪，其余语言按需增量翻译。
4. 消息以英文为源文：`L.T("Operation succeeded")` / `L.T("{0} succeeded!", action)`；缺少译文自动回退英文。
5. `XException` 构造器内部已调用 `Localization.Translate`，直接写英文即可；`ApiException`、BCL 异常与 `WriteLog` 审计日志需显式使用 `L.T`。
6. 服务端日志使用英文模板并通过 `XTrace`/`Log` 输出，Core 的 `Logger.Format` 会按 `LogCulture` 自动翻译；审计日志在写入时用 `L.T` 固化当前请求语言。
7. 消息词表 1071 条（后端界面文案、AI 提示词与日志模板共用一套）：全部以**英文为源文**。视图与界面文案同样以英文源文为 key，中文译文落在 `zh-Hans.yml`。元数据词条（实体/字段/控制器/程序集标题）按语言增量补齐：实体元数据以**中文源文**为 key（`"编号": "ID"`），控制器按现有取值作 key（以中文为主，API 版部分动作名保持英文）、设置项以英文源文为 key；简体中文、繁體中文、德语、法语的元数据键已全量覆盖（2026-10-25 起 `check-locales.ps1 -FullCoverageCultures "zh-Hant,de,fr"` 强制），其余语言按 `Locales/metadata-coverage-baseline.json` 棘轮增量补齐（只拦新增缺口），缺失时回退源文。`check-locales.ps1` 校验键集合与占位符，并扫描 `.cs`、`.cshtml` 与 `.csproj` 做孤儿键检测（含 `NewLife.Cube.csproj` 链接的 CubeNC 共享源码）；`-Strict` 额外要求「译文不得等于源文」，正确同形词（如德语 `Status`、葡语/挪威语 `Agent`）在 `Locales/identical.allow.json` 按语言登记放行。`check-english-messages.ps1` 保证 API 可见调用点不出现中文；`check-missing-keys.ps1` 保证每个英文源文键在 `zh-Hans.yml` 都有中文译文。中文源文的元数据（实体/字段/菜单/控制器/作业）其英文译文统一登记在 `Locales/en.yml`：`check-locales.ps1` 要求其中每个中文键都给出非中文译文并校验占位符，同时输出「英文元数据覆盖率」。

8. 实体/控制器/枚举元数据与消息共用同一份 `Locales/<culture>.yml`：key 是精确源文。**实体模型（`Cube.xml`）与生成实体保持中文**——描述与文件名均为中文，`xcode` 重新生成不会改动命名；译文以中文为 key 写入各语言词表（如 `"用户链接": "User link"`）。**区域、控制器、作业的 `[DisplayName]`/`[Description]` 以取值本身为词表 key**：只有数据类控制器（`EntityController`/`EntityTreeController`/`ReadOnlyEntityController`，会被 xcodetool 重新生成覆盖）**必须**用开发者语言（中文）；其余控制器、作业、区域中英文皆可，但**同一个类的 DisplayName 与 Description 必须同语言**，不得一半中文一半英文。译文按该 key 写入词表，**不做中文/英文的方向性批量搬移**——确需改名时单独提交并同步词表；`check-displayname-churn.ps1` 检查提交区间内是否出现 A→B→A 的往返，防止再次来回改。只有后端运行时消息（异常/日志/审计/API 提示）用英文源文。两类 key 在同一份词表中共存。`DataField.Fill` 识别「显示名. 说明」两段式并保留整段源文，`Localize()` 翻译后按请求语言拆分；元数据 key 允许只在部分语言出现，缺失回退源文。`Locales/metadata-keys.json` 登记元数据 key，`check-locales.ps1 -MetadataKeys` 放行部分语言缺失；`collect-metadata-keys.ps1` 除 `[DisplayName]`/`[Description]` 特性外，还会收集 `DisplayName`/`Header`/`HeaderTitle` 属性赋值与 `.csproj` 的 `AssemblyTitle`/`Description`。

8.1 视图文案：`.cshtml` 与代码里的界面标签**以英文源文为 key**（`@L.T("Name")`、`placeholder="@L.T("Search department")"`、`'@L.T("Please enter the user name")'`），中文译文写在 `Locales/zh-Hans.yml`，其余 30 种语言已全量补齐（2026-10-22），新增键按需增量补译，缺失回退英文源文。不要再用中文原文作 key——中文 key 只保留给实体/枚举/菜单等「源文即数据」的元数据。带数值/名称的句子用含占位符的整句键（`L.T("{0}, {1} cores, {2}")`），不要把标点或量词切成独立键（原 `核心，`、`个`、`，开机` 一类碎片键已全部改为整句）。视图 key 登记到 `Locales/metadata-extra.json`，生成 `metadata-keys.json` 时自动合并，从而允许部分语言缺失并免于“多余键”报错。`check-missing-keys.ps1` 保证每个英文源文键在 `zh-Hans.yml` 都有中文译文（含中文的元数据键豁免，AI 工具提示词等经 `Locales/missing-keys.allow.json` 放行）。表单分组名（如 `默认`）在 `_Form_Body`/`ObjectForm` 渲染时翻译；实体枚举值（如 `男`/`女`/`未知`）与数据范围值（`全部`/`本部门`）仍以中文为 key 补译文。
9. 程序集元数据按 Core 规范以**英文源文**入表：`AssemblyTitle`/`Description` 用英文并作为词表键，`PackageDescription` 承接中英双语描述；界面展示与执行上下文中的标题经 `L.T` 翻译，原始特性值保持不变。XCode 内置实体的中英文元数据由其自带 `Locales` 随包分发，因此**升级 `NewLife.XCode` 包后列表页字段名才会翻译**；`12.2.2026.1021-beta0423` 起已随包分发，无需再本地替换 `Bin` 下的 `XCode.dll`。
8. 设置页字段在每次请求时按当前语言翻译：字段元数据带静态缓存，缓存中保存源文；`DataField.Localize()` 在克隆副本上先翻译、再按首个句末标点拆分显示名与右侧描述（中文句号、英文半角句点、印地语 danda 均支持），分类与页面标题同样走词表。

## 4. 新增一条消息

```csharp
// 源文（英文，占位符与译文必须一致）
throw new XException("The requested data [{0}] does not exist.", id);

// BCL 异常需要显式翻译
throw new InvalidOperationException(L.T("Only available in development mode."));
```

设置页字段描述必须写在源工程（Core/星尘/XCode/魔方）的特性上，以英文为源文，并在该工程自己的 `Locales/*.yml` 补译文；魔方本地词表只保留魔方自身的设置项与视图文案。跨包翻译在运行时自动合并，无需在魔方重复登记。

实体/枚举/控制器元数据与消息共用同一份词表，key 用**精确源文**：中文模型的 key 就是中文（如 `"用户": "User"`）。元数据 key 登记到 `Locales/metadata-keys.json`，允许只在部分语言出现，缺失回退源文；`collect-metadata-keys.ps1` 可从 `Model.xml` 或生成代码重新生成清单。代码里以 `L.T` 使用的界面标签（图表系列名、日志动作等）登记在 `Locales/metadata-extra.json`，生成清单时自动合并，同样允许按语言增量翻译。

同步在全部 31 份 `Locales/*.yml` 中补键（元数据键可只补需要的语言），然后运行：

```powershell
# 重新生成元数据键清单（模型文件 + [DisplayName]/[Description] 特性 + DisplayName/Header 赋值 + csproj 程序集元数据）
pwsh -Command "& ./collect-metadata-keys.ps1 -Model NewLife.Cube/Entity/Cube.xml -SourceDir NewLife.Cube,NewLife.CubeNC -Output NewLife.Cube/Locales/metadata-keys.json"

# 词表键集合、占位符与格式说明符一致（默认扫描 NewLife.Cube 与 NewLife.CubeNC，避免共享源码被误判为孤儿键）
# 元数据键允许部分语言缺失，并免于孤儿键检查
pwsh -File check-locales.ps1 -LocaleDir NewLife.Cube/Locales -Baseline zh-Hans.yml -MetadataKeys NewLife.Cube/Locales/metadata-keys.json -MetadataSourceDir NewLife.Cube/Entity

# 严格模式：译文不得回退英文（同形词登记在 Locales/identical.allow.json）
pwsh -File check-locales.ps1 -LocaleDir NewLife.Cube/Locales -Baseline zh-Hans.yml -Strict -MetadataKeys NewLife.Cube/Locales/metadata-keys.json

# 分区覆盖（CI 口径）：译文较全的语言强制 100%，其余语言按覆盖基线只拦新增缺口
pwsh -File check-locales.ps1 -LocaleDir NewLife.Cube/Locales -Baseline zh-Hans.yml -Strict `
     -MetadataKeys NewLife.Cube/Locales/metadata-keys.json -MetadataSourceDir NewLife.Cube/Entity `
     -FullCoverageCultures "zh-Hant,de,fr" -CoverageBaseline NewLife.Cube/Locales/metadata-coverage-baseline.json

# 新增元数据键后刷新覆盖基线（人工确认后执行，只允许减少不允许新增）
pwsh -File check-locales.ps1 -LocaleDir NewLife.Cube/Locales -MetadataKeys NewLife.Cube/Locales/metadata-keys.json `
     -FullCoverageCultures "zh-Hant,de,fr" -CoverageBaseline NewLife.Cube/Locales/metadata-coverage-baseline.json -UpdateCoverageBaseline

# 全量覆盖：元数据键必须每种语言都有译文，缺一即失败（不分区时使用）
pwsh -File check-locales.ps1 -LocaleDir NewLife.Cube/Locales -Baseline zh-Hans.yml -Strict -MetadataKeys NewLife.Cube/Locales/metadata-keys.json -RequireFullCoverage

# 运行时消息（异常/日志/审计/提示）不得含中文，必须写英文源文
pwsh -File check-english-messages.ps1
```

CI 的 `localization` job 会执行上述两个脚本，分别校验词表一致性与运行时消息英文 源文；词表目录存在 `metadata-keys.json` 时自动传入 `-MetadataKeys` 与 `-MetadataSourceDir`，存在 `metadata-coverage-baseline.json` 时再传入 `-FullCoverageCultures "zh-Hant,de,fr"` 与 `-CoverageBaseline`（强制三种语言 100%、其余语言只拦新增缺口），否则退回 `-RequireFullCoverage`。

## 4.1 元数据落库约定（以菜单为例）

菜单显示名落库的是**开发者语言快照**：扫描只在显示名为空时写入，已有值不覆盖；译文一律在渲染期按当前语言产生。

| 落库值 | 语义 |
|---|---|
| `用户`、`审计日志` 一类开发者语言文本 | 自动菜单的源文快照。扫描只在**为空**时按「控制器 `[DisplayName]` → 实体表描述 → 类名短名」填充，已有值不动 |
| 管理员直接编辑的名称 | 保留不覆盖，但**只在源文语言界面**生效；其它语言按词表翻译 |
| 空 | 尚未扫描到（新建控制器、历史遗留行），读取时即时计算 |

### 渲染规则：先判语言，再决定用库值还是查表

「开发者语言」按**源文的书写文字**判定：含汉字视为中文源，只有 `zh`/`zh-CN`/`zh-SG`/`zh-Hans` 算一致（`zh-Hant` 走词表拿繁体译文）；其余视为英文源，`en` 与不变文化算一致。

| 场景 | 显示 |
|---|---|
| 当前语言与源文一致，且库值非空 | **直接用库值**（管理员改过的名字在这里生效） |
| 当前语言与源文不同 | 依次查 `menu:<FullName>` → `entity:<实体全名>` → 普通词条 `L.T(源文)` → 源文 |
| 库值为空 | 同上，即时计算，界面不会出现空白 |
| `FullName` 为空（手工菜单）或类型已不存在 | 库值命中词条则翻译，否则原样显示 |

- 代码改了 `[DisplayName]` 后，**源文语言界面不会自动跟进**，用菜单管理页工具栏的「刷新菜单」按需重置；其它语言因为走词表，**永远是最新的**。
- 「刷新菜单」按钮由 `[ToolbarButton]` 声明：MVC 标准主题与 SPA（`meta.toolbar`）自动渲染，LayuiAdmin 皮肤走自家 layui 模板未接入该机制。按钮文案在 `ToolbarBuilder.Build` 里统一走 `CubeLocalization.T(DisplayName)`（缺词条回退源文），与 MVC 视图的 `@L.T(item.DisplayName)` 同口径。
- 词表键两个前缀分工：`menu:` 用于控制器/区域/区域命名空间全名（Cube 维护），`entity:` 用于实体类型全名（XCode 维护，Cube 冗余一份，因为魔方运行时只有一套合并词表）。业务代码禁止手拼词表键，统一走 `MenuHelper.GetDisplayName(menu)` 与 `MenuHelper.GetEntityDisplayName(type)`。
- `check-locales.ps1` 把 `menu:`、`entity:`、`field:` 前缀视为**运行期组合键**：免于孤儿键检测，非强制覆盖语言允许缺失。

**词条维护**：新增控制器/实体后，在 `NewLife.Cube/Locales/*.yml` 追加 `"menu:<类型全名>"` 或 `"entity:<实体全名>"`；`zh-Hans`、`en`、`zh-Hant`、`de`、`fr` 五种语言由 `check-locales.ps1 -FullCoverageCultures` 强制齐全。菜单管理页列出**显示名**（最终效果）与**落库值**两列，便于排查。

同一套约定适用于**权限子项、控制器标题、区域名称**等由代码派生的元数据：写库只写源文，译文只在渲染期产生。审计日志、站内信正文等**业务数据**不在此列——它们记录的是当时的语境，允许在写入时固化请求语言。

## 5. 语言选择

### 5.1 优先级

| 顺序 | 来源 | 示例 | 说明 |
|------|------|------|------|
| 1 | 查询参数 | `?lang=zh-TW` | 显式链接，单次生效 |
| 2 | 请求头 | `Accept-Language: ja-JP` | SPA 每次请求携带当前选择 |
| 3 | Cookie | `.AspNet.Culture=zh-CN` | 仅 MVC/整页跳转；SPA 不依赖 |
| 4 | 租户默认 | `TenantSetting.DefaultLanguage`（规划） | 多租户站点 |
| 5 | 站点默认 | `NewLife.Setting.Language` | 兜底 |
| 6 | 英文源文 | `en-US` | 最终回退 |

`NewLife.Setting.Language` 只作站点默认，不强制覆盖用户选择。需要固定单语言的部署（内网、合规场景）可开启 `LanguageLocked`（规划中的站点/租户配置），此时忽略前两项并使用对应的默认语言。

### 5.2 存储

第三代 SPA 的语言选择**只存在浏览器**：

| 层 | 用途 |
|---|---|
| `localStorage['cube-language']` | 当前浏览器的界面语言；换浏览器/电脑允许不同 |
| `Accept-Language` 请求头 | 每次 API 请求携带当前选择，服务端据此返回本地化消息 |
| Cookie `.AspNet.Culture` | 仅 MVC/整页跳转使用；SPA 不依赖 |

不写用户 `Parameter`：跨设备一致性价值低，且引入登录态依赖、数据库写入与缓存失效。服务端主动消息（定时/批量邮件、站内信）无法按用户偏好，只能使用请求语言或租户/站点默认。

### 5.3 切换语言（无接口）

前端切换时：

1. 更新 `vue-i18n`/`react-i18next` 的 locale。
2. 设置 `<html lang>` 与 `dir`。
3. 写入 `localStorage['cube-language']`。
4. 更新 HTTP 客户端默认 `Accept-Language`，后续请求自动携带。

不需要调用后端接口。若页面已展示服务端下发的文本（如 `loginTip`），可重新请求 `/Cube/Site` 获取新语言内容。

恢复自动：删除 `localStorage['cube-language']`，使用 `navigator.language`，并同步更新请求头。

前端从 `/Cube/Site` 的 `language` 读取可选语言与锁定状态（Site 为可选接口）：

| 字段 | 用途 |
|---|---|
| `current` | 服务端按 §5.1 解析的本次语言；启动兜底，`localStorage` 有值时以本地为准 |
| `default` | 站点/租户默认语言；浏览器语言不受支持时的兜底 |
| `locked` | `true` 时隐藏语言切换器 |
| `options` | 下拉选项（Core `LanguageInfo`）；`nativeName` 为母语名称，`dir` 由语言代码推导 |

前端流程：启动读 `localStorage` → 用 `options` 渲染下拉 → 切换按 §5.3 更新本地与请求头 → 恢复自动删除本地选择并使用浏览器语言。

### 5.4 站点默认与基本设置

语言设置已统一到 NewLife.Core 的 **基本设置 → 界面语言**（`NewLife.Setting.Language`），魔方不再单独维护语言配置。留空时跟随浏览器/系统；填写受支持的语言代码（如 `zh-CN`、`en-US`、`ja`）时作为站点默认语言；填写不受支持的语言（如 `sw-KE`）时忽略。

服务端日志语言仍由 `Localization.LogCulture` 固定（默认取站点默认或启动时系统语言），不随请求语言变化，避免同一日志文件混杂。

> 魔方直接读取 `NewLife.Setting.Language`（要求 NewLife.Core ≥ 12.0.2026.1020）。星尘、XCode 的设置描述已改为英文源文，各自包内 `Locales/*.yml` 提供中文译文，升级对应 NuGet 包后生效。

基本设置页的语言字段直接绑定 Core 的 `Localization.GetLanguageOptions()`（含运行时注册语言，名称随界面语言本地化）：选项格式为「当前语言名称 (自称)」，同属一种语言时只显示自称（如中文界面的 `西班牙语 (Español)`、`德语 (Deutsch)`、`繁體中文`，英文界面的 `Chinese (Simplified) (简体中文)`），空选项表示自动。列表中的旧版别名（`in`/`iw`/`no`/`mo`）已由 Core 归一化到区域语言，不会重复出现；`CubeLocalization.SupportedCultures` 与 `NormalizeCulture` 也直接委托 Core，魔方不再维护第二份语言清单。

语言名称会先归一化到受支持的区域语言再匹配：裸语言码（`?lang=en`、`Accept-Language: fr`）与未列入支持列表的区域（`de-AT`、`pt-PT`）分别映射到 `en-US`、`fr-FR`、`de-DE`、`pt-BR`，旧版别名（`in`/`iw`/`no`/`mo`）映射到 `id-ID`/`he-IL`/`nb-NO`/`ro-RO`；只有完全不支持的语言（如 `sw-KE`）才回退默认语言。设置页导航在切换时自动携带当前 `lang` 参数。

设置页表单的「保存/取消」按钮与页面底部执行耗时（`RunTimeMiddleware.DbRunTimeFormat`）同样走词表：英文源文为 `Save`/`Cancel` 与 `Queries {0}, executes {1}, elapsed {2:n0} ms`，中文环境由词表提供译文。

## 6. 前端（Vue / React）

前后端分离前端统一提供 11 种语言：`zh-CN`、`zh-TW`、`en-US`、`es-ES`、`de-DE`、`ja-JP`、`fr-FR`、`pt-BR`、`ru-RU`、`ko-KR`、`ar-SA`。后端支持 32 个区域，`/Cube/Site` 的 `language.options` 返回后端全部受支持语言（复用 Core `LanguageInfo`）；前端可用自身词表与 options 取交集，缺少词表的语言会回退英文。

- Vue：语言文件在 `NewLife.Cube.Vue/web/core/i18n/locales/*.ts`；`setLanguage()` 写入 `localStorage['cube-language']`，同步 `<html lang>`、`dir`（阿拉伯语 RTL）与 Element Plus locale，并更新 HTTP 客户端默认 `Accept-Language`；不调用后端接口。
- Vue 登录页：`LoginPage.vue` 顶部提供语言切换（选项可来自 `/Cube/Site` 的 `language.options`，未接入 Site 时用本地语言清单），切换后登录页文案、后端错误消息与验证码提示使用同一语言。
- Vue 启动：SPA 外壳优先读取 `localStorage['cube-language']`；接入 `/Cube/Site` 时用 `name`/`logo`/`copyright` 覆盖默认标题与 Logo，并设置 `document.title`；`language.current` 只作校验/兜底，不覆盖本地选择。
- React：语言文件在 `NewLife.Cube.React/web/src/i18n/*.ts`，业务文案词典在该目录 `app/*.ts`（548 条，以中文原文为键，缺译文回退中文）；启动按 `localStorage['cube-language']` → 浏览器语言选择，切换时同步 `<html lang>`、`dir` 并更新请求头。
- 请求：Vue 与 React 的 API 客户端统一携带 `Accept-Language`，后端按同一条链路返回本地化消息。

## 7. 边界

- MVC 版本覆盖共享外壳（导航栏、列表工具栏、分页、行操作、表单按钮）与运行时消息；实体元数据按源文 + 请求语言翻译，菜单名已统一在渲染期翻译，各业务页面的静态文案仍按页面分批迁移。
- 数据库管理页（`Admin/Db` 的列表、实体、数据表与模型差异视图）是视图文案英文源文的先行实现，与其余视图走同一条规则：控制器与视图中的 `L.T("...")` 直接写英文，`Locales/en.yml` 不登记这些键，31 份译文词表按英文 key 补齐；覆盖表头、操作链接、版本提示与 XML 片段说明；标题中的表名、差异数量等使用带 `{0}` 的整句键，避免跨语言语序问题。
- 菜单名称（`Menu.DisplayName`）属于可编辑的持久化数据：自动项保存**开发者语言快照**（扫描只在为空时填充），菜单树/面包屑/快捷链接在**渲染期**先判语言：与源文一致用库值，否则按 `menu:`/`entity:` 词条翻译；代码改名后用管理页「刷新菜单」显式重置（详见 §4.1）。
- 实体与业务控制器的 `[DisplayName]` 保持源文，作为词表 key；生成器为实体类与控制器显式写入 `[DisplayName(Table.DisplayName)]`，表头/标题/菜单在消费端翻译，不在运行时改写特性。
- 英文为源文与对外口径，简体中文与繁體中文同批维护；其他语言缺失词条时自动回退英文。
- 服务端日志与配置注释可通过 `Localization.LogCulture` 固定语言，避免随请求变化；`Localization.Culture` 保持 `null`，由请求中间件驱动界面与异常语言。
- 登录页、注册/激活/找回密码页允许选择语言；对外网站页面（服务端渲染）把语言放入 URL（`/en/...` 或子域）并输出 `hreflang`，Cookie 只用于记忆选择，`localStorage` 不能作为唯一来源。
- 多租户下，租户可设置默认语言与允许语言白名单；浏览器选择的语言不在白名单时回退租户默认，且不覆盖本地选择。
- 服务端主动消息（站内信、告警、批量邮件）使用请求语言或租户/站点默认；不保存用户语言偏好，因此不保证与用户浏览器选择一致。
- 新增语言只需追加 `Locales/{code}.yml` 并在 `readme-languages.json` 登记；不要修改已有键。

## 8. 界面文案术语表

固定译法，新增界面文案优先选用，避免同一中文在不同页面译成不同英文。

| 中文 | 英文源文 | 说明 |
|---|---|---|
| 保存 / 取消 | `Save` / `Cancel` | 表单按钮固定用词，不使用 `Submit` |
| 添加 / 编辑 / 删除 | `Add` / `Edit` / `Delete` | 列表行操作 |
| 删除选中 / 删除全部 | `Delete selected` / `Delete all` | 批量操作 |
| 查询 / 刷新 / 重置 | `Query` / `Refresh` / `Reset` | 工具栏 |
| 名称 / 显示名 / 编号 | `Name` / `Display name` / `ID` | 实体字段 |
| 备注 / 描述 | `Remark` / `Description` | 长文本字段 |
| 状态 / 类型 / 分类 | `Status` / `Type` / `Category` | 属性列 |
| 登录 / 注册 / 退出 | `Sign in` / `Sign up` / `Sign out` | 认证动作，不使用 `Login` 作按钮 |
| 注销账号 | `Close account` | 个人信息保护法口径 |
| 用户名 / 密码 | `User name` / `Password` | 登录表单 |
| 原密码 / 新密码 / 确认密码 | `Current password` / `New password` / `Confirm password` | 改密表单 |
| 上传 / 下载 / 导出 / 导入 | `Upload` / `Download` / `Export` / `Import` | 文件动作 |
| 启动于 / 时间 | `Started at` / `Time` | 服务器信息页 |
| 升序 / 降序 | `Asc` / `Desc` | 表头排序图标列 |
| 未绑定 / 已绑定 | `Not bound` / `Bound` | 第三方绑定状态 |
| 在线 / 离线 | `Online` / `Offline` | 用户状态 |
| 只读 / 禁用 / 启用 | `Read-only` / `Disabled` / `Enabled` | 状态标识 |

> 界面 key 也要写完整句子或带占位符的模板（`{0}, {1} cores, {2}`），不要拆成标点/量词碎片；英文文案内避免使用撇号，否则会截断 `alert('@L.T("...")')` 里的 JS 字符串。
