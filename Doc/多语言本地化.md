# 魔方多语言本地化

> 基线：NewLife.Core 12 编译期词表｜运行时 31 种译文语言 + 英文源文（32 个区域，与 Core 词表集对齐）｜英文为源文与兜底

## 1. 能力范围

| 面 | 状态 | 说明 |

## 3. 工作方式

1. `NewLife.Core` 包内的源生成器读取 `Locales/*.yml`，编译期生成压缩语言表与自动注册代码。
2. `NewLife.Cube` 与 `NewLife.CubeNC` 共用 `NewLife.Cube/Locales`（NC 通过 `AdditionalFiles` 挂载），词表只有一份事实源。
3. 请求进入 `UseCube` 后由 `UseCubeLocalization()` 写入 `CurrentUICulture`；未配置固定语言时 `Localization.Culture` 保持 `null`，避免进程级覆盖；`Localization.LogCulture` 固定为 `NewLife.Setting.Language` 或启动时的系统语言，避免服务端日志随请求语言混杂。服务端日志模板统一用 `L.TLog("English template", args)`，按 LogCulture 翻译（缺失翻译回退英文源文），中文（简/繁）已就绪，其余语言按需增量翻译。
4. 消息以英文为源文：`L.T("Operation succeeded")` / `L.T("{0} succeeded!", action)`；缺少译文自动回退英文。
5. `XException` 构造器内部已调用 `Localization.Translate`，直接写英文即可；`ApiException`、BCL 异常与 `WriteLog` 审计日志需显式使用 `L.T`。
6. 服务端日志使用英文模板并通过 `XTrace`/`Log` 输出，Core 的 `Logger.Format` 会按 `LogCulture` 自动翻译；审计日志在写入时用 `L.T` 固化当前请求语言。
7. 当前词表共 602 条：公共/管理消息、日志模板与设置页条目共用一套词表，全部以**英文为源文**（设置描述改由各包自己的 `Locales/*.yml` 提供后，魔方本地只保留魔方自身的设置项与视图文案）；简体/繁体中文提供译文，其他语言暂以英文兜底。`check-locales.ps1` 校验键集合与占位符、并扫描 `.cs` 与 `.cshtml` 做孤儿键检测（含 `NewLife.Cube.csproj` 链接的 CubeNC 共享源码），`check-english-messages.ps1` 保证 API 可见调用点不出现中文（CubeNC 中已改 `L.TLog` 的日志按英文校验，未迁移的中文日志暂时豁免）。
8. 设置页字段在每次请求时按当前语言翻译：字段元数据带静态缓存，缓存中保存源文；`DataField.Localize()` 在克隆副本上先翻译、再按首个句末标点拆分显示名与右侧描述（中文句号、英文半角句点、印地语 danda 均支持），分类与页面标题同样走词表。

## 4. 新增一条消息

```csharp
// 源文（英文，占位符与译文必须一致）
throw new XException("The requested data [{0}] does not exist.", id);

// BCL 异常需要显式翻译
throw new InvalidOperationException(L.T("Only available in development mode."));
```

设置页字段描述必须写在源工程（Core/星尘/XCode/魔方）的特性上，以英文为源文，并在该工程自己的 `Locales/*.yml` 补译文；魔方本地词表只保留魔方自身的设置项与视图文案。跨包翻译在运行时自动合并，无需在魔方重复登记。

同步在全部 31 份 `Locales/*.yml` 中补键，然后运行：

```powershell
# 词表键集合、占位符与格式说明符一致（默认扫描 NewLife.Cube 与 NewLife.CubeNC，避免共享源码被误判为孤儿键）
pwsh -File check-locales.ps1 -LocaleDir NewLife.Cube/Locales -Baseline zh-Hans.yml

# 运行时消息（异常/日志/审计/提示）不得含中文，必须写英文源文
pwsh -File check-english-messages.ps1
```

CI 的 `localization` job 会执行上述两个脚本，分别校验词表一致性与运行时消息英文源文。

## 5. 语言选择

| 来源 | 示例 | 优先级 |
|------|------|--------|
| 查询参数 | `?lang=zh-TW` | 最高 |
| Cookie | `.AspNet.Culture=zh-CN` | 次之 |
| 请求头 | `Accept-Language: ja-JP` | 再次 |
| 宿主配置 | `NewLife.Setting.Language` | 默认值（填写受支持语言时最高） |

语言设置已统一到 NewLife.Core 的 **基本设置 → 界面语言**（`NewLife.Setting.Language`），魔方不再单独维护语言配置。留空时跟随浏览器/系统；填写受支持的语言代码（如 `zh-CN`、`en-US`、`ja`）后转为强制模式：忽略查询串、Cookie 与 `Accept-Language`，界面语言与日志语言（`Localization.LogCulture`）同时固定为该语言。强制在请求管道中按当前配置判定，修改后立即生效，无需重启。填写不受支持的语言（如 `sw-KE`）时视为自动模式。

> 魔方直接读取 `NewLife.Setting.Language`（要求 NewLife.Core ≥ 12.0.2026.1020），并在请求管道中强制执行。星尘、XCode 的设置描述已改为英文源文，各自包内 `Locales/*.yml` 提供中文译文，升级对应 NuGet 包后生效。

基本设置页的语言字段直接绑定 Core 的 `Localization.GetLanguageOptions()`（含运行时注册语言，名称随界面语言本地化）：选项格式为「当前语言名称 (自称)」，同属一种语言时只显示自称（如中文界面的 `西班牙语 (Español)`、`德语 (Deutsch)`、`繁體中文`，英文界面的 `Chinese (Simplified) (简体中文)`），空选项表示自动。列表中的旧版别名（`in`/`iw`/`no`/`mo`）已由 Core 归一化到区域语言，不会重复出现；`CubeLocalization.SupportedCultures` 与 `NormalizeCulture` 也直接委托 Core，魔方不再维护第二份语言清单。

语言名称会先归一化到受支持的区域语言再匹配：裸语言码（`?lang=en`、`Accept-Language: fr`）与未列入支持列表的区域（`de-AT`、`pt-PT`）分别映射到 `en-US`、`fr-FR`、`de-DE`、`pt-BR`，旧版别名（`in`/`iw`/`no`/`mo`）映射到 `id-ID`/`he-IL`/`nb-NO`/`ro-RO`；只有完全不支持的语言（如 `sw-KE`）才回退默认语言。设置页导航在切换时自动携带当前 `lang` 参数。

设置页表单的「保存/取消」按钮与页面底部执行耗时（`RunTimeMiddleware.DbRunTimeFormat`）同样走词表：英文源文为 `Save`/`Cancel` 与 `Queries {0}, executes {1}, elapsed {2:n0} ms`，中文环境由词表提供译文。

## 6. 前端（Vue / React）

前后端分离前端统一提供 11 种语言：`zh-CN`、`zh-TW`、`en-US`、`es-ES`、`de-DE`、`ja-JP`、`fr-FR`、`pt-BR`、`ru-RU`、`ko-KR`、`ar-SA`。

- Vue：语言文件在 `NewLife.Cube.Vue/web/core/i18n/locales/*.ts`；`setLanguage()` 写入 `localStorage['cube-language']`，同步 `<html lang>` 与 Element Plus locale。
- React：语言文件在 `NewLife.Cube.React/web/src/i18n/*.ts`，业务文案词典在该目录 `app/*.ts`（548 条，以中文原文为键，缺译文回退中文）；启动时按 `localStorage['cube-language']` → 浏览器语言 → 英文选择，切换时同步 `<html lang>` 与 `dir`（阿拉伯语 RTL）。
- 请求：Vue 与 React 的 API 客户端统一携带 `Accept-Language`，后端按同一条链路返回本地化消息。

## 7. 边界

- MVC 版本不做视图级多语言；API 后端与 Vue/React 前端覆盖运行时消息。
- 菜单名称（`Menu.DisplayName`）属于可编辑的持久化数据，建菜单时按启动语言落库，不随请求语言切换；XCode 实体与业务控制器的 `DisplayName` 保持单语言源文。内置控制器 `[DisplayName]` 仅作为设置页标题/设置导航的翻译键，由消费端 `L.T` 翻译。
- 英文为源文与对外口径，简体中文与繁體中文同批维护；其他语言缺失词条时自动回退英文。
- 服务端日志与配置注释可通过 `Localization.LogCulture` 固定语言，避免随请求变化；`Localization.Culture` 保持 `null`，由请求中间件驱动界面与异常语言。
- 新增语言只需追加 `Locales/{code}.yml` 并在 `readme-languages.json` 登记；不要修改已有键。
