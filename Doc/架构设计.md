**多设备登录控制**：通过 `EnableMultiDeviceLogin` 配置（默认 true）。多设备模式下注销仅吊销当前设备令牌（通过 JWT jti 精确定位），不牵连其他设备。单设备模式下新登录自动踢掉旧设备，注销时吊销该账号全部令牌。`ManageProvider.Logout` 已集成该策略判断。管理员可通过 `UserOnlineController.Kick` 强制用户下线（吊销令牌+清除会话），或通过 `UserController.RevokeTokens` 按用户批量吊销。

### 3.6 OAUTH：统一认证（OAUTH-1 ~ OAUTH-5）

关联功能清单：OAUTH-1 OAuth 第三方登录 · OAUTH-2 SSO 单点登录 · OAUTH-3 OAuth 配置管理 · OAUTH-4 OAuth 日志管理 · OAUTH-5 用户链接管理

统一认证模块提供 OAuth 2.0 第三方登录和 SSO 单点登录能力：
- **OAuth 第三方登录**：对接微信/钉钉/GitHub/QQ/支付宝/微软/百度/淘宝/微博/企业微信等 10+ 平台
- **SSO 单点登录**：统一用户中心，支持 SSO 服务端与客户端模式
- **OAuth 配置管理**：第三方 OAuth 服务商的参数配置与启用/禁用
- **OAuth 日志管理**：OAuth 认证调用的回调日志记录与查看
- **用户链接管理**：用户第三方账号绑定关系管理

## 4. 关键设计决策

### 4.1 第二代 vs 第三代架构选择

| 决策 | 第二代 (CubeNC) | 第三代 (Cube) |
|------|----------------|---------------|
| 交付模式 | NuGet 包 `NewLife.Cube.Core` | NuGet 包 `NewLife.Cube` |
| 前端渲染 | 服务端 Razor 渲染 | 客户端渲染（JSON API） |
| 视图机制 | ThemeViewLocationExpander | CubeEmbeddedFileProvider |
| 适用场景 | 快速开发、内部系统 | 复杂前端、移动端对接 |
| 演进策略 | 存量维护，不新增功能 | 主力演进，持续迭代 |

### 4.2 文件链接策略

CubeNC 通过 `<Compile Include="..\NewLife.Cube\...">` 链接引用 Cube 项目中的服务层、实体模型、视图模型等公共代码。目标是单向（CubeNC → Cube）；**当前仍有反向链接**：API 项目通过 `<Compile Include="..\NewLife.CubeNC\...">` 引用 42 个核心服务、实体模型、作业、模块、Session 与中间件文件。两个包共同编译 196 个源文件（MVC 共 379 个编译项），反向链接尚未收敛。

链接的目录包括：
- `Services/` — 业务服务层
- `Entity/` — 实体模型
- `ViewModels/` — 视图模型
- `Common/` — 公共基类
- `Jobs/` — 定时作业
- `Extensions/` — 扩展方法
- `WebMiddleware/` — 中间件
- `AI/` — AI 服务

API 专属能力不下沉到 MVC：值集 LOV、页面元数据 `/meta`、REST 认证/令牌、图形验证码、应用令牌接口基类、代码优先模型管理、短信与邮件通知等只在 API 项目编译，清单见《[功能清单](功能清单.md)》「平台归属：API 专属能力」。MVC 的字段模型保留自己的实现，`DataField` 不再包含 `LovCode` 与 `[Parent]` 级联输出。

### 4.3 统一响应协议

所有 API 接口统一返回 `ApiResponse<T>` 结构：

```json
{
  "code": 0,
  "message": "成功",
  "data": { ... },
  "traceId": "xxx"
}
```

列表接口使用 `ApiListResponse<T>` 扩展分页信息：

```json
{
  "code": 0,
  "data": [ ... ],
  "page": { "pageIndex": 1, "pageSize": 20, "totalCount": 100 },
  "stat": { ... },
  "traceId": "xxx"
}
```

### 4.4 权限模型

魔方采用 Membership 风格的 RBAC 授权模型：

- **用户 (User)**：支持本地用户和 SSO 用户
- **角色 (Role)**：一组菜单与功能动作权限的集合
- **菜单 (Menu)**：可嵌套的树形结构，每个菜单项可关联 URL 和 Action 权限位
- **权限位 (PermissionFlags)**：Detail/Insert/Update/Delete/Export 等

首个用户自动成为管理员，`admin` 名称被禁用。

### 4.7 语言设置归属

| 决策 | 内容 |
|------|------|
| 背景 | 魔方 `CubeSetting.Language` 与 NewLife.Agent 各自维护语言设置，重复且行为不一致；不同程序都需要运行时固定语言 |
| 决策 | 语言统一由 NewLife.Core 的 `NewLife.Setting.Language` 提供**站点默认值**；SPA 实际生效语言按 `?lang=` → `Accept-Language` → 租户默认 → 站点默认 → 英文 解析（MVC/整页场景可继续使用 Cookie）。用户选择优先于系统设置，系统设置不再强制覆盖 |
| 影响面 | 破坏性：`NewLife.Setting.Language` 从"强制语言"改为"站点默认语言"。旧配置项 `Cube.Language` 仍不生效。**4.23 起进一步收敛：界面语言留空即自动、指定即全站锁定，不再提供锁定开关** |
| 回退损失 | 旧版 Core 包下无站点默认语言；自动识别与 `?lang`/Cookie/`Accept-Language` 行为不变；锁定开关关闭时用户可自行切换语言 |
| 前端 | 基本设置的界面语言使用全量语言下拉框，清单与显示名称由 Core `Localization.GetLanguageOptions()` 提供（格式「当前语言名称 (自称)」，如中文界面的 `德语 (Deutsch)`），设置页导航保留 `lang` 参数；登录页与后台都提供语言切换，只更新 `localStorage` 与请求头 `Accept-Language`，不写服务端 |

### 4.8 站点配置拆分

| 决策 | 内容 |
|------|------|
| 背景 | 站点名称/版权/Logo/语言选项既被登录页使用，也被登录后的 SPA 外壳使用；原 `/Auth/LoginConfig` 混装登录能力与站点展示信息，前端只能硬编码或重复调用 |
| 决策 | 在 `CubeController` 新增高级/可选 `GET /Cube/Site`，返回**按租户合并后的品牌有效值**、语言选项、站点级能力（AI）、版本与 `tenantCode`；语言清单直接复用 NewLife.Core 的 `LanguageInfo`；`/Auth/LoginConfig` 只保留登录能力与租户开关，不返回站点品牌 |
| 影响面 | 新增公开端点与缓存头（`ETag`、`Vary: X-Tenant, Accept-Language`）；登录页可选并行请求 Site（品牌/语言）与 LoginConfig（登录能力）；不接入 Site 时前端硬编码品牌 |
| 回退损失 | 不接入 Site 时使用前端内置默认品牌；登录能力不受影响 |
| 前端 | 可选读取 `name/logo/copyright/language/features.ai`；`tenantCode` 仅用于判断租户上下文 |

### 4.9 语言偏好存储

| 决策 | 内容 |
|------|------|
| 背景 | 跨设备语言一致性价值低；服务端存储会引入登录态依赖、数据库写入与缓存失效；匿名阶段又没有 UserID |
| 决策 | 语言只存浏览器：`localStorage['cube-language']` + 每次请求的 `Accept-Language`；不写用户 `Parameter`、不设 SPA Cookie、不提供保存语言接口。MVC/整页场景保留 Cookie/`?lang` |
| 影响面 | API 消息依赖请求头；服务端主动消息（定时/批量邮件、站内信）使用请求语言或租户/站点默认；OAuth 整页错误页可能使用浏览器语言，可在跳转 URL 追加 `?lang=` |
| 回退损失 | 清除 `localStorage` 后回退浏览器语言/站点默认；换设备语言可能不同（可接受） |
| 前端 | 登录页与后台都提供语言切换；切换只更新 i18n、`<html lang>`/`dir`、`localStorage` 与请求头 |

### 4.10 租户语言设置

| 决策 | 内容 |
|------|------|
| 背景 | 多租户站点可能需要按租户限定语言（区域子公司、合规要求），而 `Tenant` 目前没有语言字段 |
| 决策 | 新增魔方自有 `TenantSetting`（默认语言、允许语言白名单、是否锁定、按语言的品牌覆盖）；站点配置按「租户+语言 → 租户默认 → 站点+语言 → 站点默认」合并 |
| 影响面 | 新增一张表与管理界面；`/Cube/Site` 缓存键包含租户与语言；浏览器选择不在白名单时回退租户默认且不覆盖本地选择 |
| 回退损失 | 未配置 `TenantSetting` 的租户行为与当前一致（使用站点默认） |
| 前端 | `language.options` 返回站点全集与租户白名单的交集；租户 Logo/版权按语言覆盖 |

### 4.11 跨宿主菜单可用性

| 决策 | 内容 |
|------|------|
| 背景 | WebAPI/SPA 与 MVC、不同业务应用可能共用同一个 Membership 数据库。各宿主扫描控制器生成的菜单互相可见，出现「值集管理」等只在一端存在的菜单，点击打不开页面；删除菜单行后，拥有该控制器的宿主下次启动又会重建 |
| 决策 | 菜单树输出前按类路径过滤：`Menu.FullName` 解析不到对应类型时不在导航显示（`MenuHelper.IsMenuAvailable` / `FilterAvailable`）。判定与类型解析结果使用 `ConcurrentDictionary` 缓存；区域根节点（`.Controllers` 命名空间）在无可用子菜单时整组隐藏。菜单行与权限项保留在数据库，供拥有该控制器的宿主使用 |
| 影响面 | 不改变数据结构；`FullName` 为空的手工菜单不做校验；菜单管理与权限分配页不过滤，仍显示全量菜单 |
| 回退损失 | 未部署的插件/业务控制器菜单不再显示，需在对应宿主部署后才能看到 |

### 4.13 页面呈现架构（第一版）

| 决策 | 内容 |
|------|------|
| 背景 | 页面呈现有两种极端做法（纯元数据渲染 / 纯代码页面）。目标是用一套自描述元数据覆盖绝大多数 CRUD 页面，仅少数特殊交互写前端页面 |
| 决策 | ①后端声明优先：`Model.xml` 的 `ShowIn`（五区显隐）、`ItemType`（控件与格式化）、`Category`（分组）是首选，控制器字段集合只做页面级例外；②三种页面模式：M1 动态页（`/meta` 驱动）、M2 混合页（`CubeTable` + 具名插槽）、M3 自定义页；③`/meta` 视图自描述：`entity` / `setting` / `list` / `form` / `add` / `detail` / `search` / `toolbar` 各自输出完整字段数组，消费端零合并；不设契约版本号，结构只做加法；④`enableAdd` 只表达页面能力，不新增 `enableUpdate/Delete`；编辑/删除由用户权限控制，整页只读用 `isReadOnly`；有效权限不写入可缓存的 `/meta`，只下发 `menuId` + `requiredPermissions`；⑤列表直接是全部可用字段数组，`visible=false` 的列可由表格设置打开，列序与显隐由前端 `localStorage` 维护；⑥`Q` 和主时间区间由 `search` 描述，API `FieldCollection` 默认增加 `Q`，主时间存在时输出 `dtStart/dtEnd`；⑦字段 `Category` 驱动前端表单分组；⑧工具栏由 `meta.toolbar` 声明，服务端按权限过滤；⑨API 与 MVC 的字段模型拆成两份，MVC 保留原实现，API 专属能力不再反向影响 MVC |
| 影响面 | 仓库内皮肤经 `@newlifex/cube` 展开，调用方式不变；外部直读 `/meta` 的定制皮肤需按第一版结构读取 |
| 文档 | 设计说明见《[页面呈现架构](Api/页面呈现架构.md)》；接口字段见《[WebAPI接口规范](Api/WebAPI接口规范.md)》36.10 |
| 实现状态 | preset、字段级全局渲染器、`range` 查询项、B2 请求期初始化、用户列序保存、工具栏图标与 M2/M3 回归均已落地，见《[页面呈现架构](Api/页面呈现架构.md)》第 10 节与《功能清单》PAGE 模块 |

### 4.13.1 路由来源与优先级

| 决策 | 内容 |
|------|------|
| 背景 | 前端曾出现第三套机制：`apps/cube-admin/src/routes/index.ts` 用静态表逐个 import 手写视图，导致手写页接管了本可由 `/meta` 渲染的页面 |
| 决策 | ①**静态路由只承载外壳页**（`/`、`/login`、`/404`、`/loading`、`/profile/security` 等），业务页一律不经静态表；②业务路由由后端菜单驱动：`registerMenuRoutes(flatMenus)` 为**每个叶子菜单**注册路由，`resolvePageComponent` 命中 `views/**/index.vue` 用自定义视图（M2/M3），否则回落 `AutoPage`（M1）；③**隐藏菜单（`visible=false`）同样注册路由**——它只是不出现在导航里，仍需可直达（设置页、调试页都属此类）；导航与全局搜索在渲染期用 `filterVisibleMenuTree` 过滤；④优先级：静态路由/业务声明路由 > 菜单动态注册——`registerMenuRoutes` 按精确 path 去重、已有路径跳过，业务应用可用 `externalRoutes` + `addFrameworkRoute` 显式接管同名路径 |
| 影响面 | `core/stores/menu.ts` 不再丢弃隐藏菜单；`SideMenu`/`TopMenu`/`CyberLayout`/`SearchBar` 增加渲染期过滤 |
| 回归 | `menuHelpers.spec`（3 例）覆盖隐藏菜单过滤与“入参不被修改”；实测 `/Admin/MailConfig`（隐藏菜单 + 无视图）从 404 变为 M1 正常渲染 |

### 4.17 菜单显示名契约：源文快照 + 按语言决定显示

| 决策 | 内容 |
|------|------|
| 背景 | 菜单名曾在落库时写入「当时的语言」译文，切换语言后显示错乱；此前的规范键 + `Ex` 标记方案规则过多（三态标记、所有权开关、值比对），维护成本高于收益 |
| 决策 | ①**扫描只填空**：`DisplayName` 为空时写入开发者语言（`[DisplayName]` → 实体表描述 → 类名短名），已有值一个字节都不改；②**显示时先判语言**：源文含汉字视为中文源，只有 `zh`/`zh-CN`/`zh-SG`/`zh-Hans` 算一致（`zh-Hant` 走词表），英文源则 `en` 与不变文化一致；一致时直接用库值（管理员改的名在这一种语言下生效），否则按 `menu:<FullName>` → `entity:<实体全名>` → 普通词条 → 源文 即时翻译；③**漂移由按钮对齐**：菜单管理页工具栏「刷新菜单」按 `[ToolbarButton]` 声明的动作批量把选中行重置为代码源文，`FullName` 为空时按菜单名猜控制器补全；④废弃 `Menu.Ex6` 标记，代码不再读写，也没有任何"谁的写的"判定 |

| 回退损失 | 旧代码只读 `DisplayName`，看到的是源文快照，语义等价于更早版本，不会崩；数据无需回滚（`Ex6` 残留值新代码不读）。若回退词表前缀，需同时回退 `check-locales.ps1`，否则 `menu:`/`entity:` 条目会被判孤儿键 |

### 4.22 协议治理（状态码/限流/幂等）

| 决策 | 内容 |
|------|------|
| 背景 | 业务失败一律 HTTP 200 使网关无法限流与监控；匿名高频接口缺少通用配额；导入/上传重复提交可能重复落库 |
| 决策 | ① `EnableHttpStatusCodes`（默认关闭）：开启后 401/403/404/409/422/429/500 映射为真实状态码，业务码仍 200；② `RateLimitAttribute` 按「接口+IP」固定窗口计数，受 `EnableRateLimit`（默认开启）控制，超限 429 + `Retry-After`；③ `IdempotentAttribute` 对携带 `Idempotency-Key` 的导入/上传重放首次成功结果（10 分钟） |
| 影响面 | 限流默认开启，正常用户无感；状态码开关默认关闭以保持既有客户端行为；幂等为可选头，不传则行为不变 |
| 回退损失 | 状态码开启后依赖「200+code」的客户端需同时判断 HTTP 状态；限流计数单机内存，多节点需切换 Redis 共享 |

### 4.23 语言锁定合并到界面语言

| 决策 | 内容 |
|------|------|
| 背景 | 4.7 设计的「站点默认语言 + 可选锁定开关」双语义只在代码里落地了一半：中间件强制语言时直接使用配置的语言，从不读取锁定开关；而 `/Cube/Site` 的 `language.locked` 又依赖它，造成「后端已锁定、前端仍显示语言切换器」的不一致。租户级锁定字段同样只影响前端入口，不影响请求语言 |
| 决策 | 不提供锁定开关，语义收敛到「基本设置 → 界面语言」一个字段：留空表示自动跟随请求语言（`?lang=` → Cookie → `Accept-Language`），填写受支持语言表示全站锁定（界面与 `Localization.LogCulture` 同时固定）；`language.locked` 由「是否配置了受支持界面语言」派生；租户配置只保留默认语言与语言白名单 |
| 影响面 | 破坏性：不再支持「默认中文但允许用户自由切换」，有此需求的站点应留空界面语言、交由请求语言决定；租户 `languageLocked` 配置项失效（旧 JSON 仍可解析，未知字段忽略） |
| 回退损失 | 单语言部署更直接（选语言即锁定）；多语言站点的默认语言改为跟随浏览器，无 `Accept-Language` 的客户端回退服务器系统语言 |

### 4.24 前端皮肤包 NuGet 化与多皮肤共存

| 决策 | 内容 |
|------|------|
| 背景 | 皮肤包原本各自实现「替换 WebRootFileProvider + UseStaticFiles + MapFallbackToFile」，同时引用两个皮肤包会重复注册 SPA 回退路由（请求时路由歧义），皮肤包内的 `IModule` 被 AppModule 扫描启用后还会重复注册静态文件；Vue 包的 CI 前端构建曾在 `db4972bd` 中被移除，导致无法产出带前端产物的包 |
| 决策 | ① 核心新增 `ICubeSkin` + `CubeSkinManager` + `CubeSkinFileProvider`，由 `UseCube` 自动发现已引用的皮肤包并注册静态资源与回退路由，用户项目保持 `AddCube` + `UseCube` 不变；② 当前皮肤由 `CubeSetting.SpaSkin` 每次请求实时解析（显式指定 > 设置项 > 默认 Vue），设置页保存后刷新即生效，无需重启；③ 皮肤包移除 `IModule`，避免重复注册；④ `UseVue`/`UseReact`/`UseCubeSkin` 仅保留为强制入口；⑤ Vue/React 包在 CI 先 `pnpm build` 再 `dotnet pack`，打包排除 sourcemap，缺 `wwwroot/index.html` 时直接报错 |
| 影响面 | 皮肤包只携带静态前端，控制器仍只有 `NewLife.Cube` + 业务项目一套；多个皮肤包可同时引用，未选中的皮肤零注册；包体积约 7MB/TFM（排除 sourcemap 前为 29MB/TFM） |
| 回退损失 | 不支持同进程内 `/vue`、`/react` 两套皮肤同时在线（需前端 base 路径改造）；`UseVue`/`UseReact` 仍为强制语义，配置切换需改用 `UseCubeSkin()` |

### API 端点

```
POST /Ai/AiChat                  # 全局统一端点（所有页面共用；实体页经 IEntityAiContext 提供数据上下文工具，非实体页通用工具）
```

### 安全设计

- **最小工具集**：仅暴露只读数据收集、表单预填与 run_js 页面操作工具，无写库工具
- **字段安全过滤**：工具复用 `AiDataHelper` 敏感过滤；fill_form 拒绝敏感/自动维护/只读字段
- **权限**：全局 `AiController.AiChat` 要求 `[EntityAuthorize(PermissionFlags.Detail)]`（AI 菜单）；实体页对话额外按目标实体控制器菜单校验 Detail（等价原 `{controller}/AiChat` 语义，经 `IEntityAiContext` 目标解析后校验）；`OperationResult` 同全局权限；AISwitch 由服务统一校验
- **浏览器操作**：run_js 脚本在用户自己浏览器、自己登录会话内执行（等价用户在 DevTools 执行）；`OperationResult` 要求登录且检查点编号绑定当前用户、一次性消费、30 秒超时；脚本内容走 `ToolChatClient` 审计日志
- **审计**：`ToolChatClient.OnToolExecuted` 记录每次工具调用（名称/参数/结果/耗时）
- **会话隔离**：前端按页面生成会话号（sessionStorage + URL 作用域，同页多轮共享、跨页/跨标签页互不干扰）；后端会话键由 `AiController` 内联按用户+页面作用域构建（`ai:{userId}:{url}:{sessionId}`，防跨用户/跨页面串话）；会话历史存 NewLife.AI 内置 `MemoryCacheSessionStore`（1 小时过期、限长 30 条，后续升级为 ICacheProvider 版本支持分布式）
- **数据查询**：列表/记录查询委托由实体控制器提供（SearchData），保留子类重载与数据权限，服务层不绕过

### 扩展点（二次开发）

实体控制器可按需重载以下 `protected virtual` 成员，定制 AI 的提示词与数据逻辑；重载点经 `IEntityAiContext` 能力接口暴露给全局 `AiController` 统一调用：

| 重载点 | 位置 | 作用 |
|--------|------|------|
| `CreateCubeTools(pager, entityId)` | 实体控制器 | 返回自定义 AI 工具集（默认 `CubeTools<TEntity>`） |
| `BuildChatSystemPrompt(req, pager)` | 实体控制器 | 定制 AI 对话系统提示词（页面上下文） |
| `SearchData(pager)` / `Search(pager)` | 实体控制器 | 定制数据查询（含数据权限） |
| `CubeTools<TEntity>` 各工具方法 | AI 工具集 | 工具方法均为 `virtual`：`GetDataContext` / `GetFormSchema` / `FillForm`；数据收集方法 `GetListContext` / `GetRecordContext` 为 `protected virtual`，可继承重写调整数据收集逻辑；也可新增 `[ToolDescription]` 标注的自定义工具 |
| `SystemInfoToolService` 工具方法 | AI 工具服务 | 系统信息工具 `get_system_info` 为 `virtual`，可继承重写调整服务器指标采集逻辑 |
| `BrowserToolService` 工具方法 | AI 工具集 | 浏览器工具方法均为 `virtual`（当前 `run_js`），工具方法接受 `ToolCallContext? context = null`（检查点编号用 ToolCallId，通道经 `CubeBrowserContext` 上下文注入），可继承重写限制脚本或调整执行方式；也可新增 read_element / write_element / click 等页面操作工具 |
| `IPageDataContext` | 任意页面控制器 | 页面实现 `GetPageDataContextAsync()` 为 AI 提供服务端数据上下文；未实现自动降级浏览器采集 |
| `PageDataContextToolService` 工具方法 | AI 工具服务 | `get_page_context` 为 `virtual`，可继承重写调整页面上下文采集逻辑 |

```csharp
// 示例：定制表单 Schema、列表数据收集 + 新增自定义工具
public class MyUserTools : CubeTools<User>
{
    public MyUserTools(IEntityFactory factory, Pager? pager, Int64 entityId, Func<Pager, IList<User>> queryData)
        : base(factory, pager, entityId, queryData) { }

    public override String GetFormSchema(String mode = "add")
        => new { mode, custom = true }.ToJson();

    // 重写数据收集（protected virtual）：调整 get_data_context 的列表数据逻辑
    protected override String GetListContext()
        => new { custom = true, summary = "自定义数据摘要" }.ToJson();

    [ToolDescription("get_my_context", ReadOnly = true)]
    public String GetMyContext() => new { extra = true }.ToJson();
}

// 控制器：重载工具工厂
protected override CubeTools<User> CreateCubeTools(Pager? pager, Int64 entityId)
    => new MyUserTools(Factory, pager, entityId, p => SearchData(p).ToList());
```

> 工具方法的 `[ToolDescription]` 特性支持继承（NewLife.AI ≥ 1.5.2026.804）：重写带特性的 virtual 工具方法后，工具仍会被 `ToolRegistry` 发现并走虚分派到重写实现。
