# 前端开发规范

前端项目（`NewLife.Cube.Vue/web` 及各皮肤 `*/web`，pnpm workspace monorepo）的开发与提交规范。
本文档由根目录 `AGENTS.md` 路由引用：**执行任何前端任务前必读本文**。

## 1. 修改前端后必须先跑一次 `pnpm install`

**规则**：只要修改了前端项目（尤其是 `NewLife.Cube.Vue/web`），提交前必须在仓库根目录执行一次：

```powershell
pnpm install
```

**原因**：`NewLife.Cube.Vue/web` 的 `postinstall` 钩子会执行主题 token 门禁检查
（[scripts/theme-check.mjs](../../NewLife.Cube.Vue/web/scripts/theme-check.mjs)），任何一项失败都会让 `pnpm install` 以非零退出码终止。先跑一次可以在本地立即发现违规，避免把问题带到 CI 或下一次安装。

也可单独快速检查（跳过依赖解析）：

```powershell
pnpm --filter ./NewLife.Cube.Vue/web run check:theme:refresh
```

## 2. 主题 token 门禁的校验内容

门禁扫描 `NewLife.Cube.Vue/web/core` 下所有 vue/ts/scss/css 文件，校验三条规则：

1. `--el-` 开头的 CSS 自定义属性必须是 Element Plus 真实存在的 token（对照 `scripts/element-tokens.json`，升级 element-plus 后由 `check:theme:gen` 重新生成）。
2. 非 `--el-` 前缀的自定义 token 必须登记在 `scripts/custom-tokens-allow.json` 白名单（`prefixes` 命名空间或 `tokens` 独立 token）中，否则报"未授权的自定义 token"。
3. 禁止硬编码颜色：16 进制（`#xxx`）、`rgb(a)(...)`、CSS 命名颜色（`red`/`blue` 等）出现在样式上下文中即报错，仅放行 `transparent` / `currentColor`。注意 `.vue` 文件只在 `<style>` 块内检查颜色。

## 3. 字段标签禁止手写（元数据红线）

**规则**：实体页与设置页的**字段名、字段提示**一律取后端 `/meta`（`displayName` / `description` / `category` / `dataSource`），**禁止**在前端写 `t('xxx.fieldName')` 之类的字段键，也禁止手写 `el-table-column` 的列清单。

- 列表/表单优先用框架 M1 动态页（`core/views/index.vue` + `/meta`）；需要局部定制用 M2 的 `CubeTable` 具名插槽。
- 只有**元数据表达不了**的交互（工作台、图表、表结构诊断、列配置画布、权限树、拖拽排序、上传）才允许整页自定义（M3），且提交说明必须写明理由。
- 前端词表只承载**界面文案**：按钮、空态、确认框、客户端校验、调试页文案。
- 已有反例（待收敛，见 `Doc/功能清单.md` 的 IMP-5/6/7）：`apps/cube-admin/src/views/admin/**` 下 22 个手写页，手写了 400 余个字段标签键、200 余个表头键，且与后端元数据已漂移（实测缺失 82 个实体字段）。

**判定依据**：后端字段元数据已按 `Accept-Language` 本地化（`DataField.Localize()`），德语等译文由后端词表提供，前端再存一份必然漂移。

## 4. 违规修复方式优先级

- 优先改用合法的 `--el-` 主题 token（如阴影用 `var(--el-box-shadow-light)` 替代 `rgb(0 0 0 / 8%)`；色值合成用 `color-mix(in srgb, var(--el-color-...), ...)` 替代硬编码色）。
- 布局类无法用主题 token 表达的（如栅格跨列数），改为通过 `:style` 内联样式直接下发（如 `gridColumn: 'span 6'`），不要自造 `--xx-` 自定义 token。
- 确需新增设计系统级自定义 token 时，须经评审后登记进 `scripts/custom-tokens-allow.json`。
- 不要用 `--ignore-scripts` 绕过 postinstall 检查。
