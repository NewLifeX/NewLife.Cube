### FIX-SQLITE-LIKE：SQLite 下含下划线/百分号的模糊搜索查不到数据（已修复，待 XCode 发版后升级依赖）

- **是什么问题**：SQLite 部署时，列表搜索框输入含 `_` 或 `%` 的关键字，结果为空；同样的关键字不含这两个字符时正常。
- **有什么危害**：用户会误判"没有数据"；影响所有走 `FieldItem.Contains/StartsWith/EndsWith` 的查询（各列表页高级搜索、值集远程搜索等）。Cube 新建站点默认就是 SQLite，命中面大。
- **怎么修改**：根因在 NewLife.XCode `DbBase.FormatLike`（`C:\X\NewLife.XCode\XCode\DataAccessLayer\Common\DbBase.cs:920`）把 `%`/`_` 转义成 `\%`/`\_`，但生成的 SQL 没有 `ESCAPE '\'` 子句；SQL Server/MySQL 默认反斜杠即转义所以正常，SQLite 无反斜杠转义语义故失配。应在 XCode 中为 SQLite 重写 `FormatLike`（或统一追加 `ESCAPE`），并补单测；本仓库升级 XCode 后加回归用例。
- **修改后的遗憾**：需要升级 XCode 依赖；对含 `%`/`_` 的历史查询属于行为修正（原先查不到，修正后能查到），不构成破坏性变更。
- **触发路径**：SQLite 环境下，任意管理员在列表页搜索框输入含下划线的关键字（如设备号 `dev_001`）。
- **证据**：临时探针（已删除）在同一库写入 `sess_xxxx`/`sessxxxx` 两条记录，`Contains("sess_xxxx")=0`、`Contains("sessxxxx")=1`、`StartsWith("sess_xxxx")=0`。
- **进展（2026-10-27）**：根因已在 XCode 修复——SQLite 方言 `FormatLike` 在转义生效时追加 `ESCAPE '\'`（XCode 提交 `d91b47694`），XCode 侧新增 DB 级回归测试（写入 `sess_xxxx`/`sessxxxx` 后 `Contains` 精确命中 1 行，去掉 `ESCAPE` 时该用例失败）。Cube 侧新增 `SqliteLikeEscapeTests`（下划线/百分号字面量匹配），随 XCode 版本门槛自动启用：当前引用 `12.3.2026.1024` 时自动跳过，升级到含该修复的版本后自动生效。 **已用本地构建的 XCode（`12.3.2026.1027`）置换 DLL 做过端到端验证**：`SqliteLikeEscapeTests` 在该版本下不再跳过且通过（1/1），证明 Cube 的 `Contains` → XCode SQLite `ESCAPE` → 查询链路打通；随后已还原引用包，等正式发版后把 `NewLife.XCode` 版本从 `12.3.2026.1024` 升上去即可自动转绿。
