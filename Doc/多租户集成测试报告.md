## 二、关键发现（首轮）

1. **fixture 缺口修复**：`TenantAuthFixture` 构造 `UserService` 时密码服务传了 `null!`（注册路径的密码强度校验 `passwordService.Valid` 会用到，登录不触发）→ 已改为注入真实 `PasswordService`。测试装配缺陷，非产品缺陷。
2. **注册语义验证通过**：M1（Shadow 无标识放行不绑定）、M2/M2e/M6（带 X-Tenant/X-App-Id 自动绑定）、M1e/M4r（Enforce 无标识拒绝、无效租户拒绝且**不建用户**）与清单预期一致。
3. **X-App-Id 一等公民验证通过**：注册（M6）、登录自动绑定（M7）、访问成员/非成员（M8）三条路径均按 OAuth 配置租户正确解析与校验。
4. **Enforce 自救通道验证通过**（M9）：存量无绑定用户的注册旧令牌在 Enforce 下被拒，带 X-Tenant 重登自动补绑后新令牌可用——规则B 是永久能力、不依赖 Shadow。
5. **显式标识优先校验被持续锁定**：M8、M11e 与既有 4 个期望测试共同守护"请求 t2 不被静默换 t1"的修复。

## 四、二轮补测（2026-08-16，按子代理审查结论）

子代理对"测试 ↔ 清单覆盖"与断言质量的双向审查发现 3 个高优先级缺口和若干断言弱点，本轮补齐：

- **M3 登录拒绑**（新增）：此前集成测试注释声称已覆盖实为失实——只有"访问别家租户被拒"，没有"已绑定用户带别家租户**登录** → 规则B 拒绑"。现锁定：登录成功 + 绑定表仍只 t1 + 无 t2 误绑 + 上下文回落 t1。
- **B7 回落第一租户**（新增）：清单明示"重点验"的"已绑定用户无标识访问 → 回落 t1"此前零测试，现断言 CurrentId==t1。
- **M9 加固**：旧令牌腿由 `if` 包裹改为强制断言（注册必发令牌），杜绝静默跳过。
- **M10 加固**：补"旧 access 随 UserToken 吊销而失效"断言 + Enforce 分支（新令牌无标识被拒 / 带标识放行），对齐清单 M10 的"可用性随模式"语义。
- **M8 加固**：补 Enforce 迭代 + 非成员对照腿。
- **拒绝型用例加正向对照**：Expect_NonMember / Expect_NormalUser(AdminCookie) / Expect_Invalid_XTenant / M8 均补"同一令牌走放行路径成功"对照，消除"TryLogin 全局损坏导致误绿"风险。
- **方向断言补齐**：Admin_Not_Affected 补 CurrentId=0；Expect_LegacyUser_Login_Should_Succeed_Without_XTenant 补 CurrentId=0（无绑定无标识不设上下文）。

## 五、结论

清单四节注册/登录/访问场景（M1-M11）与 B 节回落语义已全部由集成测试落地并实测通过，与方案决策表（§8.2）一致。全套件 61 个测试全绿，两工程编译 0 错误。剩余未覆盖项均为 E2E/HTTP 管线范畴（M12/M13/M14/中间件状态码/数据过滤），已在第三节如实标注。
