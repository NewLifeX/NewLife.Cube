# NewLife.Cube.React 架构设计

> 版本：v1.0 | 日期：2026-08-28
> 本文档描述 `NewLife.Cube.React`（第三代魔方 React 前端皮肤）的技术架构与实现方案。功能追踪见 [功能清单](功能清单.md)。

---

## 1. 概述

### 1.1 定位

`NewLife.Cube.React` 是第三代魔方（API 版 `NewLife.Cube`）的 React 前端皮肤 NuGet 包。用户引用 `NewLife.Cube` + `NewLife.Cube.React` 两个包，`dotnet run` 后浏览器打开即有完整管理后台——登录、动态菜单、字段元数据驱动的列表/表单、CRUD、导入导出、多主题等开箱即用，零前端开发。

### 1.2 目标

1. 与 `NewLife.Cube.Vue` 皮肤**功能对等**，成为 React 系皮肤的参考标杆
2. **全面消费公共包** `packages/`（`@cube/api-core` / `@cube/auth-logic` / `@cube/page-logic` / `@cube/field-mapping` / `@cube/page-utils`），验证并补齐公共包能力
3. 编译产物嵌入 DLL：`pnpm build` → `web/../wwwroot` → csproj `<EmbeddedResource>` → NuGet 包
4. 未来 React 系皮肤（Shadcn/MUI/Arco 等）可基于本皮肤结构复用

### 1.3 与 Vue 皮肤的关系

| 维度 | Vue 皮肤（参考标杆） | React 皮肤（本工程） |
|------|---------------------|---------------------|
| 框架 | Vue3 + Element Plus + Pinia | React19 + Ant Design 6 + Zustand |
| 构建 | Vite 6 | Vite 6 |
| 公共包 | api-core / auth-logic(pinia) / page-logic(pinia) / field-mapping / page-utils | api-core / auth-logic(zustand) / page-logic(zustand) / field-mapping / page-utils |
| 布局 | RootLayout + CyberLayout/MainLayout | RootLayout + MainLayout（Sider/Header/Tabs） |
| 配置系统 | configure/（defaultConfig + env + window._CUBE_CONFIG_） | configure/ 同构移植 |
| 字段映射 | core/utils/fieldControl.ts | src/utils/fieldControl.ts（同规则） |
| 多主题 | 4 主题家族 × 明暗（CSS 变量） | 单一主题 × 明暗（antd token） |

## 2. 技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 构建 | Vite 6 | 与 Vue 皮肤一致；快、配置透明 |
| 框架 | React 19 + TypeScript | antd6 / @cube zustand 适配器最稳定 |
| UI | Ant Design 6（纯自定义字段驱动组件） | 与 field-mapping + page-logic store 数据流契合；不用 ProComponents |
| 状态 | Zustand 5 | `@cube/auth-logic/zustand`、`@cube/page-logic/zustand` 开箱即用 |
| 路由 | react-router v6 | 静态路由表 + catch-all DefaultEntity 模式 |
| 图表 | ECharts（懒加载） | 对齐 Vue 皮肤 |
| 富文本 | 轻量库（实现时按包体积决策） | 对齐 Vue @wangeditor / md-editor-v3 |
| i18n | react-i18next（中文默认） | 对齐 Vue vue-i18n |
| 测试 | Vitest + RTL + Playwright | 对齐 Vue vitest + playwright |

## 4. 核心架构

### 4.1 数据流（公共包 + zustand）

```
后端 API（/Auth /Cube /{type}）
   │  axios（@cube/api-core createCubeApi）
   ▼
stores/user（@cube/auth-logic/zustand）──► 登录/登出/用户信息/菜单/权限
stores/menu（树↔扁平 + 激活）
views/list（@cube/page-logic/zustand createPageStore）──► 字段/数据/CRUD/分页
   │  resolveWidgets（@cube/field-mapping）→ FieldMapping
   ▼
utils/fieldControl.ts（皮肤映射）→ ControlType/SearchControlType/ListControlType
   ▼
AntD 组件渲染（FieldControl 渲染器）
```

- **PageLogic（公共包）**：负责字段加载、列表查询、分页状态、CRUD、导入导出、图表——全部框架无关
- **fieldControl.ts（皮肤）**：把 FieldMapping 映射到皮肤控件类型——单一真理源，禁止在组件里写本地映射
- **组件只做渲染与交互**：不持有数据逻辑，从 store 读状态、调 store 方法

### 4.2 配置系统（对齐 Vue configure/）

```
优先级（低→高）：
  defaultConfig → env 配置（.env）→ window._CUBE_CONFIG_（运行时注入）
```

配置项：`base`（title/logo/footer）、`request`（baseUrl/timeout/附加头）、`auth`（tokenKey/登录页 URL）、`ui`（布局/主题）、`menu`（菜单字段映射）、`user`、`router`。

### 4.3 路由与菜单

- **静态路由表**（`router/index.tsx`）：`/`、`/login`、`/register`、`/activate`、`/forgot-password`、`/profile/security`、`/unauthorized`、`/loading`、`*` → `DefaultEntity`
- **DefaultEntity**（对齐 Vue `DefaultEntity.vue`）：根据当前路径在菜单树中匹配，命中 → 渲染通用列表页，未命中 → 404
- **登录守卫**：RootLayout 检查 token，无 token 且路径需认证 → 重定向 `/login?r={redirect}`

### 4.4 布局

```
RootLayout
  ├─ 未登录 → 渲染 Login 等公开页
  └─ 已登录 → 加载用户/菜单 → MainLayout
       MainLayout
       ├─ Sider：动态菜单（菜单树 → antd Menu）
       ├─ Header：折叠按钮 + 单行面包屑 + NavbarSearch + 切换器(主题/语言/明暗) + 通知 + 用户菜单
       ├─ Tabs：多标签页（stores/tabs，首页固定标签；仅剩首页时隐藏栏）
       ├─ Content：路由出口（KeepAlive 等价：zustand 缓存或简单不缓存）
       └─ Footer
```

### 4.5 字段控件映射（单一真理源）

对齐 Vue `fieldControl.ts` 的规则，皮肤内建三组映射：

| 映射 | 用途 | 输出类型 |
|------|------|----------|
| `resolveControl(field)` | 表单/编辑控件 | `ControlType` |
| `resolveSearchControl(field)` | 搜索控件 | `SearchControlType` |
| `resolveListControl(field)` | 列表单元格 | `ListControlType` |

**公共包分工**：`@cube/field-mapping` 提供框架无关的 `resolveWidget`（本工程扩展其支持 lovCode/lovMulti/json/icon/richHtml/richMarkdown/time/enum/Guid 等），皮肤 `fieldControl.ts` 在其基础上映射到 AntD 控件。

### 4.6 主题系统

- antd `ConfigProvider` + `theme.token` 驱动（对齐 Vue 4 主题家族 × 明暗）
- `stores/theme`：当前主题/明暗，持久化 localStorage
- 主题切换器组件在 Header

## 5. 构建与部署

```bash
# 本地开发（Vite dev server，代理 /api → 后端）
pnpm dev

# 构建（输出到 ../wwwroot，Vite emptyOutDir）
pnpm build

# 类型检查
pnpm type-check

# 测试
pnpm test:unit      # Vitest
pnpm test:e2e       # Playwright
```

- `vite.config.ts`：`build.outDir = '../wwwroot'`、`emptyOutDir: true`
- `.NET 侧`：`NewLife.Cube.React.csproj` `<EmbeddedResource Include="wwwroot\**\*">` 嵌入 DLL；`ReactService.UseReact()` 注册嵌入式静态文件 + SPA 回退
- 部署只需 `NewLife.Cube.React.dll` + `NewLife.Cube.dll`

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 全量对等工作量大 | 按功能清单分批迭代（dev-loop），每批可编译可验证 |
| 公共包能力不足 | 扩展 field-mapping 并补单测；发现其他缺口时同步补齐公共包 |
| antd 主题 token 与 Vue CSS 变量差异 | 主题仅保证"同名同感"，不追求像素级一致 |
| 富文本/通知等第三方依赖 | 实现时评估体积与维护性，必要时降级 |
